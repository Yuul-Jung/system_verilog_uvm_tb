제06장 · 배열·큐·패키지

기존 UART Echo RTL로 packed/unpacked 배열·queue·package를 배우는 2시간 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00학습 개요 · 검증 데이터의 순서를 관리한다

제05장에서는 struct(스트럭트, 구조체)로 한 번의 입력을 묶었습니다. 이번 장에서는 여러 개의 입력을 배열(array, 어레이)에 담고, 전송할 것으로 예상되는 데이터를 큐(queue, 큐)에 저장하며, 공통 타입을 패키지(package, 패키지)로 분리합니다. 실제 DUT(검증 대상 회로)는 수정하지 않습니다.

구간학습 내용완료 기준
1교시 · 0~60분packed/unpacked 배열 · 큐 · 패키지의 차이기대 데이터 A·B·C·D 저장 구조 설명
2교시 · 60~120분기존 UART Echo 연결, 전체 TB, 실행 및 검증수락된 데이터만 큐에서 제거하고 결과 비교

원본 uart_echo_controller는 클록과 리셋이 없는 순수 조합 바이트 스트림 연결 회로입니다. 실제 UART 직렬 프레임이나 DUT 내부 FIFO를 구현했다고 해석하지 않습니다.

011교시 ① · packed와 unpacked 배열 (0~20분)

logic [3:0][7:0] packed_bytes;는 네 개의 8비트 값을 이어 붙인 32비트 packed 배열입니다. 반면 logic [7:0] unpacked_bytes [0:3];는 각각 독립된 8비트 원소 네 개입니다. 첫 번째는 비트 연결·슬라이싱에, 두 번째는 원소별 순차 처리에 편리합니다.

배열 예제 · 실제 TB에서 발췌 · SystemVerilog
logic [3:0][7:0] packed_bytes;
logic [7:0] unpacked_bytes [0:3];

packed_bytes = {8'h41, 8'h42, 8'h43, 8'h44};

// [3]은 41, [2]는 42, [1]은 43, [0]은 44이다.
for (i = 0; i < 4; i = i + 1)
    unpacked_bytes[i] = packed_bytes[3-i];
원소packed 선택unpacked 저장ASCII 문자
첫 번째packed_bytes[3]unpacked_bytes[0]A · 41
두 번째packed_bytes[2]unpacked_bytes[1]B · 42
세 번째packed_bytes[1]unpacked_bytes[2]C · 43
네 번째packed_bytes[0]unpacked_bytes[3]D · 44

packed_bytes[3-i]의 역순 인덱스는 의도적입니다. 가장 왼쪽의 8'h41이 가장 높은 packed 인덱스 3에 배치되기 때문입니다. 인덱스를 그대로 쓰면 D·C·B·A 순서가 됩니다.

021교시 ② · queue의 앞뒤와 전송 수락 (20~40분)

큐는 고정 크기 배열과 달리 원소를 추가·제거할 수 있습니다. expected_q[$]는 8비트 기대 데이터의 큐이며, push_back()(푸시 백, 뒤에 넣기)과 pop_front()(팝 프런트, 앞에서 꺼내기)를 이용해 입력 순서를 보존합니다.

큐 동작 · 실제 TB에서 발췌 · SystemVerilog
logic [7:0] expected_q[$];
logic [7:0] expected_byte;

// 기대 데이터 A, B, C, D를 뒤에 차례대로 넣는다.
for (i = 0; i < 4; i = i + 1)
    expected_q.push_back(unpacked_bytes[i]);

// 유효하고 준비된 경우에만 앞의 기대값을 꺼낸다.
if (sample.valid && sample.ready) begin
    if (expected_q.size() != 0) begin
        expected_byte = expected_q.pop_front();
        if (tx_data_o !== expected_byte)
            $error("DATA_MISMATCH");
    end
end

핵심은 수락 시점입니다. valid=1이더라도 ready=0이면 데이터가 전송 수락되지 않습니다. 이때 큐에서 B를 제거하면 다음 C를 비교할 때 기대 순서가 어긋납니다. valid && ready가 참일 때에만 앞의 원소를 제거해야 합니다.

입력validready큐 변화
무효 입력01A B C D 유지
A11B C D
B · 대기10B C D 유지
B · 재개11C D
C, D11비어 있음

031교시 ③ · package와 import (40~60분)

package(패키지, 공통 선언 묶음)는 여러 테스트벤치가 사용하는 자료형을 한 파일에 정의합니다. import uart_expect_pkg::*;는 그 패키지의 공개 선언을 현재 범위에서 사용할 수 있게 합니다. 제05장의 struct를 재사용하기 좋게 분리하는 단계입니다.

tb/ch06/uart_expect_pkg.sv · SystemVerilog
// 제06장: 기대값의 자료형을 재사용 가능한 패키지에 모은다.
// 이 파일은 검증용이며 합성 대상 DUT에 포함하지 않는다.
package uart_expect_pkg;
    // packed: valid, ready, data를 하나의 10비트 값으로 묶는다.
    typedef struct packed {
        logic       valid;
        logic       ready;
        logic [7:0] data;
    } uart_sample_t;

    // 검증 결과 기록용 2상태 열거형.
    typedef enum bit [1:0] {
        CASE_IDLE  = 2'd0,
        CASE_SEND  = 2'd1,
        CASE_STALL = 2'd2,
        CASE_RESUME = 2'd3
    } case_kind_t;
endpackage

uart_sample_t는 10비트 packed 구조체로, valid 1비트, ready 1비트, data 8비트를 묶습니다. case_kind_t는 테스트 사례의 이름이며 DUT에 실제 상태기가 있다는 뜻은 아닙니다.

패키지 사용 · 실제 TB에서 발췌 · SystemVerilog
module tb_uart_arrays_queues;
    import uart_expect_pkg::*;

    uart_sample_t sample;
    case_kind_t kind;

    // 구조체 필드 순서: valid, ready, data.
    // A를 수락하는 검증 입력을 전달한다.
    apply_sample(CASE_SEND, '{1'b1, 1'b1, 8'h41});
endmodule

컴파일할 때 uart_expect_pkg.sv를 먼저 지정해야 합니다. import는 소스 파일을 자동으로 읽어오는 기능이 아니라, 이미 컴파일된 패키지의 선언을 참조하는 문법입니다.

042교시 ① · 실제 DUT의 포트·시간 계약 (60~70분)

이번 장의 DUT는 기존 part03/common/rtl/uart_echo_controller.v입니다. 아래 세 개의 연속 대입이 전부이므로 입력이 바뀌면 조합 출력도 바뀝니다. 클록·리셋·상태 저장은 없습니다.

기존 RTL · 읽기 전용 원본 · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule
입력출력동작 계약
rx_data_i[7:0]tx_data_o[7:0]바이트를 그대로 연결
rx_valid_itx_valid_o유효 신호 그대로 전달
tx_ready_irx_ready_o수신 가능 신호를 역방향 전달

테스트벤치는 입력을 변경한 뒤 #1로 관찰 시간을 확보합니다. 이는 테스트벤치의 샘플링 지연이지 실제 RTL의 1ns 지연 사양이 아닙니다. 한 입력 사례마다 1ns씩 시간이 진행됩니다.

052교시 ② · 전체 테스트벤치 (70~95분)

아래 코드는 배열 네 개의 원소를 큐에 넣은 다음, 유효하지 않은 입력·수락·대기·재개·연속 수락을 순서대로 시험합니다. 조합 출력 세 신호를 매 사례에서 비교하고, 수락 시에만 큐의 맨 앞 데이터를 꺼내 비교합니다.

tb/ch06/tb_uart_arrays_queues.sv · SystemVerilog
`timescale 1ns/1ps
// 제06장: packed/unpacked 배열, queue, package로 UART Echo 기대값을 관리.
// 실제 DUT는 조합 회로이며 UART 직렬 전송기나 FIFO가 아니다.
module tb_uart_arrays_queues;
    import uart_expect_pkg::*;

    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    logic       tx_ready_i;
    wire [7:0]  tx_data_o;
    wire        tx_valid_o;
    wire        rx_ready_o;

    // 실제 원본의 여섯 포트를 정확한 이름으로 연결한다.
    uart_echo_controller dut (
        .rx_data_i(rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

    // packed 배열: 4개 바이트를 하나의 32비트 벡터로 저장한다.
    logic [3:0][7:0] packed_bytes;
    // unpacked 배열: 4개의 독립된 8비트 원소를 보관한다.
    logic [7:0] unpacked_bytes [0:3];

    // queue: 기대되는 출력 데이터를 입력 순서대로 보관한다.
    // 원본 DUT 내부에 FIFO가 있다는 뜻이 아니다.
    logic [7:0] expected_q[$];
    uart_sample_t sample;
    case_kind_t kind;
    logic [7:0] expected_byte;
    integer checks = 0;
    integer failures = 0;
    integer i;

    // 전송은 valid와 ready가 모두 1일 때에만 수락된다.
    task automatic apply_sample(
        input case_kind_t next_kind,
        input uart_sample_t next_sample
    );
        begin
            kind = next_kind;
            sample = next_sample;

            rx_data_i  = sample.data;
            rx_valid_i = sample.valid;
            tx_ready_i = sample.ready;
            #1; // 조합 전파 관찰용 시간, 실제 DUT 레이턴시 아님.

            checks = checks + 1;
            if ((tx_data_o !== sample.data) ||
                (tx_valid_o !== sample.valid) ||
                (rx_ready_o !== sample.ready)) begin
                failures = failures + 1;
                $error("SIGNAL_MISMATCH kind=%0d data=%h", kind, sample.data);
            end

            if (sample.valid && sample.ready) begin
                if (expected_q.size() == 0) begin
                    failures = failures + 1;
                    $error("QUEUE_UNDERFLOW kind=%0d", kind);
                end else begin
                    expected_byte = expected_q.pop_front();
                    checks = checks + 1;
                    if (tx_data_o !== expected_byte) begin
                        failures = failures + 1;
                        $error("DATA_MISMATCH got=%h expected=%h",
                            tx_data_o, expected_byte);
                    end else begin
                        $display("ACCEPT t=%0t data=%h remain=%0d",
                            $time, tx_data_o, expected_q.size());
                    end
                end
            end else begin
                $display("HOLD t=%0t kind=%0d valid=%b ready=%b",
                    $time, kind, sample.valid, sample.ready);
            end
        end
    endtask

    initial begin
        $dumpfile("ch06_uart_arrays_queues.vcd");
        $dumpvars(0, tb_uart_arrays_queues);
    end

    initial begin
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        packed_bytes = {8'h41, 8'h42, 8'h43, 8'h44};

        // packed 인덱스 3은 최상위 바이트(41), 인덱스 0은 44.
        for (i = 0; i < 4; i = i + 1)
            unpacked_bytes[i] = packed_bytes[3-i];

        // 아직 전송 전이므로 예상값 네 개를 큐에 먼저 쌓는다.
        for (i = 0; i < 4; i = i + 1)
            expected_q.push_back(unpacked_bytes[i]);

        $display("=== CH06 ARRAYS QUEUES PACKAGES START ===");
        $display("ARRAY packed=%h first=%h last=%h",
            packed_bytes, unpacked_bytes[0], unpacked_bytes[3]);
        $display("QUEUE size=%0d", expected_q.size());

        // 유효하지 않은 데이터: queue에서 꺼내지 않는다.
        apply_sample(CASE_IDLE, '{1'b0, 1'b1, 8'h00});

        // A는 수락, B는 ready=0인 동안 수락하지 않는다.
        apply_sample(CASE_SEND, '{1'b1, 1'b1, 8'h41});
        apply_sample(CASE_STALL, '{1'b1, 1'b0, 8'h42});
        apply_sample(CASE_RESUME, '{1'b1, 1'b1, 8'h42});

        // C, D를 이어서 전송하고 큐를 비운다.
        apply_sample(CASE_SEND, '{1'b1, 1'b1, 8'h43});
        apply_sample(CASE_SEND, '{1'b1, 1'b1, 8'h44});

        checks = checks + 1;
        if (expected_q.size() != 0) begin
            failures = failures + 1;
            $error("QUEUE_NOT_EMPTY remain=%0d", expected_q.size());
        end

        if (failures == 0) begin
            $display("PASS checks=%0d failures=0 queue=0", checks);
            $finish;
        end else begin
            $fatal(1, "FAIL checks=%0d failures=%0d", checks, failures);
        end
    end

    // wait 없이 종료되도록 전체 시간 상한을 별도로 설정한다.
    initial begin
        #100;
        $fatal(1, "TIMEOUT: testbench did not finish");
    end
endmodule

코드 풀이 — 검증이 실제로 진행되는 순서

packed_bytes에 32비트 데이터를 저장하고, for로 unpacked_bytes의 네 원소를 채웁니다. 이어 push_back()으로 기대값 A·B·C·D를 저장합니다. apply_sample()은 세 입력을 DUT에 연결하고 #1 후 출력과 기대 신호를 비교합니다.

첫 번째 A가 수락되면 pop_front()가 A를 반환하고 큐 크기는 3이 됩니다. B의 ready가 0일 때는 꺼내지 않습니다. 다시 ready=1이면 B를 꺼내고, C·D까지 완료하면 큐가 비어야 합니다. !==를 사용하므로 X가 발생한 데이터도 일반 !=보다 명확히 검사할 수 있습니다.

이번 장은 원본의 조합 연결과 큐의 기대 순서를 검사합니다. 클록 기반 버퍼나 실제 전송 유지 계약을 추가로 가정하지 않습니다. 이러한 인터페이스 타이밍 검증은 이후 제07장과 제14장에서 확장합니다.

062교시 ③ · Ubuntu 실행과 예상 출력 (95~110분)

Ubuntu에서 Icarus Verilog(아이카루스 베릴로그, RTL 시뮬레이터)를 사용해 실행합니다. 패키지 → 원본 DUT → 테스트벤치 순서로 컴파일하고, 출력 로그와 VCD(브이시디, 신호 변화 기록)를 .build/ch06에 저장합니다.

scripts/run_ch06.sh · Bash
#!/usr/bin/env bash
# 제06장: 패키지를 DUT/TB보다 먼저 컴파일한다.
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
COURSE_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
DUT_PATH="${DUT_PATH:-$COURSE_ROOT/reference_rtl/uart_echo_controller.v}"
PKG_PATH="$COURSE_ROOT/tb/ch06/uart_expect_pkg.sv"
TB_PATH="$COURSE_ROOT/tb/ch06/tb_uart_arrays_queues.sv"
OUT_DIR="$COURSE_ROOT/.build/ch06"

for tool in iverilog vvp; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "ERROR: $tool 명령이 없습니다. sudo apt install iverilog"
    exit 2
  fi
done

if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 원본 DUT 파일 없음: $DUT_PATH"
  exit 2
fi

mkdir -p "$OUT_DIR"
# SystemVerilog 패키지를 먼저 지정해야 import가 해석된다.
iverilog -g2012 -s tb_uart_arrays_queues \
  -o "$OUT_DIR/simulation.vvp" "$PKG_PATH" "$DUT_PATH" "$TB_PATH"

# pipefail로 시뮬레이터의 실패 종료 코드를 유지한다.
(cd "$OUT_DIR" && vvp simulation.vvp | tee output.log)
echo "로그: $OUT_DIR/output.log"
echo "파형: $OUT_DIR/ch06_uart_arrays_queues.vcd"

현상원인 후보확인 방법
