00개요 · 연결과 시간의 분리

01원본 RTL과 포트 계약

원본 DUT는 수신 데이터와 유효 신호를 송신 경로로 전달하고 준비 신호는 반대로 전달합니다. 버퍼, FIFO, 직렬 송수신, 내부 상태기는 없습니다.

reference_rtl/uart_echo_controller.v · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule
DUT 입력DUT 출력폭
rx_data_itx_data_o8비트
rx_valid_itx_valid_o1비트
tx_ready_irx_ready_o1비트

여섯 포트를 그대로 연결하면 기존 회로는 변경하지 않고 검증 환경만 바꿀 수 있습니다.

02전체 연결 구조와 역할 분리

최상위 tb_uart_interface가 공통 인터페이스 인스턴스와 연결 래퍼, 검증 모듈을 연결합니다. 각 모듈이 직접 접근하는 신호의 범위를 구분합니다.

계층 구조 · 실제 인스턴스 이름
tb_uart_interface
├─ tb_clk                     10ns 주기, TB 전용
├─ stream : uart_stream_if    6개 신호 + cb
├─ adapter : uart_echo_bind  DUT modport
│  └─ dut : uart_echo_controller
└─ agent : uart_stream_agent TB modport → cb
기능실제 코드역할
interfaceuart_stream_if stream(tb_clk)공통 신호와 타이밍 정책
modport DUTuart_echo_bind adapter(stream)평면 RTL 포트 직접 연결
modport TBuart_stream_agent agent(stream)cb를 통해 입력 구동·출력 샘플링

uart_echo_bind는 단순 연결용 래퍼입니다. tb_clk은 stream의 clocking 이벤트만 정의하며 DUT에 연결하지 않습니다. agent는 이번 장의 일반 SystemVerilog 검증 모듈이며 UVM Agent 클래스가 아닙니다.

03interface·modport·clocking block

신호 선언과 접근 방향, 시간 정책을 한 파일에서 관리합니다. TB 관점의 output은 DUT 입력을 구동하고 input은 DUT 출력을 관찰합니다.

tb/ch07/uart_stream_if.sv · SystemVerilog
`timescale 1ns/1ps
// 제07장: UART Byte Stream(바이트 데이터 흐름)의 6개 신호를 한 묶음으로 관리한다.
// tb_clk은 테스트벤치의 샘플링 기준이며, 원본 DUT의 입력 포트가 아니다.
interface uart_stream_if(input logic tb_clk);
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    logic       tx_ready_i;
    logic       rx_ready_o;
    logic [7:0] tx_data_o;
    logic       tx_valid_o;

    // (추가) TB 관점에서 출력은 구동, 입력은 관찰 대상이다.
    // input #1step: 현재 상승 에지 직전의 안정된 값을 샘플링한다.
    // output #0  : 상승 에지의 Re-NBA 영역에서 다음 구간의 입력을 구동한다.
    clocking cb @(posedge tb_clk);
        default input #1step output #0;
        output rx_data_i, rx_valid_i, tx_ready_i;
        input  rx_ready_o, tx_data_o, tx_valid_o;
    endclocking

    // (추가) TB에서는 cb로만 구동·샘플링하도록 접근 방식을 지정한다.
    modport TB (clocking cb);

    // (추가) 원본의 6개 평면 포트를 연결할 Adapter용 방향 선언.
    // DUT 원본 자체는 interface 포트를 갖지 않는다.
    modport DUT (
        input  rx_data_i, rx_valid_i, tx_ready_i,
        output rx_ready_o, tx_data_o, tx_valid_o
    );
endinterface
구문의미
clocking cb @(posedge tb_clk)상승 에지를 기준 이벤트로 지정
input #1step현재 이벤트 직전의 값을 샘플링(전역 시간 정밀도 한 단위)
output #0현재 이벤트에 구동을 예약
modport TB (clocking cb)검증 모듈에서 cb를 이용
modport DUT (...)연결 래퍼가 사용할 입출력 방향 선언

정밀도 1ps가 적용되는 이 실습에서 #1step은 한 클록이 아닙니다. 관찰은 에지 직전 값, 구동은 해당 이벤트에 예약된 새 값으로 구분합니다. 따라서 같은 이벤트에 새 값을 구동하더라도 그 값을 같은 이벤트의 이전 샘플이라고 해석하지 않습니다.

04타이밍 계약 · 관찰과 구동을 분리

이벤트관찰다음 입력
5ns검사 없음A(41), 1, 1
15nsA_ACCEPT: 41/1/1Z(5A), 1, 0
25nsZ_STALL: 5A/1/0ready만 1
35nsZ_ACCEPT: 5A/1/1valid만 0
45nsIDLE: 5A/0/1종료

여기서 문자 Z는 ASCII(아스키, 문자 코드) 0x5A이며 논리의 고임피던스 Z와 다릅니다. 25ns에 데이터와 valid는 유지하고 ready만 올립니다. 35ns 수락 조건을 관찰한 뒤 valid를 내립니다. 실제 클록 기반 DUT의 거래 검증이 아니라 조합 연결에 TB의 관찰 경계를 적용한 실습입니다.

05테스트벤치 전체 코드

tb/ch07/tb_uart_interface.sv · SystemVerilog
`timescale 1ns/1ps
// 제07장: interface → modport → clocking block → 기존 UART Echo 검증.
// uart_echo_controller.v 원본은 읽기 전용으로 컴파일한다.

// (추가) 기능 없이 기존 DUT 포트를 interface 신호로만 연결하는 Wrapper.
module uart_echo_bind(uart_stream_if.DUT bus);
    uart_echo_controller dut (
        .rx_data_i (bus.rx_data_i),
        .rx_valid_i(bus.rx_valid_i),
        .rx_ready_o(bus.rx_ready_o),
        .tx_data_o (bus.tx_data_o),
        .tx_valid_o(bus.tx_valid_o),
        .tx_ready_i(bus.tx_ready_i)
    );
endmodule

// (추가) TB modport를 통해서 clocking block 신호만 접근한다.
module uart_stream_agent(uart_stream_if.TB bus);
    integer checked;

    // 출력과 기대값을 4상태(0, 1, X, Z)까지 포함하여 비교한다.
    // 제04장에서 배운 자동 PASS/FAIL 검증을 이번 인터페이스에 재사용한다.
    task automatic check_case(
        input string      case_name,
        input logic [7:0] exp_data,
        input logic       exp_valid,
        input logic       exp_ready
    );
        begin
            if ((bus.cb.tx_data_o !== exp_data) ||
                (bus.cb.tx_valid_o !== exp_valid) ||
                (bus.cb.rx_ready_o !== exp_ready)) begin
                $fatal(1,
                    "FAIL %s: data=%02h valid=%b ready=%b (expected %02h/%b/%b)",
                    case_name,
                    bus.cb.tx_data_o, bus.cb.tx_valid_o, bus.cb.rx_ready_o,
                    exp_data, exp_valid, exp_ready);
            end
            checked = checked + 1;
            $display("PASS %s: data=%02h valid=%b ready=%b",
                case_name,
                bus.cb.tx_data_o, bus.cb.tx_valid_o, bus.cb.rx_ready_o);
        end
    endtask

    initial begin
        checked = 0;
        $display("=== CH07 INTERFACE / MODPORT / CLOCKING START ===");

        // t=5ns: 첫 clocking event 후 A를 구동한다.
        // output #0 때문에 이 에지에서 샘플된 값은 아직 A가 아니다.
        @(bus.cb);
        bus.cb.rx_data_i  <= 8'h41;
        bus.cb.rx_valid_i <= 1'b1;
        bus.cb.tx_ready_i <= 1'b1;

        // t=15ns: 앞선 주기 A/valid/ready가 샘플된 것을 확인한다.
        @(bus.cb);
        check_case("A_ACCEPT", 8'h41, 1'b1, 1'b1);

        // t=15ns 이후: Z를 제시하지만 수신 준비를 내린다.
        bus.cb.rx_data_i  <= 8'h5A;
        bus.cb.rx_valid_i <= 1'b1;
        bus.cb.tx_ready_i <= 1'b0;

        // t=25ns: 정지(backpressure) 중에는 ready=0이다.
        @(bus.cb);
        check_case("Z_STALL", 8'h5A, 1'b1, 1'b0);

        // (중요) 수락될 때까지 Z와 valid=1을 유지한다.
        bus.cb.tx_ready_i <= 1'b1;

        // t=35ns: 동일한 Z 데이터가 정상 수락된 것을 확인한다.
        @(bus.cb);
        check_case("Z_ACCEPT", 8'h5A, 1'b1, 1'b1);
        bus.cb.rx_valid_i <= 1'b0;

        // t=45ns: valid가 없으므로 데이터 값은 있어도 전송하지 않는다.
        @(bus.cb);
        check_case("IDLE", 8'h5A, 1'b0, 1'b1);

        // (추가) 네 관찰 사례 모두 완료되었는지 확인한다.
        if (checked != 4)
            $fatal(1, "FAIL COUNT checked=%0d expected=4", checked);
        $display("CH07 PASS: %0d cases checked", checked);
        $finish;
    end
endmodule

// (추가) DUT에는 클록을 연결하지 않는다.
// tb_clk은 오직 테스트벤치의 구동·관찰 경계를 정의한다.
module tb_uart_interface;
    logic tb_clk = 1'b0;
    always #5 tb_clk = ~tb_clk;

    uart_stream_if   stream(tb_clk);
    uart_echo_bind   adapter(stream);
    uart_stream_agent agent(stream);

`ifdef VCD
    // (변경) Verilator 실행 시 파형 기록을 활성화한다.
    initial begin
        $dumpfile("ch07_uart_interface.vcd");
        $dumpvars(0, tb_uart_interface);
    end
`endif

    // 정지 상태나 입력 오류로 무한 대기할 때 검사한다.
    initial begin
        #200;
        $fatal(1, "CH07 TIMEOUT: clocking block sequence did not finish");
    end
endmodule

07오류 분석과 검증 범위

네 관찰 사례가 모두 완료되어 checked가 4일 때만 최종 PASS를 출력합니다.

현상확인 방법
clocking/modport 문법 오류설치된 시뮬레이터 지원표와 interface 선행 컴파일
첫 관찰 값 불일치5ns 구동과 15ns 첫 검사를 구분
Z_STALL 오류데이터 5A, valid 1, ready 0 확인
Z_ACCEPT 오류대기 구간에 data/valid를 유지했는지 확인
TIMEOUTtb_clk의 상승 에지 및 @(bus.cb) 이벤트 확인

반례: 첫 5ns 이벤트에서 A를 즉시 검사하면 아직 A의 샘플이 아닙니다. 대기 중 데이터를 바꾸면 Z 유지 시나리오를 위반합니다. 네 사례의 비교는 해당 조건의 전달을 확인할 뿐 모든 프로토콜 규칙을 증명하지 않습니다.

다음 장은 class(클래스, 객체 설계 단위), extends(익스텐즈, 상속), rand(랜드, 무작위 변수), constraint(컨스트레인트, 입력 제약)를 통해 거래 데이터를 객체로 표현합니다.
