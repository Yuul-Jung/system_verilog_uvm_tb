00학습 개요

제09장에서는 참조 모델과 스코어보드로 일반 동작을 비교했습니다. 이번에는 Corner Case(코너 케이스, 경계조건)와 Fault Injection(폴트 인젝션, 의도적 비정상 조건 주입)을 다룹니다. 0%·100% 듀티, 동작 중 리셋, 적용 지연 타임아웃을 각각 검사합니다.

교시시간핵심 활동
1교시0~60분실제 포트·시간 계약, 경계값과 리셋 시험 설계
2교시60~120분전체 TB·스크립트, 예상 출력, 장애 분석

011교시 ① · 실제 DUT 계약 (0~20분)

읽기 전용 DUT는 reference_rtl/pwm_core.v의 pwm_core입니다. 입력 7개(clk, resetn, cfg_apply, cfg_period, cfg_duty, cfg_enable, cfg_polarity)와 출력 6개(pwm_out, pending, active_period, active_duty, active_enable, active_polarity)를 그대로 연결합니다.

RESET_PERIOD=8로 시험하므로 주기 8클록, 클록은 10ns입니다. cfg_apply는 Shadow(섀도, 대기 설정)를 기록하며 pending이 1로 됩니다. 주기 경계에서 활성값이 갱신됩니다. 리셋은 LOW 활성이고 내부 레지스터는 상승 에지에서 초기화되지만 pwm_out은 조합식으로 즉시 LOW 차단됩니다.

021교시 ② · 경계값과 예상 결과 (20~40분)

시나리오입력예상 출력
0%cfg_duty=016클록 모두 LOW
100%cfg_duty=816클록 모두 HIGH
동작 중 리셋resetn=0pwm_out 즉시 LOW, 다음 posedge에서 active_* 초기화
리셋 후 재시작cfg_duty=8 재요청16클록 모두 HIGH

주기 8에서 듀티 0은 counter < active_duty가 항상 거짓이고, 듀티 8은 항상 참입니다. 주기 0은 별도 입력 유효성 명세가 필요한 범위이므로 정상값으로 가정하지 않습니다.

031교시 ③ · 시간과 타임아웃 (40~60분)

요청 · negedge에서 cfg_apply 설정
↓
적용 · 주기 경계에서 active_duty 갱신
↓
비교 · posedge 후 #1에서 4상태 비교
↓
실패 처리 · 10클록 적용 상한 / 5000ns 전체 상한

테스트벤치의 #1은 DUT 지연이 아니라 비차단 대입 결과를 안정적으로 읽기 위한 관찰 지연입니다. 적용이 늦어지는 경우 무한 대기하지 않고 $fatal로 실패합니다.

042교시 ① · 실행 가능한 전체 TB (60~90분)

아래 전체 소스는 공개 13포트만 연결하며 원본 RTL 내부 상태에 접근하지 않습니다. !==는 X/Z를 포함한 4상태 비일치를 검사합니다.

tb/ch10/tb_pwm_corner_reset_timeout.sv · 전체 코드 · RTL_SIM NOT_RUN
`timescale 1ns/1ps
// 제10장: PWM 경계값, 실행 중 리셋, 타임아웃을 자동 판정한다.
// 원본 pwm_core는 수정하지 않고 공개 포트만 사용한다.
module tb_pwm_corner_reset_timeout;
    reg clk = 1'b0;
    reg resetn = 1'b0;
    reg cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8, cfg_duty = 32'd0;
    reg cfg_enable = 1'b1, cfg_polarity = 1'b0;
    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    integer checks = 0;
    integer requests = 0;

    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .pwm_out(pwm_out), .pending(pending),
        .active_period(active_period), .active_duty(active_duty),
        .active_enable(active_enable), .active_polarity(active_polarity)
    );
    always #5 clk = ~clk;

    // 실패 시 무한 대기하지 않도록 전체 시뮬레이션에 상한을 둔다.
    initial begin
        #5000;
        $fatal(1, "FAIL GLOBAL_TIMEOUT");
    end

    // 모든 검사는 NBA 갱신 뒤 수행한다.
    task check_outputs(input [31:0] expected_duty,
                       input expected_pwm, input expected_pending);
        begin
            if (active_period !== 32'd8 ||
                active_duty !== expected_duty ||
                active_enable !== 1'b1 ||
                active_polarity !== 1'b0 ||
                pending !== expected_pending ||
                pwm_out !== expected_pwm)
                $fatal(1, "FAIL t=%0t duty=%0d pwm=%b pending=%b",
                       $time, active_duty, pwm_out, pending);
            checks = checks + 1;
        end
    endtask

    // 하강 에지에서 요청을 변경하여 상승 에지 경쟁을 피한다.
    task request_duty(input [31:0] duty);
        begin
            @(negedge clk);
            cfg_period = 32'd8;
            cfg_duty = duty;
            cfg_enable = 1'b1;
            cfg_polarity = 1'b0;
            cfg_apply = 1'b1;
            @(negedge clk);
            cfg_apply = 1'b0;
            requests = requests + 1;
            if (pending !== 1'b1)
                $fatal(1, "FAIL request not pending");
        end
    endtask

    // 주기 8클록, 듀티 0 또는 8에서 모든 샘플이 일정해야 한다.
    task check_constant_window(input [31:0] duty,
                               input expected_level);
        integer i;
        begin
            request_duty(duty);
            // pending은 다음 주기 경계에서 해제된다.
            for (i = 0; i < 10 && pending !== 1'b0; i = i + 1) begin
                @(posedge clk); #1;
            end
            if (pending !== 1'b0 || active_duty !== duty)
                $fatal(1, "FAIL APPLY_TIMEOUT duty=%0d", duty);
            for (i = 0; i < 16; i = i + 1) begin
                @(posedge clk); #1;
                check_outputs(duty, expected_level, 1'b0);
            end
        end
    endtask

    initial begin
        // 동기 리셋: 첫 상승 에지 이후 초기 레지스터를 검사한다.
        @(posedge clk); #1;
        if (active_period !== 32'd8 || active_duty !== 0 ||
            active_enable !== 0 || pending !== 0 || pwm_out !== 0)
            $fatal(1, "FAIL initial reset");
        @(negedge clk);
        resetn = 1'b1;

        check_constant_window(32'd0, 1'b0); // 0%: 항상 LOW
        check_constant_window(32'd8, 1'b1); // 100%: 항상 HIGH

        // 동작 중 리셋을 하강 에지 사이에 가한다.
        #2 resetn = 1'b0;
        #1;
        if (pwm_out !== 1'b0)
            $fatal(1, "FAIL async output gate");
        @(posedge clk); #1;
        if (active_period !== 32'd8 || active_duty !== 0 ||
            active_enable !== 0 || pending !== 0 || pwm_out !== 0)
            $fatal(1, "FAIL synchronous register reset");
        @(negedge clk);
        resetn = 1'b1;

        check_constant_window(32'd8, 1'b1); // 리셋 뒤 재설정
        $display("PASS CH10 requests=%0d checks=%0d", requests, checks);
        $finish;
    end
endmodule

코드 풀이 — 핵심 구문

request_duty는 하강 에지에서 설정을 한 클록 유지합니다. check_constant_window는 pending 해제를 최대 10클록 기다린 뒤 16클록의 출력과 활성 설정을 확인합니다. check_outputs의 $fatal(1,...)은 오류가 생긴 시점에 즉시 비정상 종료합니다.

리셋 주입은 마지막 검사 상승 에지 뒤 #2에서 수행하고, #1 후 pwm_out을 확인합니다. 레지스터는 그 다음 상승 에지에서 확인하므로 조합 리셋과 동기 리셋의 차이를 직접 검증합니다.

052교시 ② · 실행과 예상 출력 (90~105분)

스크립트는 iverilog -g2012와 vvp를 사용합니다. 원본 파일은 읽기만 하고 빌드 산출물은 .build/ch10/에 생성합니다.

scripts/run_ch10.sh · 전체 코드 · RTL_SIM NOT_RUN
#!/usr/bin/env bash
# 제10장: 원본 RTL을 읽기 전용으로 사용하여 컴파일/시뮬레이션한다.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
if ! command -v iverilog >/dev/null 2>&1 || ! command -v vvp >/dev/null 2>&1; then
  echo "NOT_RUN: iverilog 또는 vvp 미설치" >&2
  exit 2
fi
test -f "$DUT_PATH" || { echo "FAIL: DUT 파일 없음" >&2; exit 1; }
mkdir -p "$ROOT/.build/ch10"
iverilog -g2012 -s tb_pwm_corner_reset_timeout -o "$ROOT/.build/ch10/sim.out" \
  "$DUT_PATH" "$ROOT/tb/ch10/tb_pwm_corner_reset_timeout.sv"
vvp "$ROOT/.build/ch10/sim.out"
예상 출력 · 실제 실행 로그 아님
PASS CH10 requests=3 checks=48

3회 설정 요청과 시나리오당 16회 검사에서 계산한 값입니다. 시뮬레이터로 실행한 결과가 아니므로 검증 PASS로 기록하지 않습니다.
