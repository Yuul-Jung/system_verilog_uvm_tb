제5부 · UVM 검증 환경

제19장 · Monitor·Agent·Scoreboard

기존 PWM RTL의 입력 구동·출력 관찰·독립 판정을 분리해 실무형 UVM 검증 구조를 완성합니다.

PART 05 · CHAPTER 191교시 60분 + 2교시 60분원본 RTL 변경 없음

00학습 개요 · 구동과 관찰을 분리하기

제18장에서는 Sequence(시퀀스, 거래 입력 순서 지정) → Sequencer(시퀀서, 거래 전달) → Driver(드라이버, 신호 구동)를 연결했습니다. 제19장에서는 Monitor(모니터, 신호를 구동하지 않고 관찰하는 컴포넌트)와 Scoreboard(스코어보드, 실제값과 독립 기준값의 비교기)를 추가합니다. Agent(에이전트, 시퀀서·드라이버·모니터를 묶는 컴포넌트)는 재사용 가능한 검증 단위가 됩니다.

구간시간실습 내용
1교시0~60분Monitor·Analysis Port·Agent·Scoreboard의 책임과 이벤트 시간표
2교시60~120분UVM 전체 TB, 컴파일·시뮬레이션, 기대값 판정과 장애 분석

기존 DUT(디유티, 검증 대상 회로)는 reference_rtl/pwm_core.v입니다. 10ns 클록·8클록 주기·LOW 활성 리셋을 그대로 사용하고, 원본 RTL은 수정하지 않습니다.

011교시 ① · Driver와 Monitor는 왜 다른가 (0~20분)

Driver는 입력 cfg_apply, cfg_duty, cfg_enable 등을 실제로 구동합니다. Monitor는 같은 pwm19_if에 연결하지만 값을 바꾸지 않고, DUT가 어떤 요청을 수락하고 언제 실제 설정을 반영했는지를 읽습니다. 두 기능을 한 곳에 섞으면 검증기가 구동한 의도와 DUT의 실제 반응을 혼동할 위험이 있습니다.

컴포넌트실제 코드주요 책임
입력 생성pwm19_sequence듀티 2→6→0 순서의 거래 생성
입력 구동pwm19_driver설정 신호를 하강 에지에 구동, 다음 요청 시점 조절
출력 관찰pwm19_monitor상승 에지 뒤 cfg_apply·pending·Active 출력 관찰
정답 비교pwm19_scoreboard독립 계획값 2/6/0과 실제 관찰값 검증
재사용 단위pwm19_agentsqr, drv, mon 생성·연결

핵심 차이: Driver는 active_duty가 정답인지 판단하지 않습니다. pending이 해제되기를 기다려 다음 요청 시점만 정합니다. 실제 출력값은 Monitor가 관찰하고 Scoreboard가 판정합니다.

021교시 ② · Analysis Port로 관찰 거래를 전달하기 (20~40분)

Monitor가 관찰할 때마다 pwm19_sample 객체를 새로 만들어 ap.write(sample)로 전달합니다. 이는 TLM(티엘엠, 거래 수준 모델링)의 Analysis(애널리시스, 관찰 결과의 단방향 전달) 통로입니다. Monitor는 값을 보내기만 하며, Scoreboard가 몇 개를 받는지 또는 어떻게 판정하는지 알 필요가 없습니다.

Analysis 연결의 핵심 구문 · SystemVerilog · 실제 소스 발췌
// Monitor 내부: 관찰 거래를 외부로 내보내는 Analysis Port
uvm_analysis_port #(pwm19_sample) ap;
ap = new("ap", this);

// Scoreboard 내부: 관찰 거래를 받아 write()를 호출하는 Imp
uvm_analysis_imp #(pwm19_sample, pwm19_scoreboard) analysis_export;
analysis_export = new("analysis_export", this);

// pwm19_env.connect_phase(): 두 컴포넌트 연결
ag.mon.ap.connect(sb.analysis_export);

// 실제 이벤트가 생겼을 때 Monitor에서 전송
ap.write(sample);

첫 번째 관찰 종류 PWM19_REQUEST는 cfg_apply를 캡처한 경우이고, 두 번째 PWM19_APPLIED는 pending이 1에서 0으로 바뀌며 설정이 반영된 경우입니다. 두 종류를 pwm19_event_kind_e로 구별하면 Scoreboard가 시간상 서로 다른 사건을 정확히 처리할 수 있습니다.

uvm_analysis_port는 보통 구동·관찰을 분리할 때 사용하는 논블로킹 전달 경로입니다. 본 예제의 write()는 함수이므로 시간을 소비하는 대기문을 포함하지 않습니다.

031교시 ③ · 독립 기대값과 시간 순서 검증 (40~50분)

관찰한 cfg_duty를 그대로 기대값으로 복사하면, Driver가 잘못된 값을 구동했을 때 그 결함을 놓칠 수 있습니다. 따라서 Scoreboard에는 planned_duty[3]에 2·6·0이라는 계획을 미리 고정합니다. Monitor가 전달한 입력 요청도 이 계획과 대조하고, 나중에 관찰한 Active 설정도 다시 대조합니다.

이벤트검사 내용예상 조건
PWM19_REQUEST요청 순서·듀티·주기·Enable·극성듀티 2→6→0, 주기 8, Enable 1
PWM19_APPLIED요청 존재·적용 듀티·Active·출력동일 순서, pending=0, 올바른 PWM
요청→반영 시간sampled_at - request_time1주기(80ns) 이내
최종 집계requests·applied둘 다 정확히 3회

현재 코드는 **서로 다른 세 설정을 순차로 요청**하며, 하나가 적용되기 전 다음 요청을 보내지 않습니다. 겹치는 설정 요청, 동일한 값의 연속 요청, 임의 리셋은 다음 확장 실습에서 별도로 검증해야 합니다. 이 제한을 구분해야 현재 Monitor의 pending 하강 검출을 일반적인 모든 PWM 상황에 적용한다고 오해하지 않습니다.

041교시 ④ · 상승 에지 이후 관찰 시간표 (50~60분)

Driver는 negedge vif.clk에서 입력을 바꾸고 DUT는 다음 posedge clk에서 요청을 읽습니다. Monitor는 같은 상승 에지의 #1 뒤에 출력을 관찰하므로 DUT 비차단 대입 결과가 반영된 상태에서 이벤트를 기록합니다.

예를 들어 첫 설정 요청은 40ns에 구동되고 45ns에 수락됩니다. Monitor는 46ns에 요청을 기록합니다. 처음 8클록의 경계가 105ns에 발생하면 Active 듀티는 2로 변하고, Monitor는 106ns에 적용 완료를 보고합니다. 이 시각은 코드에 기반한 계산 예시로, 실제 시뮬레이터 로그가 아닙니다.

052교시 ① · 전체 SystemVerilog/UVM 테스트벤치 (60~90분)

한 파일에 pwm19_if, 두 가지 거래 객체, Sequence·Sequencer·Driver·Monitor·Scoreboard·Agent·Environment·Test와 최상위 모듈을 포함합니다. 학습 흐름이 끊기지 않도록 실제 배포 파일을 아래에 전문 수록했습니다.

tb/ch19/tb_pwm_monitor_agent_scoreboard.sv · SystemVerilog · UVM 전체 TB · RTL 시뮬레이션 미실행
`timescale 1ns/1ps
// 제19장: Sequence → Sequencer → Driver와 분리된 Monitor/Agent/Scoreboard.
// 원본 pwm_core.v의 포트·RTL은 수정하지 않는다.
// 입력 요청 2→6→0의 기대값은 Scoreboard가 독립적으로 관리한다.

interface pwm19_if(input logic clk);
    logic resetn = 1'b0;
    logic cfg_apply = 1'b0;
    logic [31:0] cfg_period = 32'd8;
    logic [31:0] cfg_duty = 32'd0;
    logic cfg_enable = 1'b0;
    logic cfg_polarity = 1'b0;
    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
endinterface

package ch19_uvm_pkg;
    import uvm_pkg::*;
    `include "uvm_macros.svh"

    typedef enum {PWM19_REQUEST, PWM19_APPLIED} pwm19_event_kind_e;

    // (추가) Sequence가 Driver로 보내는 설정 거래.
    class pwm19_item extends uvm_sequence_item;
        bit [31:0] duty;
        `uvm_object_utils(pwm19_item)
        function new(string name="pwm19_item");
            super.new(name);
        endfunction
    endclass

    // (추가) Monitor가 관찰한 공개 신호를 담는 별도 거래.
    class pwm19_sample extends uvm_sequence_item;
        pwm19_event_kind_e kind;
        logic [31:0] duty, period;
        logic enable, polarity, pending, pwm;
        time sampled_at;
        `uvm_object_utils(pwm19_sample)
        function new(string name="pwm19_sample");
            super.new(name);
        endfunction
    endclass

    // (유지/확장) 제18장의 2, 6, 0 듀티 순서를 그대로 재사용.
    class pwm19_sequence extends uvm_sequence #(pwm19_item);
        `uvm_object_utils(pwm19_sequence)
        function new(string name="pwm19_sequence");
            super.new(name);
        endfunction
        task body();
            pwm19_item req;
            for (int i=0; i<3; i++) begin
                req = pwm19_item::type_id::create($sformatf("req_%0d", i));
                start_item(req);
                case (i)
                    0: req.duty = 32'd2;
                    1: req.duty = 32'd6;
                    default: req.duty = 32'd0;
                endcase
                finish_item(req);
            end
        endtask
    endclass

    class pwm19_sequencer extends uvm_sequencer #(pwm19_item);
        `uvm_component_utils(pwm19_sequencer)
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
    endclass

    // (변경) Driver는 입력 신호만 구동하고 응답의 정답 판정은 하지 않는다.
    class pwm19_driver extends uvm_driver #(pwm19_item);
        `uvm_component_utils(pwm19_driver)
        virtual pwm19_if vif;
        int unsigned driven = 0;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(virtual pwm19_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "pwm19_if missing")
        endfunction
        task drive_one(pwm19_item req);
            int guard;
            @(negedge vif.clk);
            vif.cfg_period = 32'd8;
            vif.cfg_duty = req.duty;
            vif.cfg_enable = 1'b1;
            vif.cfg_polarity = 1'b0;
            vif.cfg_apply = 1'b1;
            @(negedge vif.clk);
            vif.cfg_apply = 1'b0;

            // 대기 신호를 통해 다음 요청을 언제 보낼지만 제어한다.
            // 실제 적용 듀티·출력 판정은 Monitor/Scoreboard의 책임.
            guard = 0;
            while (vif.pending !== 1'b0) begin
                @(negedge vif.clk);
                guard++;
                if (guard > 12)
                    `uvm_fatal("DRV_TIMEOUT", "pending was not cleared")
            end
            driven++;
        endtask
        task run_phase(uvm_phase phase);
            pwm19_item req;
            forever begin
                seq_item_port.get_next_item(req);
                drive_one(req);
                seq_item_port.item_done();
            end
        endtask
    endclass

    // (추가) Monitor는 DUT 출력/입력을 관찰할 뿐 신호를 구동하지 않는다.
    class pwm19_monitor extends uvm_monitor;
        `uvm_component_utils(pwm19_monitor)
        virtual pwm19_if vif;
        uvm_analysis_port #(pwm19_sample) ap;
        bit previous_pending = 1'b0;

        function new(string name, uvm_component parent);
            super.new(name, parent);
            ap = new("ap", this);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(virtual pwm19_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "pwm19_if missing")
        endfunction
        task run_phase(uvm_phase phase);
            pwm19_sample sample;
            forever begin
                @(posedge vif.clk);
                #1; // DUT의 비차단 대입 완료 이후 공개 출력 관찰
                if (!vif.resetn) begin
                    previous_pending = 1'b0;
                end else begin
                    if (vif.cfg_apply === 1'b1) begin
                        sample = pwm19_sample::type_id::create("request_sample");
                        sample.kind = PWM19_REQUEST;
                        sample.duty = vif.cfg_duty;
                        sample.period = vif.cfg_period;
                        sample.enable = vif.cfg_enable;
                        sample.polarity = vif.cfg_polarity;
                        sample.pending = vif.pending;
                        sample.pwm = vif.pwm_out;
                        sample.sampled_at = $time;
                        ap.write(sample);
                    end
                    // 이번 실습의 요청은 순차적으로만 전달한다.
                    // pending이 1→0이 되는 경계를 실제 적용 완료로 관찰.
                    if (previous_pending && vif.pending === 1'b0) begin
                        sample = pwm19_sample::type_id::create("applied_sample");
                        sample.kind = PWM19_APPLIED;
                        sample.duty = vif.active_duty;
                        sample.period = vif.active_period;
                        sample.enable = vif.active_enable;
                        sample.polarity = vif.active_polarity;
                        sample.pending = vif.pending;
                        sample.pwm = vif.pwm_out;
                        sample.sampled_at = $time;
                        ap.write(sample);
                    end
                    previous_pending = (vif.pending === 1'b1);
                end
            end
        endtask
    endclass

    // (추가) Analysis Imp를 통해 Monitor의 관찰 거래를 받는다.
    // '정답 2→6→0'은 DUT에서 읽지 않고 검증 기준으로 별도 보관.
    class pwm19_scoreboard extends uvm_scoreboard;
        `uvm_component_utils(pwm19_scoreboard)
        uvm_analysis_imp #(pwm19_sample, pwm19_scoreboard) analysis_export;
        int unsigned requests = 0;
        int unsigned applied = 0;
        bit [31:0] planned_duty[3] = '{32'd2, 32'd6, 32'd0};
        time request_time[3];

        function new(string name, uvm_component parent);
            super.new(name, parent);
            analysis_export = new("analysis_export", this);
        endfunction

        function void write(pwm19_sample sample);
            if (sample.kind == PWM19_REQUEST) begin
                if (requests >= 3)
                    `uvm_fatal("SB_EXTRA", "Unexpected extra PWM request")
                if (sample.period !== 32'd8 ||
                    sample.duty !== planned_duty[requests] ||
                    sample.enable !== 1'b1 ||
                    sample.polarity !== 1'b0 ||
                    sample.pending !== 1'b1)
                    `uvm_fatal("SB_REQUEST", "Unexpected PWM request content")
                request_time[requests] = sample.sampled_at;
                requests++;
                `uvm_info("SB", $sformatf(
                    "REQUEST %0d duty=%0d", requests, sample.duty), UVM_LOW)
            end else if (sample.kind == PWM19_APPLIED) begin
                if (applied >= requests || applied >= 3)
                    `uvm_fatal("SB_ORDER", "Applied event without request")
                if (sample.period !== 32'd8 ||
                    sample.duty !== planned_duty[applied] ||
                    sample.enable !== 1'b1 ||
                    sample.polarity !== 1'b0 ||
                    sample.pending !== 1'b0 ||
                    sample.pwm !== (planned_duty[applied] != 0))
                    `uvm_fatal("SB_APPLY", "Applied PWM config/output mismatch")
                // RESET_PERIOD=8이고 요청을 순차 제출하므로 80ns 이내.
                if (sample.sampled_at < request_time[applied] ||
                    sample.sampled_at - request_time[applied] > 80)
                    `uvm_fatal("SB_LATENCY", "PWM apply exceeded one period")
                applied++;
                `uvm_info("SB", $sformatf(
                    "APPLIED %0d duty=%0d", applied, sample.duty), UVM_LOW)
            end else begin
                `uvm_fatal("SB_KIND", "Unknown monitor sample kind")
            end
        endfunction
    endclass

    // (추가) Agent가 Sequencer, Driver, Monitor를 한 단위로 묶는다.
    class pwm19_agent extends uvm_agent;
        `uvm_component_utils(pwm19_agent)
        pwm19_sequencer sqr;
        pwm19_driver drv;
        pwm19_monitor mon;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            sqr = pwm19_sequencer::type_id::create("sqr", this);
            drv = pwm19_driver::type_id::create("drv", this);
            mon = pwm19_monitor::type_id::create("mon", this);
        endfunction
        function void connect_phase(uvm_phase phase);
            super.connect_phase(phase);
            drv.seq_item_port.connect(sqr.seq_item_export);
        endfunction
    endclass

    class pwm19_env extends uvm_env;
        `uvm_component_utils(pwm19_env)
        pwm19_agent ag;
        pwm19_scoreboard sb;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            ag = pwm19_agent::type_id::create("ag", this);
            sb = pwm19_scoreboard::type_id::create("sb", this);
        endfunction
        function void connect_phase(uvm_phase phase);
            super.connect_phase(phase);
            ag.mon.ap.connect(sb.analysis_export);
        endfunction
    endclass

    class pwm19_test extends uvm_test;
        `uvm_component_utils(pwm19_test)
        virtual pwm19_if vif;
        pwm19_env env;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            env = pwm19_env::type_id::create("env", this);
            if (!uvm_config_db#(virtual pwm19_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "pwm19_if missing in test")
        endfunction
        task run_phase(uvm_phase phase);
            pwm19_sequence seq;
            phase.raise_objection(this);
            repeat (3) @(negedge vif.clk);
            if (vif.active_period !== 32'd8 ||
                vif.active_duty !== 32'd0 || vif.pending !== 1'b0)
                `uvm_fatal("RESET", "PWM reset did not complete")
            vif.resetn = 1'b1;
            seq = pwm19_sequence::type_id::create("seq");
            seq.start(env.ag.sqr);
            repeat (2) @(negedge vif.clk);
            if (env.ag.drv.driven != 3 ||
                env.sb.requests != 3 || env.sb.applied != 3)
                `uvm_fatal("SB_COUNT", "Missing driver/monitor/scoreboard events")
            `uvm_info("RESULT", "PASS CH19 requests=3 applied=3", UVM_NONE)
            phase.drop_objection(this);
        endtask
    endclass
endpackage

endmodule

코드 풀이 — 다섯 가지 연결을 읽는 순서

pwm19_agent.build_phase()는 sqr·drv·mon을 만들고, connect_phase()에서 Driver와 Sequencer를 연결합니다. pwm19_env.connect_phase()에서는 ag.mon.ap를 sb.analysis_export에 연결합니다. 이 두 연결이 없으면 거래가 입력으로 전달되지 않거나, 관찰 결과가 Scoreboard에 도달하지 못합니다.

Monitor가 새로운 pwm19_sample을 생성할 때마다 kind, duty, period, enable, polarity, pending, pwm, sampled_at을 채웁니다. Scoreboard의 write()는 kind에 따라 요청 검사와 반영 검사를 분리합니다.

검사 실패 시 SB_REQUEST, SB_APPLY, SB_ORDER, SB_LATENCY 등의 진단으로 중단합니다. 셋 모두 반영되었다는 최종 결과는 pwm19_test에서 집계값을 확인한 뒤 출력합니다.

제17·18장의 환경처럼 UVM 라이브러리와 이를 지원하는 시뮬레이터가 있어야 합니다. 예제 실행 스크립트는 Verilator(베릴레이터, Verilog/SystemVerilog 시뮬레이터)와 UVM_HOME(UVM 소스 설치 폴더 환경변수)을 사용하며, 버전별 UVM 기능 지원 여부는 설치된 환경에서 실제 빌드로 확인합니다.

scripts/run_ch19.sh · Bash · 실행 스크립트 전체 · 미실행
#!/usr/bin/env bash
# 제19장: 실제 UVM 라이브러리·시뮬레이터가 있는 환경에서 실행한다.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
TB_PATH="$ROOT/tb/ch19/tb_pwm_monitor_agent_scoreboard.sv"
OUT="$ROOT/.build/ch19"

if [[ ! -f "$DUT_PATH" ]]; then
  echo "NOT_RUN: PWM DUT not found: $DUT_PATH" >&2
  exit 2
fi
if ! command -v verilator >/dev/null 2>&1; then
  echo "NOT_RUN: Verilator not installed" >&2
  exit 2
fi
if [[ -z "${UVM_HOME:-}" || ! -f "$UVM_HOME/src/uvm_pkg.sv" ]]; then
  echo "NOT_RUN: UVM_HOME/src/uvm_pkg.sv missing" >&2
  exit 2
fi

mkdir -p "$OUT"
verilator --version | tee "$OUT/tool_version.txt"

# --timing: 시간·이벤트 제어; --assert: 런타임 검증 활성화.
# UVM 호환성은 Verilator 버전과 사용하는 UVM 라이브러리에 따라 달라진다.
verilator --binary --timing --assert --trace -Wno-fatal \
  --top-module tb_pwm_monitor_agent_scoreboard \
  --Mdir "$OUT/obj_dir" \
  +incdir+"$UVM_HOME/src" \
  "$UVM_HOME/src/uvm_pkg.sv" "$DUT_PATH" "$TB_PATH" \
  2>&1 | tee "$OUT/build.log"

(cd "$OUT" && ./obj_dir/Vtb_pwm_monitor_agent_scoreboard \
  +UVM_TESTNAME=pwm19_test | tee simulation.log)

# 단순 종료 코드 외에 Scoreboard 완료 기록도 반드시 확인한다.
# UVM 리포트의 "UVM_ERROR : 0"은 정상 요약이므로 오류로 보지 않는다.
grep -q 'PASS CH19 requests=3 applied=3' "$OUT/simulation.log" || {
  echo "FAIL: Monitor 또는 Scoreboard 검증이 완료되지 않음" >&2
  exit 1
}
if grep -Eq 'UVM_(FATAL|ERROR) @[[:space:]]*[0-9]+|UVM_(FATAL|ERROR)[[:space:]]*:[[:space:]]*[1-9]' "$OUT/simulation.log"; then
  echo "FAIL: UVM 오류 메시지 확인" >&2
  exit 1
fi
echo "PASS CH19 SUITE: 3 requests and 3 applied observations"

--binary는 실행 파일을 생성하고, --timing은 시뮬레이션의 시간·이벤트 제어를 활성화하며, --assert는 어설션 실행을 활성화합니다. --trace는 파형 기록을 지원합니다. UVM 환경이 없다면 먼저 사용 중인 시뮬레이터가 해당 UVM 라이브러리를 지원하는지 확인합니다.

072교시 ③ · 예상 출력의 의미 (105~112분)

다음은 출력 형태를 이해하기 위한 예상 로그입니다. 각 거래의 REQUEST와 APPLIED가 1:1로 대응하며, 세 거래를 모두 처리했을 때만 최종 PASS 문자열이 출력되도록 작성했습니다. 아직 실제 컴파일·실행해서 얻은 로그는 아닙니다.

simulation.log 핵심 메시지 · TEXT · 예상 출력 · RTL_SIM=NOT_RUN
UVM_INFO ... [SB] REQUEST 1 duty=2
UVM_INFO ... [SB] APPLIED 1 duty=2
UVM_INFO ... [SB] REQUEST 2 duty=6
UVM_INFO ... [SB] APPLIED 2 duty=6

092교시 ⑤ · 핵심 정리와 다음 장 (118~120분)

① Sequence가 거래를 생성합니다. ② Sequencer가 Driver에 전달합니다. ③ Driver가 DUT 입력을 구동합니다. ④ Monitor가 DUT의 공개 출력만 관찰해 ap.write()로 보냅니다. ⑤ Scoreboard는 미리 정한 계획과 실제 관찰값을 비교합니다. ⑥ Agent는 Sequencer·Driver·Monitor를 재사용 가능한 단위로 묶습니다.

완료 기준은 세 요청과 세 적용 이벤트를 분리해서 설명하고, UVM Analysis 통로의 실제 연결 코드와 데이터 흐름을 추적할 수 있는 것입니다. 본 제작 환경은 Verilator와 UVM 라이브러리를 사용할 수 없어 RTL_SIM=NOT_RUN 상태입니다.

다음 제20장: UVM Factory(팩토리, 구현 교체), Config DB(설정 데이터베이스), Objection(옵젝션, 검증 종료 제어)을 사용해 같은 환경에서 테스트 설정과 컴포넌트 구성을 재사용합니다.

10참고 · 원본 pwm_core의 전체 RTL

동작 비교에 사용한 원본은 reference_rtl/pwm_core.v입니다. 아래 원본 코드는 검증 포트의 실제 이름과 주기 경계 조건을 확인하기 위한 참고 자료이며 이번 장에서 변경하지 않았습니다.

reference_rtl/pwm_core.v · Verilog · 읽기 전용 DUT 원본 · SHA e813f3fb107bd327054d11e0b397817b8e7bd813
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

cfg_apply는 Shadow 설정 요청, pending은 적용 대기, active_duty는 실제 활성 듀티, pwm_out은 최종 출력입니다. Monitor와 Scoreboard의 신호 이름·도식·설명은 이 실제 포트에 맞춰 작성했습니다.
