제04장 · PASS/FAIL 자동 판정

기존 PWM RTL에서 기대값과 실제 출력을 비교하여 PASS/FAIL을 자동 판정하는 2시간 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00학습 개요 · 관찰에서 자동 판정으로

제03장은 PWM 출력의 HIGH 횟수를 관찰했습니다. 이번 장은 기대값과 실제 출력의 일치 여부를 자동 판정합니다. Testbench(테스트벤치, 검증용 시뮬레이션 코드)는 정상 동작을 확인하고 오류 발생 시 그 원인을 찾도록 설계해야 합니다.

시간주요 내용완료 결과
1교시 · 60분if, ===, !==, $error, $fatal, 비교 시점검증 조건 작성
2교시 · 60분기존 PWM RTL 검증 TB, 실행, 로그·파형 분석자동 PASS/FAIL

원본 part02_1/ch04/rtl/pwm_core.v를 변경하지 않고, TB에서 RESET_PERIOD=8을 지정합니다.

011교시 ① · if와 4상태 비교 (0~20분)

if(이프, 조건 분기)는 조건이 참일 때 실행합니다. RTL 신호에는 0과 1뿐 아니라 X(미정), Z(고임피던스)가 있습니다. ==는 X/Z가 섞이면 비교 결과도 X가 될 수 있지만 ===와 !==는 네 상태를 명시적으로 비교합니다.

4상태 비교 · 교육용 구문
reg actual = 1'bx;
reg expected = 1'b0;
$display("logical=%b", actual == expected); // X 가능
if (actual !== expected)
    $display("MISMATCH detected");

검증에서는 기대값을 명확한 0 또는 1로 정의하고, 실제값이 X/Z이면 불일치로 처리합니다. 기대값까지 X로 설정하면 ===는 X와 X를 일치로 판단하므로 정상 출력 검증에는 주의해야 합니다.

021교시 ② · $error와 $fatal (20~40분)

$error(에러, 오류 메시지 기록)는 검사 실패를 기록하면서 다른 입력 조건을 계속 시험할 수 있습니다. $fatal(페이털, 치명적 오류로 종료)는 더 진행할 수 없거나 최종 결과가 실패일 때 사용합니다.

검사·오류 누적 · 실제 TB 구문
checks = checks + 1;
if (actual !== expected) begin
    errors = errors + 1;
    $error("MISMATCH actual=%b expected=%b", actual, expected);
end
// 최종 오류가 0개이면 PASS, 그렇지 않으면 $fatal(1, ...)

오류를 단순 출력하는 것만으로는 자동 검증이 완성되지 않습니다. 마지막에 검사 횟수와 오류 횟수를 집계하고 실패 시 비정상 종료해야 자동 실행 환경에서 실패를 감지할 수 있습니다.

031교시 ③ · 시간 계약과 기대값 (40~60분)

기존 PWM 코어는 cfg_apply를 상승 에지에서 받아 Shadow 레지스터에 저장하고, 주기 경계에서 Active 레지스터에 반영합니다. 따라서 설정 직후 출력과 비교하면 아직 이전 듀티가 남아 있을 수 있습니다. pending이 1로 올라갔다가 0으로 내려온 뒤 검사합니다.

cfg_duty기대 HIGH기대 LOW
00/88/8
22/86/8
44/84/8
66/82/8
88/80/8

기대값은 DUT 내부 counter를 읽지 않고 입력 주기 8과 듀티 수로 독립 계산합니다. 이 장에서는 한 주기의 HIGH 표본 개수와 Active 듀티를 검증하며, 모든 클록의 위상까지 증명하지는 않습니다.

042교시 ① · 전체 테스트벤치 (60~90분)

apply_duty()는 설정 요청과 완료 대기를 담당하고, check_period()는 8개의 하강 에지에서 pwm_out을 읽습니다. check_bit()는 리셋 중 출력 LOW를 검사합니다.

tb/ch04/tb_pwm_pass_fail.sv · 전체 코드
`timescale 1ns/1ps
// CH04: 기존 pwm_core의 PASS/FAIL 자동 판정 테스트벤치.
module tb_pwm_pass_fail;
    reg clk = 1'b0;
    reg resetn = 1'b0;
    reg cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8;
    reg [31:0] cfg_duty = 32'd0;
    reg cfg_enable = 1'b1;
    reg cfg_polarity = 1'b0;
    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    integer checks = 0, errors = 0, step;

    // 원본 RTL의 13개 포트를 동일한 이름으로 연결.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn),
        .cfg_apply(cfg_apply), .cfg_period(cfg_period),
        .cfg_duty(cfg_duty), .cfg_enable(cfg_enable),
        .cfg_polarity(cfg_polarity), .pwm_out(pwm_out),
        .pending(pending), .active_period(active_period),
        .active_duty(active_duty), .active_enable(active_enable),
        .active_polarity(active_polarity)
    );
    always #5 clk = ~clk; // 10ns 주기

    // (추가) X/Z까지 검사하는 4상태 비교.
    task automatic check_bit(input reg actual, input reg expected);
        begin
            checks = checks + 1;
            if (actual !== expected) begin
                errors = errors + 1;
                $error("MISMATCH t=%0t actual=%b expected=%b",
                    $time, actual, expected);
            end
        end
    endtask

    // (추가) 설정 요청 뒤 Shadow 수락과 Active 반영을 모두 기다림.
    task automatic apply_duty(input [31:0] requested);
        begin
            @(negedge clk);
            cfg_duty = requested;
            cfg_apply = 1'b1;
            @(negedge clk);
            cfg_apply = 1'b0;
            wait (pending === 1'b1);
            wait (pending === 1'b0);
            #1; // NBA 반영 후 안정된 값 검사
            checks = checks + 1;
            if (active_duty !== requested) begin
                errors = errors + 1;
                $error("ACTIVE_DUTY expected=%0d actual=%0d",
                    requested, active_duty);
            end
            $display("APPLIED duty=%0d t=%0t", requested, $time);
        end
    endtask

    // (추가) 내부 counter를 참조하지 않는 독립 기준값.
    task automatic check_period(input integer duty_ticks);
        integer sample, high_count;
        begin
            high_count = 0;
            for (sample = 0; sample < 8; sample = sample + 1) begin
                @(negedge clk);
                if (pwm_out === 1'b1)
                    high_count = high_count + 1;
                if ((pwm_out !== 1'b0) && (pwm_out !== 1'b1)) begin
                    errors = errors + 1;
                    $error("UNKNOWN_PWM sample=%0d pwm=%b",
                        sample, pwm_out);
                end
            end
            checks = checks + 1;
            if (high_count !== duty_ticks) begin
                errors = errors + 1;
                $error("HIGH_COUNT duty=%0d expected=%0d actual=%0d",
                    duty_ticks, duty_ticks, high_count);
            end
            $display("CHECK duty=%0d high=%0d/8 expected=%0d/8",
                duty_ticks, high_count, duty_ticks);
        end
    endtask

    initial begin
        $dumpfile("ch04_pwm_pass_fail.vcd");
        $dumpvars(0, tb_pwm_pass_fail);
    end
    initial begin
        #2000;
        $fatal(1, "TIMEOUT: pending 적용 완료 대기 초과");
    end
    initial begin
        $display("=== CH04 PWM SELF-CHECK START ===");
        repeat (2) @(negedge clk);
        check_bit(pwm_out, 1'b0);
        resetn = 1'b1;
        for (step = 0; step <= 8; step = step + 2) begin
            apply_duty(step);
            check_period(step);
        end
        if (errors == 0) begin
            $display("PASS checks=%0d errors=0", checks);
            $finish;
        end else begin
            $fatal(1, "FAIL checks=%0d errors=%0d", checks, errors);
        end
    end
endmodule

코드 풀이 — 입력, 관찰, 판정

for (step = 0; step <= 8; step = step + 2)는 듀티 0·2·4·6·8을 순서대로 적용합니다. wait(pending === 1'b1)는 설정 수락, wait(pending === 1'b0)는 적용 완료를 의미합니다. check_period()의 HIGH 개수는 DUT 내부 상태를 참조하지 않고 계산한 기대값과 비교됩니다.

검사 항목은 리셋 1회, Active 듀티 5회, HIGH 표본 수 5회로 총 11회입니다. X/Z 표본은 추가 오류로 기록됩니다.

052교시 ② · Ubuntu 실행 (90~105분)

scripts/run_ch04.sh · 전체 코드
#!/usr/bin/env bash
# CH04: 기존 PWM RTL을 읽기 전용으로 참조하는 자동 검증.
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
COURSE_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
DUT_PATH="${DUT_PATH:-$COURSE_ROOT/reference_rtl/pwm_core.v}"
TB_PATH="$COURSE_ROOT/tb/ch04/tb_pwm_pass_fail.sv"
OUT_DIR="$COURSE_ROOT/.build/ch04"
for tool in iverilog vvp; do
  command -v "$tool" >/dev/null 2>&1 || {
    echo "ERROR: $tool 없음. sudo apt install iverilog"; exit 2;
  }
done
[[ -f "$DUT_PATH" ]] || { echo "ERROR: DUT 파일 없음: $DUT_PATH"; exit 2; }
mkdir -p "$OUT_DIR"
iverilog -g2012 -s tb_pwm_pass_fail -o "$OUT_DIR/simulation.vvp" \
  "$DUT_PATH" "$TB_PATH"
(cd "$OUT_DIR" && vvp simulation.vvp | tee output.log)
echo "로그: $OUT_DIR/output.log"
echo "파형: $OUT_DIR/ch04_pwm_pass_fail.vcd"

원본 RTL의 위치가 다르면 DUT_PATH=/실제/경로/pwm_core.v bash scripts/run_ch04.sh로 지정합니다. 컴파일 결과와 VCD(브이시디, 신호 변화 기록)는 .build/ch04/에 저장합니다.

08참고 · 원본 pwm_core

아래 코드는 실제 DUT의 수정되지 않은 원본입니다. 본문 신호와 테스트벤치의 포트 연결은 이 원본에 일치합니다.

part02_1/ch04/rtl/pwm_core.v · 원본 전체
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule
