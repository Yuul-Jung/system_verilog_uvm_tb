제01장 · 테스트벤치의 첫 실행

원본 UART Echo RTL을 변경하지 않고 입력 자극과 출력 관찰을 수행하는 첫 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00출발점 · 검증할 대상과 목표

이번 장은 회로를 새로 설계하지 않습니다. 이미 있는 uart_echo_controller에 테스트벤치를 연결해 어떤 입력을 주었고, 어떤 출력이 나타났는지 시간 순서대로 관찰합니다. 제1장은 파형 관찰, 제4장에서 자동 PASS/FAIL 판정으로 발전합니다.

총 2시간입니다. 1교시(0~60분)에는 구조·자료형·입력 포트를 이해하고, 2교시(60~120분)에는 입력 자극 작성·실행·결과 해석을 진행합니다.

011교시 · Testbench와 DUT 역할 구분 (0~30분)

DUT(Device Under Test, 디바이스 언더 테스트, 검증 대상 회로)는 실제 기능을 가진 원본 모듈입니다. Testbench(테스트벤치, 시험 환경)는 DUT의 입력을 흉내 내고 출력을 관찰하는 시뮬레이션 전용 코드입니다. FPGA 보드가 없어도 시간이 흐르는 상황을 만들어 입출력 관계를 검토할 수 있습니다.

포트방향의미
rx_data_i[7:0]입력전달할 8비트 데이터
rx_valid_i입력데이터가 유효한지 표시
tx_ready_i입력뒤쪽에서 받을 준비가 되었는지 표시
tx_data_o[7:0]출력전달되는 데이터
tx_valid_o출력전달 데이터의 유효 표시
rx_ready_o출력앞쪽에 전달하는 준비 신호

이 DUT는 물리 UART의 시작 비트·전송속도·정지 비트를 구현한 회로가 아니라 Byte Stream(바이트 스트림, 바이트 데이터 흐름)을 조합적으로 전달하는 컨트롤러입니다. 따라서 아직 시리얼 비트 시간을 검사하지 않습니다.

021교시 · 원본 RTL을 읽고 테스트벤치 문법 준비 (30~60분)

원본은 amd_soc_rtl/part03/common/rtl/uart_echo_controller.v입니다. 기존 코드를 바꾸지 않고 그대로 검증합니다.

uart_echo_controller.v · Verilog · 기존 원본 · 수정 없음
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule

assign rx_ready_o = tx_ready_i;는 뒤쪽 준비 상태를 앞쪽에 그대로 전달합니다. assign tx_valid_o = rx_valid_i;는 유효 신호를 전달하고, assign tx_data_o = rx_data_i;는 8비트 데이터가 그대로 통과한다는 뜻입니다.

문법쉬운 의미
`timescale 1ns/1ps시간 단위는 1ns, 시뮬레이션 시간 정밀도는 1ps
module ... endmodule시험 환경 하나의 시작과 끝
reg / wireTB가 값을 넣는 변수 / DUT 출력 연결 신호 (이번 예제의 Verilog 방식)
initial begin ... end시뮬레이션 시작 시 한 번 수행하는 절차
#10이 파일의 시간 단위로 10ns 진행
$display / $finish관찰 값을 출력 / 시뮬레이션 종료

032교시 · 테스트벤치 전체 코드 (60~90분)

다음 코드는 네 가지 상황을 10ns 간격으로 차례로 만들어 출력합니다. 20ns에 문자 A(0x41)를 보내고, 30ns에는 tx_ready_i를 0으로 내려 준비 신호의 변화를 관찰합니다.

tb/ch01/tb_uart_echo_basics.sv · SystemVerilog · 교육용 신규 코드 · 시뮬레이션 미실행
`timescale 1ns/1ps
// 제01장: 기존 UART Echo Controller의 입출력을 관찰하는 첫 테스트벤치.
// 이 단계는 출력 표시가 목적이며, 자동 PASS/FAIL은 제04장에서 학습한다.
module tb_uart_echo_basics;
    // TB가 직접 구동하는 DUT 입력은 reg로 선언한다.
    reg  [7:0] rx_data_i;
    reg        rx_valid_i;
    reg        tx_ready_i;

    // DUT가 구동하는 출력은 wire로 관찰한다.
    wire       rx_ready_o;
    wire [7:0] tx_data_o;
    wire       tx_valid_o;

    // 기존 RTL의 실제 포트 이름과 1:1로 연결한다.
    uart_echo_controller dut (
        .rx_data_i (rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o (tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

`ifdef VCD
    // Icarus Verilog 사용 시 -DVCD 옵션으로 파형 저장 기능을 켠다.
    initial begin
        $dumpfile("ch01_uart_echo.vcd");
        $dumpvars(0, tb_uart_echo_basics);
    end
`endif

    initial begin
        $display("=== CH01 UART ECHO TESTBENCH START ===");

        // 10ns: 유효 데이터가 없고 송신 준비도 안 된 상태.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 20ns: 문자 'A'(ASCII 0x41)를 정상 전달한다.
        rx_data_i  = 8'h41;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 30ns: 뒤쪽 준비 신호를 내려 전송 대기를 관찰한다.
        rx_data_i  = 8'h5A;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 40ns: 유효 데이터 없이 준비 신호만 켠다.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        $display("=== CH01 END: OBSERVATION ONLY ===");
        $finish;
    end
endmodule

코드 풀이 — 이 코드가 무엇을 하는가

① reg 입력에 값을 대입합니다. ② #10으로 조합회로 출력이 안정될 시간을 둡니다. ③ $display로 원본 RTL 출력 세 가지를 확인합니다. ④ 네 번째 상황까지 마치면 $finish로 끝냅니다. VCD(브이시디, 신호 변화 기록 파일)는 -DVCD로 켜며 파형 확인에 활용합니다.

042교시 · Ubuntu에서 컴파일·실행 (90~105분)

처음 한 번 Icarus Verilog(아이카루스 베릴로그, 오픈소스 HDL 시뮬레이터)를 설치합니다. 원본 RTL이 현재 폴더의 상위 part03에 있다는 전제로 실행 스크립트를 제공하며, 독립 저장소에서 실행할 때는 DUT_PATH로 원본 경로를 지정합니다.

Ubuntu 터미널 · Bash · 실행 명령 · 미실행
# ① 시뮬레이터 설치: Verilog 코드를 컴파일하고 실행할 도구를 설치합니다.
sudo apt update
sudo apt install -y iverilog

# ② 학습안내서 폴더로 이동합니다.
cd /path/to/system_verilog_uvm_tb

# ③ 원본 RTL과 TB를 컴파일한 뒤, 출력과 파형을 생성합니다.
bash scripts/run_ch01.sh

# ④ 필요 시 파형 분석 도구를 설치하고 VCD 파일을 열 수 있습니다.
sudo apt install -y gtkwave
gtkwave .build/ch01/ch01_uart_echo.vcd
scripts/run_ch01.sh · Bash · 교육용 신규 실행 스크립트 · 미실행
#!/usr/bin/env bash
# 제01장 실행: 원본 RTL은 수정하지 않고 테스트벤치만 컴파일한다.
set -euo pipefail

# 이 스크립트가 어느 경로에서 실행되어도 과정 폴더를 찾는다.
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
COURSE_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"

# amd_soc_rtl 저장소 안의 과정 폴더를 기준으로 원본 RTL 경로를 지정한다.
# 별도 저장소로 이동한 경우에는 DUT_PATH 환경변수로 경로를 넘긴다.
DUT_PATH="${DUT_PATH:-$COURSE_ROOT/reference_rtl/uart_echo_controller.v}"
TB_PATH="$COURSE_ROOT/tb/ch01/tb_uart_echo_basics.sv"
OUT_DIR="$COURSE_ROOT/.build/ch01"

if ! command -v iverilog >/dev/null 2>&1; then
  echo "ERROR: iverilog 명령을 찾을 수 없습니다. sudo apt install iverilog"
  exit 2
fi
if ! command -v vvp >/dev/null 2>&1; then
  echo "ERROR: vvp 명령을 찾을 수 없습니다. Icarus Verilog 설치를 확인하세요."
  exit 2
fi
if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 원본 RTL 파일 없음: $DUT_PATH"
  echo "예: DUT_PATH=/절대경로/uart_echo_controller.v bash scripts/run_ch01.sh"
  exit 2
fi

mkdir -p "$OUT_DIR"
# -g2012: SystemVerilog 2012 문법, -DVCD: 파형 기록 기능 활성화.
iverilog -g2012 -DVCD -s tb_uart_echo_basics \
  -o "$OUT_DIR/tb.out" "$DUT_PATH" "$TB_PATH"

# VCD 파일과 로그를 실행 폴더에 기록한다.
(cd "$OUT_DIR" && vvp ./tb.out | tee output.log)
echo "파형 파일: $OUT_DIR/ch01_uart_echo.vcd"

일반적으로 시뮬레이션 출력은 .build/ch01/output.log, 파형은 .build/ch01/ch01_uart_echo.vcd에 생성됩니다. 두 파일은 시뮬레이터가 실제로 실행되었을 때만 생깁니다.

052교시 · 예상 출력과 파형 해석 (105~115분)

다음은 원본의 조합 연결을 근거로 계산한 예상 출력입니다. 실제 실행 로그가 아니며, 시뮬레이터 버전에 따라 부가 메시지가 붙을 수 있습니다.

콘솔 출력 · TEXT · 예상 결과 · 실제 실행 미확인
=== CH01 UART ECHO TESTBENCH START ===
t=10 ns rx=00 rv=0 tr=0 | tx=00 tv=0 rr=0
t=20 ns rx=41 rv=1 tr=1 | tx=41 tv=1 rr=1
t=30 ns rx=5a rv=1 tr=0 | tx=5a tv=1 rr=0
t=40 ns rx=00 rv=0 tr=1 | tx=00 tv=0 rr=1
=== CH01 END: OBSERVATION ONLY ===
시간상황예상 결과의 핵심
10ns유효 데이터 없음, 준비 안 됨tv=0, rr=0
20nsA 데이터 유효, 준비 완료tx=41, tv=1, rr=1
30nsZ 데이터 유효, 뒤쪽 준비 안 됨tx=5a, tv=1, rr=0
40ns유효 데이터 없음, 뒤쪽 준비tv=0, rr=1

주의: 30ns의 tv=1은 전송이 완료되었다는 뜻이 아닙니다. tv && tr이 1일 때만 뒤쪽 전송 승인이 성립합니다. 현재 DUT에는 데이터 저장 기능이 없으므로 앞단의 데이터 유지 책임은 연결된 시스템의 Ready/Valid 계약에 따릅니다.

06마무리 · 확인 질문과 다음 단계 (115~120분)

① initial이 시뮬레이션 시작과 동시에 실행되는 이유를 설명할 수 있습니까? ② #10과 `timescale의 관계를 말할 수 있습니까? ③ 30ns에 tx_valid_o가 1이어도 전송 승인이 성립하지 않는 이유는 무엇입니까?

이번 장의 완료 기준: DUT의 입출력을 식별하고, 테스트벤치 코드를 실행하여 10/20/30/40ns의 데이터·유효·준비 신호를 예상표와 대조합니다. 현재 저장소 제작 단계에서는 시뮬레이션 미실행(NOT_RUN)이며 사용자가 자신의 Ubuntu에서 실행 후 실제 결과를 기록할 수 있습니다.

다음 장: 제2장에서는 클록·리셋이 있는 기존 PWM RTL로 이동하여 always, posedge, negedge의 차이를 관찰합니다.
