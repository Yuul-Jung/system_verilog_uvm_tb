제2부 · SYSTEMVERILOG 문법

제07장 · 인터페이스·타이밍 분리

기존 UART Echo RTL을 보존하며 interface·modport·clocking block으로 신호와 시간을 분리하는 2시간 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00학습 개요 · 신호 이름과 시간 규칙을 한 곳에

제06장에서는 배열·큐·패키지로 여러 전송 데이터를 관리했습니다. 이번 장에서는 그 데이터가 어떤 신호 묶음을 따라 이동하며, 언제 입력되고 관찰되는지를 명확히 합니다. interface(인터페이스, 공통 신호 묶음), modport(모드포트, 접근 방향 지정), clocking block(클로킹 블록, 구동·샘플링 시점 규칙)을 함께 사용합니다.

실습 구간시간완료할 내용
1교시 · 0~60분개념과 구조6개 신호의 방향, modport, clocking block, 시간 기준
2교시 · 60~120분코드와 검증원본 UART Echo 연결, A/Z/IDLE 구동, 자동 비교, 파형 확인

기존 검증 대상은 part03/common/rtl/uart_echo_controller.v입니다. 원본은 조합회로이고 클록·리셋 포트가 없습니다. 여기서 tb_clk은 테스트벤치의 입력 변경과 출력 관찰을 맞추는 기준일 뿐, DUT 내부를 구동하는 클록이 아닙니다.

011교시 ① · interface는 신호를 묶는 그릇 (0~20분)

기존 모듈을 연결할 때는 rx_data_i, rx_valid_i, tx_ready_i와 출력 세 개를 매번 따로 선언했습니다. SystemVerilog의 interface를 사용하면 이 여섯 신호를 uart_stream_if 하나에 모아 관리합니다. 버스 신호를 여러 곳에서 동일한 이름으로 쓰는 효과가 있습니다.

실제 신호방향(DUT 기준)의미
rx_data_i[7:0]입력전달할 바이트
rx_valid_i입력앞쪽에 유효 데이터가 있음
tx_ready_i입력뒤쪽에서 수락할 준비가 됨
rx_ready_o출력앞쪽에 전달하는 준비 상태
tx_data_o[7:0]출력그대로 전달되는 바이트
tx_valid_o출력뒤쪽에 전달하는 유효 표시

원본은 rx_ready_o에 tx_ready_i를, tx_valid_o에 rx_valid_i를, tx_data_o에 rx_data_i를 조합 연결합니다. UART 프레임의 시작 비트·보레이트를 처리하는 시리얼 송수신기가 아니라 8비트 데이터의 Ready/Valid 전달 컨트롤러라는 점을 구별해야 합니다.

021교시 ② · modport는 사용할 수 있는 방향을 정한다 (20~40분)

같은 인터페이스라도 검증 환경과 DUT가 수행하는 역할은 반대입니다. modport DUT에서는 rx_data_i 등을 입력으로, tx_data_o 등을 출력으로 선언합니다. 반면 modport TB는 아래의 clocking cb를 사용하도록 접근을 지정합니다.

접근 방향 핵심 구문 · SystemVerilog · 실제 interface 코드 발췌
modport TB (clocking cb);

modport DUT (
    input  rx_data_i, rx_valid_i, tx_ready_i,
    output rx_ready_o, tx_data_o, tx_valid_o
);

기존 DUT의 포트가 uart_stream_if 형식으로 선언된 것은 아닙니다. 그래서 uart_echo_bind라는 연결 전용 Wrapper(래퍼, 외부 포트 연결 모듈)를 TB 안에 두고, 원래의 6개 포트를 인터페이스 신호와 직접 연결합니다. 이 래퍼는 데이터를 저장하거나 변형하지 않습니다.

왜 인터페이스를 DUT에 곧바로 붙이지 않을까요? 이미 동작하는 원본 RTL을 변경할 이유가 없기 때문입니다. 포트 구조를 새로운 검증 환경에 맞추기 위해 원본을 수정하면 기존 실습 결과와 비교하기 어려워집니다.

031교시 ③ · clocking block은 시간의 약속이다 (40~60분)

같은 상승 에지에 TB가 값을 변경하면서 즉시 DUT 출력을 검사하면 시뮬레이터 내부의 이벤트 순서에 따라 다른 결과를 볼 수 있습니다. clocking block은 언제 입력을 구동하고 언제 DUT 출력을 읽을지를 정의하여 이런 경쟁을 줄입니다.

clocking cb 타이밍 규칙 · SystemVerilog · 실제 interface 코드 발췌
clocking cb @(posedge tb_clk);
    default input #1step output #0;
    output rx_data_i, rx_valid_i, tx_ready_i;
    input  rx_ready_o, tx_data_o, tx_valid_o;
endclocking
표현의미이번 실습
@(bus.cb)다음 clocking 이벤트까지 대기10ns 간격으로 진행
input #1step상승 에지 직전 안정된 값을 샘플링이전 구간의 DUT 출력 검사
output #0현재 상승 에지 뒤에 TB 입력 구동다음 구간의 데이터·Valid·Ready 제시
bus.cb.rx_data_i <= ...clocking 출력으로 입력 구동다음 샘플 전에 A 또는 Z 제시
bus.cb.tx_data_oclocking 입력으로 샘플된 값 읽기이전 구간에 설정한 기대값과 비교

따라서 5ns에 A를 구동했다면 15ns clocking 이벤트에서 A를 검사하는 흐름으로 작성해야 합니다. 같은 이벤트에서 구동한 값을 곧바로 샘플에 반영했다고 가정하지 않습니다. 또한 인터페이스의 tb_clk은 관찰 시점을 맞추는 신호이며 uart_echo_controller에는 연결되지 않습니다.

042교시 ① · 전체 연결과 입력 시나리오 (60~70분)

테스트벤치는 tb_uart_interface에서 세 가지 인스턴스를 연결합니다. uart_stream_if stream이 여섯 신호를 보관하고, uart_echo_bind adapter가 기존 RTL과 연결하며, uart_stream_agent agent가 구동·검사합니다.

시나리오는 A 수락 → Z 전송 정지 → 동일한 Z 수락 → IDLE 순서입니다. Z를 제시했을 때 뒤쪽 tx_ready_i=0이면 앞쪽은 rx_valid_i=1과 데이터 Z를 유지해야 합니다. 준비 신호가 다시 1이 된 다음에야 해당 데이터를 전송한 것으로 처리합니다. 데이터가 존재하는 것과 전송이 수락된 것은 다릅니다.

052교시 ② · interface 전체 코드 (70~85분)

첫 번째 신규 파일은 신호 선언과 접근·타이밍 규칙만 보관합니다. 이번 장 이후 다른 DUT나 테스트벤치를 연결할 때도 인터페이스만 재사용할 수 있습니다.

tb/ch07/uart_stream_if.sv · SystemVerilog · 신규 교육용 interface · 컴파일 미실행
`timescale 1ns/1ps
// 제07장: UART Byte Stream(바이트 데이터 흐름)의 6개 신호를 한 묶음으로 관리한다.
// tb_clk은 테스트벤치의 샘플링 기준이며, 원본 DUT의 입력 포트가 아니다.
interface uart_stream_if(input logic tb_clk);
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    logic       tx_ready_i;
    logic       rx_ready_o;
    logic [7:0] tx_data_o;
    logic       tx_valid_o;

    // (추가) TB 관점에서 출력은 구동, 입력은 관찰 대상이다.
    // input #1step: 현재 상승 에지 직전의 안정된 값을 샘플링한다.
    // output #0  : 상승 에지의 Re-NBA 영역에서 다음 구간의 입력을 구동한다.
    clocking cb @(posedge tb_clk);
        default input #1step output #0;
        output rx_data_i, rx_valid_i, tx_ready_i;
        input  rx_ready_o, tx_data_o, tx_valid_o;
    endclocking

    // (추가) TB에서는 cb로만 구동·샘플링하도록 접근 방식을 지정한다.
    modport TB (clocking cb);

    // (추가) 원본의 6개 평면 포트를 연결할 Adapter용 방향 선언.
    // DUT 원본 자체는 interface 포트를 갖지 않는다.
    modport DUT (
        input  rx_data_i, rx_valid_i, tx_ready_i,
        output rx_ready_o, tx_data_o, tx_valid_o
    );
endinterface

코드 풀이 — 세 개의 문법이 연결되는 방법

interface uart_stream_if(input logic tb_clk)에서 외부 클록을 받아 내부 clocking cb의 이벤트 기준으로 씁니다. modport TB (clocking cb)로 검증 모듈에 이 블록만 노출하고, modport DUT로 연결 전용 래퍼의 포트 방향을 제한합니다. 신호 선언·역할·타이밍 정책이 한 파일에 정리됩니다.

062교시 ③ · 테스트벤치와 원본 연결 코드 (85~105분)

두 번째 파일의 uart_echo_bind는 원본 포트 연결만 담당합니다. uart_stream_agent는 check_case()에서 기대 데이터·유효·준비 신호를 4상태 비교 연산자 !==로 검사하고, 잘못되면 $fatal로 시뮬레이션을 중단합니다.

tb/ch07/tb_uart_interface.sv · SystemVerilog · 신규 교육용 TB · 실제 시뮬레이션 미실행
`timescale 1ns/1ps
// 제07장: interface → modport → clocking block → 기존 UART Echo 검증.
// uart_echo_controller.v 원본은 읽기 전용으로 컴파일한다.

// (추가) 기능 없이 기존 DUT 포트를 interface 신호로만 연결하는 Wrapper.
module uart_echo_bind(uart_stream_if.DUT bus);
    uart_echo_controller dut (
        .rx_data_i (bus.rx_data_i),
        .rx_valid_i(bus.rx_valid_i),
        .rx_ready_o(bus.rx_ready_o),
        .tx_data_o (bus.tx_data_o),
        .tx_valid_o(bus.tx_valid_o),
        .tx_ready_i(bus.tx_ready_i)
    );
endmodule

// (추가) TB modport를 통해서 clocking block 신호만 접근한다.
module uart_stream_agent(uart_stream_if.TB bus);
    integer checked;

    // 출력과 기대값을 4상태(0, 1, X, Z)까지 포함하여 비교한다.
    // 제04장에서 배운 자동 PASS/FAIL 검증을 이번 인터페이스에 재사용한다.
    task automatic check_case(
        input string      case_name,
        input logic [7:0] exp_data,
        input logic       exp_valid,
        input logic       exp_ready
    );
        begin
            if ((bus.cb.tx_data_o !== exp_data) ||
                (bus.cb.tx_valid_o !== exp_valid) ||
                (bus.cb.rx_ready_o !== exp_ready)) begin
                $fatal(1,
                    "FAIL %s: data=%02h valid=%b ready=%b (expected %02h/%b/%b)",
                    case_name,
                    bus.cb.tx_data_o, bus.cb.tx_valid_o, bus.cb.rx_ready_o,
                    exp_data, exp_valid, exp_ready);
            end
            checked = checked + 1;
            $display("PASS %s: data=%02h valid=%b ready=%b",
                case_name,
                bus.cb.tx_data_o, bus.cb.tx_valid_o, bus.cb.rx_ready_o);
        end
    endtask

    initial begin
        checked = 0;
        $display("=== CH07 INTERFACE / MODPORT / CLOCKING START ===");

        // t=5ns: 첫 clocking event 후 A를 구동한다.
        // output #0 때문에 이 에지에서 샘플된 값은 아직 A가 아니다.
        @(bus.cb);
        bus.cb.rx_data_i  <= 8'h41;
        bus.cb.rx_valid_i <= 1'b1;
        bus.cb.tx_ready_i <= 1'b1;

        // t=15ns: 앞선 주기 A/valid/ready가 샘플된 것을 확인한다.
        @(bus.cb);
        check_case("A_ACCEPT", 8'h41, 1'b1, 1'b1);

        // t=15ns 이후: Z를 제시하지만 수신 준비를 내린다.
        bus.cb.rx_data_i  <= 8'h5A;
        bus.cb.rx_valid_i <= 1'b1;
        bus.cb.tx_ready_i <= 1'b0;

        // t=25ns: 정지(backpressure) 중에는 ready=0이다.
        @(bus.cb);
        check_case("Z_STALL", 8'h5A, 1'b1, 1'b0);

        // (중요) 수락될 때까지 Z와 valid=1을 유지한다.
        bus.cb.tx_ready_i <= 1'b1;

        // t=35ns: 동일한 Z 데이터가 정상 수락된 것을 확인한다.
        @(bus.cb);
        check_case("Z_ACCEPT", 8'h5A, 1'b1, 1'b1);
        bus.cb.rx_valid_i <= 1'b0;

        // t=45ns: valid가 없으므로 데이터 값은 있어도 전송하지 않는다.
        @(bus.cb);
        check_case("IDLE", 8'h5A, 1'b0, 1'b1);

        $display("CH07 PASS: %0d cases checked", checked);
        $finish;
    end
endmodule

// (추가) DUT에는 클록을 연결하지 않는다.
// tb_clk은 오직 테스트벤치의 구동·관찰 경계를 정의한다.
module tb_uart_interface;
    logic tb_clk = 1'b0;
    always #5 tb_clk = ~tb_clk;

    uart_stream_if   stream(tb_clk);
    uart_echo_bind   adapter(stream);
    uart_stream_agent agent(stream);

    initial begin
        $dumpfile("ch07_uart_interface.vcd");
        $dumpvars(0, tb_uart_interface);
    end

    // 정지 상태나 입력 오류로 무한 대기할 때 검사한다.
    initial begin
        #200;
        $fatal(1, "CH07 TIMEOUT: clocking block sequence did not finish");
    end
endmodule

코드 풀이 — 앞 장과 달라진 부분

제06장의 평면 포트 선언과 달리 현재 코드는 uart_stream_if stream(tb_clk)를 공통 신호 통로로 사용합니다. uart_echo_bind adapter(stream)와 uart_stream_agent agent(stream)가 동일한 인스턴스를 연결하므로 신호 이름이 갈라지지 않습니다.

check_case("Z_STALL", 8'h5A, 1'b1, 1'b0)의 마지막 0은 수락을 막는 준비 신호입니다. Z_ACCEPT에서 다시 1을 확인하기 전까지 데이터와 Valid를 유지합니다. IDLE은 valid=0이므로 데이터 선에 Z가 남아 있어도 전송은 성립하지 않습니다.

072교시 ④ · Ubuntu 실행 절차 (105~112분)

이번 장은 clocking block과 modport를 실제로 사용하므로 앞 장의 Icarus Verilog(아이카루스 베릴로그) 대신 이를 지원하는 Verilator(베릴레이터, Verilog/SystemVerilog 시뮬레이터) 기반 실행 절차를 사용합니다. 시뮬레이터의 버전별 구현 차이가 있으므로 컴파일 지원 여부를 먼저 확인해야 합니다.

Ubuntu 터미널 · Bash · 실행 명령 · 현재 제작 환경 미실행
# 1. 컴파일·실행 도구의 설치 여부를 확인한다.
verilator --version

# 2. 이 학습안내서 폴더로 이동한다.
cd /path/to/system_verilog_uvm_tb

# 3. 기존 DUT와 두 SystemVerilog 파일을 함께 빌드하고 실행한다.
bash scripts/run_ch07.sh

# 4. 실제 실행이 성공했다면 로그에서 검사 결과를 확인한다.
grep -E '^(PASS|FAIL|CH07)' .build/ch07/output.log

# 5. GTKWave가 설치된 경우 샘플·구동 시점을 파형으로 확인한다.
gtkwave .build/ch07/ch07_uart_interface.vcd
scripts/run_ch07.sh · Bash · 신규 실행 스크립트 · 미실행
#!/usr/bin/env bash
# 제07장: interface/modport/clocking block이 포함된 SystemVerilog 시뮬레이션.
# iverilog는 clocking block 지원이 제한적이므로 이 장은 Verilator 사용.
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
COURSE_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"

DUT_PATH="${DUT_PATH:-$COURSE_ROOT/reference_rtl/uart_echo_controller.v}"
IF_PATH="$COURSE_ROOT/tb/ch07/uart_stream_if.sv"
TB_PATH="$COURSE_ROOT/tb/ch07/tb_uart_interface.sv"
OUT_DIR="$COURSE_ROOT/.build/ch07"

# 도구 버전과 DUT 경로를 먼저 확인해 모호한 실패를 방지한다.
if ! command -v verilator >/dev/null 2>&1; then
  echo "ERROR: Verilator가 설치되지 않았습니다."
  echo "Ubuntu: sudo apt update && sudo apt install verilator g++ make"
  exit 2
fi
if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 기존 UART Echo RTL 파일 없음: $DUT_PATH"
  echo "DUT_PATH=/실제/경로/uart_echo_controller.v bash scripts/run_ch07.sh"
  exit 2
fi
mkdir -p "$OUT_DIR"
verilator --version | tee "$OUT_DIR/tool_version.txt"

# --timing: 이벤트·시간 제어를 활성화한다.
# --trace: VCD 파형 출력 기능을 활성화한다.
# 컴파일 오류가 나면 clocking 지원이 되는 Verilator 버전인지 확인한다.
verilator --binary --timing --trace --top-module tb_uart_interface \
  --Mdir "$OUT_DIR/obj_dir" \
  "$IF_PATH" "$DUT_PATH" "$TB_PATH" \
  2>&1 | tee "$OUT_DIR/build.log"

# pipefail을 사용하므로 DUT 검증 실패나 실행 실패를 성공으로 숨기지 않는다.
(cd "$OUT_DIR" && ./obj_dir/Vtb_uart_interface | tee output.log)
echo "실제 실행 로그: $OUT_DIR/output.log"

Verilator가 없으면 sudo apt update로 패키지 목록을 갱신하고 sudo apt install verilator g++ make로 설치합니다. 이 장에서 --timing은 시간·이벤트 제어를, --trace는 VCD 기록을 활성화합니다. 버전이 오래되어 clocking 문법을 처리하지 못한다면, 해당 기능이 지원되는 버전이나 IEEE 1800 호환 상용 시뮬레이터를 사용해야 합니다.

09마무리 · 기억할 세 가지와 다음 장 (118~120분)

interface는 무엇을 연결할지, modport는 각 역할에서 어느 방향으로 사용할지, clocking block은 언제 구동·관찰할지를 정의합니다. 세 개념은 서로 대체하지 않고 각자의 문제를 해결합니다.

완료 기준은 ① 기존 UART Echo 포트 여섯 개를 원본 그대로 연결하고, ② 네 시나리오에서 입력 유지와 Ready/Valid 수락 조건을 설명하며, ③ 실제 시뮬레이터로 네 개 검사가 통과했는지 로그를 확인하는 것입니다. 현재 제작 환경에서는 RTL_SIM=NOT_RUN입니다.

다음 제08장: 이미 만든 인터페이스를 유지하고 class(클래스, 객체 설계 단위), extends(상속), rand(무작위 입력 변수), constraint(입력 제약)로 반복 생성되는 트랜잭션 객체를 다룹니다.

기술 참고: IEEE 1800-2017 SystemVerilog 명세의 인터페이스·모드포트·클로킹 블록 개념을 기준으로 정리했습니다.

10참고 · 기존 uart_echo_controller 원본

아래 코드는 실제 검증 대상인 기존 RTL 원본입니다. uart_echo_bind가 이 모듈의 실제 6개 포트에 정확히 연결되어 있습니다. 원본 파일과 합성 회로의 동작은 변경하지 않습니다.

part03/common/rtl/uart_echo_controller.v · Verilog · 기존 원본 · 읽기 전용
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule

원본에 클록이 없다는 점과 rx_ready_o, tx_valid_o, tx_data_o가 각각 대응하는 입력을 그대로 전달한다는 점이 이번 장 예상 출력의 근거입니다.
