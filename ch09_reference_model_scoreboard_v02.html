제09장 · 참조 모델·스코어보드

기존 PWM RTL에 독립 참조 모델과 스코어보드를 연결하고 매 클록 6개 출력을 자동 검증합니다.

제3부 · 제09장1교시 60분 + 2교시 60분기존 RTL 변경 없음

00학습 개요 · 출력 관찰을 정답 판정으로

제04장에서는 PWM 출력의 HIGH 개수를 비교했습니다. 제09장에서는 검증 수준을 높여 원본 RTL과 독립된 참조 모델을 같은 입력으로 움직이고, 매 클록 출력이 같은지 자동 검사합니다. 이 과정을 Reference Model(레퍼런스 모델, 정답 동작을 계산하는 모델)과 Scoreboard(스코어보드, 정답과 실제 출력 비교기)로 구성합니다.

구간시간실습 범위
1교시0~60분독립 모델의 역할, 출력 계약, 모델 상태, 경계·리셋 시간 분석
2교시60~120분모델·스코어보드 전체 코드, 6가지 시나리오, 실행·검증·오류 분석

실제 검증 대상은 기존 reference_rtl/pwm_core.v이며, 새 모델·테스트벤치만 tb/ch09/에 만듭니다. Basys3 보드 없이 시뮬레이션만 진행합니다.

011교시 ① · DUT·참조 모델·스코어보드 구분 (0~20분)

DUT(디유티, 검증 대상 회로)는 검증받을 실제 RTL입니다. 참조 모델은 기능 명세대로 움직여야 할 결과를 계산합니다. 스코어보드는 두 출력의 차이를 판정합니다. 세 역할을 섞어 놓으면 오류가 발생했을 때 원인이 불분명해지므로 명확히 구별합니다.

역할실제 코드책임
DUTpwm_core기존 RTL 기능 실행
참조 모델pwm_reference_model입력만 읽어 예상 파형·상태 계산
스코어보드tb_pwm_scoreboard의 always @(posedge clk)매 클록 DUT 공개 출력 6개 대조

중요한 원칙: 참조 모델은 DUT 내부 counter, boundary, shadow_duty에 접근하지 않습니다. 내부 값을 읽어 정답으로 사용하면 DUT가 잘못 계산한 상태를 그대로 복사할 위험이 있습니다. 이번 모델은 독립된 phase, queued_*, ref_* 상태를 유지합니다.

다만 RTL과 모델이 같은 명세를 잘못 해석하면 공통 오류를 놓칠 수 있습니다. 실무에서는 별도의 수학적 정답, 경계값·어설션까지 함께 적용하며 제10~12장에서 보완합니다.

021교시 ② · 비교할 실제 출력 6개 (20~40분)

PWM 출력만 일치해도 설정 적용 시점이 잘못되었을 수 있습니다. 따라서 이번 장에서는 원본 모듈이 밖으로 제공하는 상태 출력을 함께 검사합니다. 내부 신호에 의존하지 않으면서도 설정 적용 오류를 조기에 발견할 수 있습니다.

원본 출력예상 출력검사 내용
pwm_outref_pwmHIGH/LOW 파형과 극성
pendingref_pending설정 반영 대기 여부
active_periodref_period현재 동작 주기
active_dutyref_duty현재 듀티
active_enableref_enable출력 활성화
active_polarityref_polarity출력 반전 상태

비교에는 !==(4상태 비일치 비교)를 사용합니다. 일반적인 !=는 알 수 없는 X가 포함되면 결과 자체가 X일 수 있지만, !==는 X/Z까지 포함한 차이를 0 또는 1로 판단합니다.

031교시 ③ · 시간 계약과 모델의 적용 경계 (40~60분)

cfg_apply가 1이 되면 설정이 queued_*에 저장되고 ref_pending이 1로 올라갑니다. 모델의 phase가 한 주기의 마지막 박자에 도달하면 다음 주기로 돌아오면서 대기 설정을 ref_*에 반영합니다.

함정 사례: 세 번째 요청은 250ns에 발생해 다음 상승 에지인 255ns의 주기 경계와 겹칩니다. 이때 이번 요청을 즉시 적용하는 것은 잘못된 동작입니다. 이미 대기 중이던 요청에만 현재 경계의 적용 기회가 있고, 새 요청은 다음 경계인 335ns까지 기다려야 합니다.

모델에서는 period_end에 따른 적용과 cfg_apply에 따른 새 요청 저장을 같은 순차 블록에서 다루되, cfg_apply 조건을 뒤에 두어 최종 ref_pending 값을 결정합니다. 이는 기존 RTL의 명세상 우선순위에 맞춘 것입니다.

리셋은 별도로 구분합니다. 내부 상태는 상승 에지에서 초기화되지만, pwm_out은 resetn을 조합식으로 사용하므로 580ns에 리셋을 내린 직후 LOW가 되어야 합니다.

042교시 ① · 참조 모델 전체 코드 (60~78분)

첫 번째 신규 파일은 기존 PWM RTL을 수정하거나 복제하지 않고, 관찰 가능한 기능 계약에 따라 예상 결과를 계산합니다. 모델의 입력은 DUT와 동일하게 받지만 출력 이름은 ref_ 접두사를 사용하여 실제 출력과 혼동하지 않습니다.

tb/ch09/pwm_reference_model.sv · SystemVerilog · 신규 참조 모델 · 실제 컴파일 미실행
`timescale 1ns/1ps
// (추가) 제09장: 공개 PWM 계약으로 예상값을 계산하는 독립 참조 모델.
// DUT 내부 신호 counter, boundary, shadow_*는 참조하지 않는다.
module pwm_reference_model #(
    parameter [31:0] INITIAL_PERIOD = 32'd8
)(
    input wire clk, resetn, cfg_apply,
    input wire [31:0] cfg_period, cfg_duty,
    input wire cfg_enable, cfg_polarity,
    output wire ref_pwm,
    output reg ref_pending,
    output reg [31:0] ref_period, ref_duty,
    output reg ref_enable, ref_polarity
);
    reg [31:0] phase, queued_period, queued_duty;
    reg queued_enable, queued_polarity;

    // 주기/듀티 기준으로 DUT와 별개 예상 파형을 구한다.
    // 이번 장의 입력 주기는 항상 8이므로 0 주기는 다루지 않는다.
    wire period_end = (phase + 32'd1 >= ref_period);
    wire high_window = (phase < ref_duty);
    assign ref_pwm = resetn && ref_enable &&
                     (ref_polarity ? !high_window : high_window);

    always @(posedge clk) begin
        if (!resetn) begin
            phase           <= 32'd0;
            ref_period      <= INITIAL_PERIOD;
            ref_duty        <= 32'd0;
            ref_enable      <= 1'b0;
            ref_polarity    <= 1'b0;
            queued_period   <= INITIAL_PERIOD;
            queued_duty     <= 32'd0;
            queued_enable   <= 1'b0;
            queued_polarity <= 1'b0;
            ref_pending     <= 1'b0;
        end else begin
            // 현재 주기를 완료한 뒤 대기 중인 설정을 반영한다.
            if (period_end) begin
                phase <= 32'd0;
                if (ref_pending) begin
                    ref_period   <= queued_period;
                    ref_duty     <= queued_duty;
                    ref_enable   <= queued_enable;
                    ref_polarity <= queued_polarity;
                    ref_pending  <= 1'b0;
                end
            end else begin
                phase <= phase + 32'd1;
            end

            // 경계와 cfg_apply가 겹치면 새 값은 다음 경계에서 적용.
            if (cfg_apply) begin
                queued_period   <= cfg_period;
                queued_duty     <= cfg_duty;
                queued_enable   <= cfg_enable;
                queued_polarity <= cfg_polarity;
                ref_pending     <= 1'b1;
            end
        end
    end
endmodule

코드 풀이 — 수식과 상태 흐름

phase + 1 >= ref_period는 현재 주기의 마지막 박자에 도달하는지 계산합니다. 주기 8에서는 phase가 7일 때 다음 상승 에지에 0으로 돌아갑니다. phase < ref_duty는 출력이 HIGH인 박자인지 판단하며, 듀티 2이면 8박자 중 2박자가 HIGH입니다.

queued_period·queued_duty는 아직 실제 적용하지 않은 설정이고, ref_period·ref_duty는 활성 설정입니다. 비차단 대입 <=은 상승 에지의 이전 상태를 기준으로 계산하므로 같은 에지의 요청과 적용 순서를 올바르게 모델링합니다.

052교시 ② · 스코어보드 전체 테스트벤치 (78~98분)

두 번째 파일은 DUT와 모델을 동일한 클록·설정 신호에 연결합니다. 비교 담당 always는 매 상승 에지 이후 #1을 기다린 다음 6개 출력을 대조하고, 차이가 하나라도 있으면 $fatal로 즉시 종료합니다. 입력 발생 담당 태스크는 하강 에지에서 값을 바꿔 경쟁 상태를 줄입니다.

tb/ch09/tb_pwm_scoreboard.sv · SystemVerilog · 신규 스코어보드 TB · 실제 컴파일 미실행
`timescale 1ns/1ps
// (추가) 제09장: DUT와 참조 모델의 공개 출력 6개를 자동 비교한다.
module tb_pwm_scoreboard;
    reg clk = 1'b0, resetn = 1'b0, cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8, cfg_duty = 32'd0;
    reg cfg_enable = 1'b1, cfg_polarity = 1'b0;

    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    wire ref_pwm, ref_pending, ref_enable, ref_polarity;
    wire [31:0] ref_period, ref_duty;
    integer score_cycles = 0, scenarios = 0;

    // (추가) 원본 DUT 13포트를 변경 없이 연결한다.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .pwm_out(pwm_out), .pending(pending),
        .active_period(active_period), .active_duty(active_duty),
        .active_enable(active_enable), .active_polarity(active_polarity)
    );

    // (추가) 같은 입력을 독립된 Golden(정답) 모델에도 공급한다.
    pwm_reference_model #(.INITIAL_PERIOD(32'd8)) golden (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .ref_pwm(ref_pwm), .ref_pending(ref_pending),
        .ref_period(ref_period), .ref_duty(ref_duty),
        .ref_enable(ref_enable), .ref_polarity(ref_polarity)
    );

    // 입력 자극은 하강 에지에서, 비교는 상승 에지 이후에 수행한다.
    always #5 clk = ~clk;

    // (추가) scoreboard: 4상태 비교 !==로 X/Z까지 놓치지 않는다.
    // #1은 비차단 대입이 완료된 뒤 읽는 테스트벤치 관찰 지연이다.
    always @(posedge clk) begin
        #1;
        score_cycles = score_cycles + 1;
        if ((pwm_out         !== ref_pwm)      ||
            (pending         !== ref_pending)  ||
            (active_period   !== ref_period)   ||
            (active_duty     !== ref_duty)     ||
            (active_enable   !== ref_enable)   ||
            (active_polarity !== ref_polarity)) begin
            $display("EXPECTED t=%0d pwm=%b pend=%b period=%0d duty=%0d en=%b pol=%b",
                $time, ref_pwm, ref_pending, ref_period,
                ref_duty, ref_enable, ref_polarity);
            $fatal(1,
                "FAIL t=%0d pwm=%b pend=%b period=%0d duty=%0d en=%b pol=%b",
                $time, pwm_out, pending, active_period,
                active_duty, active_enable, active_polarity);
        end
    end

    // (추가) 설정을 한 클록만 HIGH로 전달하는 재사용 태스크.
    task automatic request_config(
        input integer case_id,
        input [31:0] duty_ticks,
        input reg enabled, inverted
    );
        begin
            @(negedge clk);
            cfg_period   = 32'd8;
            cfg_duty     = duty_ticks;
            cfg_enable   = enabled;
            cfg_polarity = inverted;
            cfg_apply    = 1'b1;
            scenarios = scenarios + 1;
            $display("REQUEST case=%0d t=%0d duty=%0d en=%b pol=%b",
                case_id, $time, duty_ticks, enabled, inverted);
            @(negedge clk);
            cfg_apply = 1'b0;
        end
    endtask

    initial begin
        $dumpfile("ch09_pwm_scoreboard.vcd");
        $dumpvars(0, tb_pwm_scoreboard);
    end
    initial begin
        #1200;
        $fatal(1, "CH09 TIMEOUT: 검증이 정상 종료되지 않음");
    end

    initial begin
        $display("=== CH09 PWM MODEL / SCOREBOARD START ===");

        repeat (2) @(negedge clk); // t=20ns 초기 리셋 해제
        resetn = 1'b1;

        request_config(1, 32'd2, 1'b1, 1'b0); // t=30ns: 25%
        repeat (9) @(negedge clk);

        request_config(2, 32'd6, 1'b1, 1'b0); // t=140ns: 75%
        repeat (9) @(negedge clk);

        // t=250ns 요청이 t=255ns 주기 경계와 겹친다.
        // 새 극성은 다음 주기 경계(t=335ns)에 반영되어야 한다.
        request_config(3, 32'd6, 1'b1, 1'b1);
        repeat (9) @(negedge clk);

        request_config(4, 32'd6, 1'b0, 1'b1); // 출력 차단
        repeat (9) @(negedge clk);

        request_config(5, 32'd8, 1'b1, 1'b0); // 100% HIGH
        repeat (9) @(negedge clk);

        // t=580ns: PWM HIGH 상태에서 LOW 리셋 인가.
        @(negedge clk);
        resetn = 1'b0;
        #1;
        if ((pwm_out !== 1'b0) || (ref_pwm !== 1'b0))
            $fatal(1, "FAIL RESET_GATE: 출력 즉시 LOW 실패");
        $display("RESET_GATE PASS t=%0d", $time);

        repeat (2) @(negedge clk); // t=600ns 리셋 해제
        resetn = 1'b1;
        request_config(6, 32'd0, 1'b1, 1'b0); // 0% 듀티
        repeat (10) @(negedge clk);

        $display("PASS CH09 score_cycles=%0d scenarios=%0d",
            score_cycles, scenarios);
        $finish;
    end
endmodule

코드 풀이 — 한 사이클에서 수행하는 검사

score_cycles는 출력 전체를 검사한 상승 에지 수를 기록합니다. 특정 출력을 검사한 횟수가 아니라 6개 신호 묶음 비교를 수행한 횟수입니다. 실제 데이터가 정답과 다르면 EXPECTED와 FAIL 로그로 해당 시각의 출력 묶음을 함께 표시합니다.

request_config()는 한 클록 동안 cfg_apply를 HIGH로 올립니다. 25% → 75% → 극성 반전 → 비활성화 → 100% → 리셋 후 0%의 여섯 시나리오를 순서대로 실행합니다. 고정 입력으로 시작하므로 오류 발생 시 동일한 조건을 재현하기 쉽습니다.

062교시 ③ · Ubuntu 컴파일·시뮬레이션 (98~108분)

Icarus Verilog(아이카루스 베릴로그, Verilog/SystemVerilog 시뮬레이터)의 iverilog로 기존 DUT·새 모델·테스트벤치를 컴파일하고, vvp로 실행합니다. 이 과정의 독립 저장소 루트에서 명령을 수행합니다.

# 1. 독립 저장소 루트로 이동합니다.
cd /path/to/system_verilog_uvm_tb

# 2. Icarus Verilog 도구가 설치되었는지 확인합니다.

# 3. PWM DUT, Reference Model, Scoreboard를 함께 실행합니다.

scripts/run_ch09.sh · Bash · 교육용 실행 스크립트 · 미실행
#!/usr/bin/env bash
# 제09장: PWM 원본, 독립 참조 모델, 스코어보드를 컴파일·실행한다.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
MODEL="$ROOT/tb/ch09/pwm_reference_model.sv"
TB="$ROOT/tb/ch09/tb_pwm_scoreboard.sv"
OUT="$ROOT/.build/ch09"

for tool in iverilog vvp; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "ERROR: $tool 미설치. sudo apt update && sudo apt install iverilog"
    exit 2
  fi
done
if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 원본 PWM 파일 없음: $DUT_PATH"
  exit 2
fi

mkdir -p "$OUT"

# -g2012: SystemVerilog 문법 활성화. 실패한 빌드 로그도 확인한다.
iverilog -g2012 -s tb_pwm_scoreboard -o "$OUT/simulation.vvp" \
  "$DUT_PATH" "$MODEL" "$TB" 2>&1 | tee "$OUT/build.log"

# pipefail: 시뮬레이터에서 $fatal이 발생하면 실행 실패로 전달된다.
(cd "$OUT" && vvp simulation.vvp | tee output.log)
echo "로그: $OUT/output.log"
echo "파형: $OUT/ch09_pwm_scoreboard.vcd"

iverilog 명령이 없으면 sudo apt update(패키지 목록 갱신), sudo apt install iverilog(시뮬레이터 설치) 순으로 실행합니다. output.log는 텍스트 결과이고, VCD(브이시디, 신호 변화 기록) 파일에서는 pwm_out과 ref_pwm을 함께 관찰할 수 있습니다.

09참고 · 기존 PWM 원본 RTL

아래는 실제 검증 대상인 reference_rtl/pwm_core.v 전체 코드입니다. 별도 저장소로 이관할 때 원본 Blob SHA를 확인했으며 이번 장에서도 소스는 수정하지 않았습니다.

reference_rtl/pwm_core.v · Verilog · 기존 RTL 원본 · Blob SHA e813f3fb107bd327054d11e0b397817b8e7bd813
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

정확한 비교를 위해 DUT의 공개 출력과 참조 모델의 출력만 관찰합니다. 내부 counter·shadow_duty를 읽지 않는 것이 본 예제의 핵심 설계 원칙입니다.
