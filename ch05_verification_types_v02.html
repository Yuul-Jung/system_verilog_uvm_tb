제05장 · 검증 자료형과 타입

기존 UART Echo RTL을 통해 logic·bit·enum·struct·typedef를 배우는 2시간 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00학습 개요 · SystemVerilog로 검증 데이터를 표현한다

제04장에서는 출력과 기대값을 자동 비교했습니다. 이제 검증에 사용할 데이터를 명확한 자료형(type, 타입)으로 정의합니다. 여러 신호를 하나의 값으로 묶고, 검증 단계에 의미 있는 이름을 붙이면 복잡한 검증 코드에서도 실수를 줄일 수 있습니다.

시간진행완료 기준
1교시 · 0~60분logic, bit, enum, struct, typedef 기초4상태/2상태 차이와 자료형 정의
2교시 · 60~120분기존 UART Echo의 전체 TB 작성·실행·결과 해석데이터·유효·준비 신호와 X 보존 검사

기존 part03/common/rtl/uart_echo_controller.v는 입력을 출력에 연결하는 조합 회로입니다. UART 직렬 비트 송수신기나 FIFO가 아니며 클록·리셋 포트가 없습니다. 따라서 이번 장은 바이트 스트림의 논리적 입력/출력만 검증합니다.

011교시 ① · logic과 bit의 4상태·2상태 (0~20분)

logic(로직, 0·1·X·Z를 저장하는 4상태 변수형)은 아직 초기화되지 않은 값 X(미정)와 Z(고임피던스)를 표현합니다. RTL 검증에서는 미정값을 감추지 않는 것이 중요합니다. bit(비트, 0과 1만 저장하는 2상태 변수형)는 메모리를 절약하고 순수한 2상태 계산에 적합하지만 X/Z를 담으면 0으로 변환합니다.

자료형의 차이 · 간단한 예 · SystemVerilog
logic [7:0] four_state_copy;
bit   [7:0] compact_copy;

four_state_copy = 8'hx5; // 상위 니블은 X, 하위 니블은 5
compact_copy = 8'hx5;    // 상위 X가 0으로 변환됨
$display("logic=%h bit=%h", four_state_copy, compact_copy);
// 예상 출력: logic=x5 bit=05

여기서 8'hx5는 8비트 16진수로, 상위 네 비트가 X이고 하위 네 비트가 0101입니다. 4상태 비교 연산자 ===와 !==는 X까지 포함하여 같은지 판단합니다. 검증 신호에 무심코 bit를 사용하면 미정값이 사라져 결함을 놓칠 수 있습니다.

021교시 ② · typedef와 enum으로 상태 이름 붙이기 (20~40분)

typedef(타입디프, 자료형에 이름을 붙이는 선언)는 복잡한 타입을 재사용할 때 쓰고, enum(이넘, 열거형)은 서로 다른 상태를 의미 있는 이름으로 구분합니다. 이번 예제의 CASE_IDLE은 DUT의 실제 FSM(유한상태머신) 상태가 아니라 테스트벤치에서 구분하는 입력 사례입니다. 조합 DUT에 없는 상태기를 도식에 만들어 넣지 않습니다.

열거형 선언 · SystemVerilog
typedef enum logic [1:0] {
    CASE_IDLE  = 2'd0, // 유효하지 않은 데이터
    CASE_SEND  = 2'd1, // valid=1, ready=1
    CASE_STALL = 2'd2, // valid=1, ready=0
    CASE_XDATA = 2'd3  // X 포함 데이터
} case_kind_t;

case_kind_t kind;
kind = CASE_SEND;

각 열거형 항목은 2비트로 표현되지만, 코드에서는 숫자 1보다 CASE_SEND가 훨씬 분명합니다. 열거형 변수에 숫자를 무분별하게 대입하기보다는 정의된 이름을 사용하면 입력 사례를 추적하기 쉽습니다.

031교시 ③ · packed struct로 관련 신호 묶기 (40~60분)

struct packed(스트럭트 팩트, 여러 필드를 연속된 비트로 묶는 구조체)는 바이트 데이터와 제어 신호를 하나의 값으로 전달합니다. 필드 순서는 선언 순서대로 상위 비트에서 하위 비트로 배치됩니다. 이번 예제는 데이터 8비트, 유효 신호 1비트, 준비 신호 1비트로 총 10비트입니다.

구조체 선언과 사용 · SystemVerilog
typedef struct packed {
    logic [7:0] data;  // 상위 8비트: 데이터
    logic       valid; // 다음 1비트: 유효
    logic       ready; // 마지막 1비트: 수락 준비
} uart_sample_t;

uart_sample_t sample;
sample = '{8'h41, 1'b1, 1'b1};
// sample.data는 8'h41, sample.valid와 ready는 1
// 10비트 패킹 표현: {8'h41, 1'b1, 1'b1}

이처럼 필드를 묶으면 run_case() 호출 시 여러 개의 입력을 빠뜨릴 위험이 줄어듭니다. 다만 이 구조체는 검증용 데이터 표현일 뿐, 원본 DUT의 실제 포트 구조를 변경하지 않습니다.

042교시 ① · 실제 UART Echo 포트·시간 계약 (60~75분)

검증 대상은 기존 uart_echo_controller입니다. 이 회로는 rx_data_i를 tx_data_o로, rx_valid_i를 tx_valid_o로, tx_ready_i를 rx_ready_o로 조합 연결합니다. 준비 신호가 LOW여도 데이터·유효 신호는 그대로 전달되지만, 실제 스트림 전송은 valid와 ready가 모두 HIGH일 때만 수락된 것으로 해석합니다.

입력 포트출력 포트원본 계약
rx_data_i[7:0]tx_data_o[7:0]8비트 데이터 그대로 전달
rx_valid_itx_valid_o유효 신호 그대로 전달
tx_ready_irx_ready_o준비 신호 그대로 전달

이 DUT에는 순차 레지스터가 없으므로 #1은 실제 하드웨어의 1ns 지연이 아니라 테스트벤치의 조합 출력 안정화·관찰용 시간 이동입니다. 시뮬레이션 시각 0ns에 첫 입력을 지정하고 1ns 후에 첫 결과를 확인합니다.

052교시 ② · 전체 테스트벤치 코드 (75~100분)

다음은 네 가지 입력 사례를 구조체로 전달하고, X 포함 데이터와 2상태 변환까지 자동 비교하는 완전한 테스트벤치입니다. 원본 DUT의 여섯 포트를 실제 이름 그대로 연결했습니다.

tb/ch05/tb_uart_types.sv · 전체 소스 · SystemVerilog
`timescale 1ns/1ps
// 제05장: SystemVerilog 자료형으로 UART Echo의 입력·출력을 모델링한다.
// 기존 uart_echo_controller는 수정하지 않는다.
// DUT는 조합 논리이므로 클록·리셋·지연된 UART 직렬 비트는 없다.
module tb_uart_types;
    // (추가) 4상태 logic: X/Z를 포함한 신호 검증에 사용한다.
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    logic       tx_ready_i;
    wire        rx_ready_o;
    wire [7:0]  tx_data_o;
    wire        tx_valid_o;

    // (추가) typedef + enum: 검증 단계 이름을 숫자 대신 타입으로 지정한다.
    typedef enum logic [1:0] {
        CASE_IDLE  = 2'd0,
        CASE_SEND  = 2'd1,
        CASE_STALL = 2'd2,
        CASE_XDATA = 2'd3
    } case_kind_t;

    // (추가) packed struct: 한 번의 스트림 입력을 하나의 값으로 묶는다.
    typedef struct packed {
        logic [7:0] data;
        logic       valid;
        logic       ready;
    } uart_sample_t;

    // (추가) bit는 2상태 값만 저장한다. X/Z를 저장하면 0으로 변환된다.
    bit [7:0] compact_copy;
    logic [7:0] four_state_copy;
    uart_sample_t sample;
    case_kind_t  kind;
    integer checks = 0;
    integer failures = 0;

    // 실제 원본 RTL의 여섯 포트를 이름 그대로 연결한다.
    uart_echo_controller dut (
        .rx_data_i(rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

    // (추가) 입력 적용 후 조합 회로가 안정될 시간을 1ns 제공한다.
    // 출력은 rx_ready_o=tx_ready_i, tx_valid_o=rx_valid_i,
    // tx_data_o=rx_data_i의 관계를 그대로 만족해야 한다.
    task automatic run_case(
        input case_kind_t next_kind,
        input uart_sample_t next_sample
    );
        begin
            kind = next_kind;
            sample = next_sample;
            rx_data_i  = sample.data;
            rx_valid_i = sample.valid;
            tx_ready_i = sample.ready;
            #1;

            checks = checks + 1;
            if ((rx_ready_o !== sample.ready) ||
                (tx_valid_o !== sample.valid) ||
                (tx_data_o !== sample.data)) begin
                failures = failures + 1;
                $error("MISMATCH kind=%0d data=%h valid=%b ready=%b",
                    kind, tx_data_o, tx_valid_o, rx_ready_o);
            end else begin
                $display("MATCH kind=%0d data=%h valid=%b ready=%b",
                    kind, tx_data_o, tx_valid_o, rx_ready_o);
            end
        end
    endtask

    initial begin
        $dumpfile("ch05_uart_types.vcd");
        $dumpvars(0, tb_uart_types);
    end

    initial begin
        $display("=== CH05 SYSTEMVERILOG TYPES START ===");

        // 입력 데이터가 있어도 valid=0이면 전송은 유효하지 않다.
        run_case(CASE_IDLE, '{8'h00, 1'b0, 1'b1});

        // valid=1, ready=1이면 전송 가능 상태이다.
        run_case(CASE_SEND, '{8'h41, 1'b1, 1'b1});

        // ready=0이면 출력 valid와 data는 유지되지만 수락은 안 된다.
        run_case(CASE_STALL, '{8'h42, 1'b1, 1'b0});

        // logic과 원본 조합 DUT는 X를 보존하는지 확인할 수 있다.
        run_case(CASE_XDATA, '{8'hx5, 1'b1, 1'b1});
        four_state_copy = rx_data_i;
        compact_copy = rx_data_i;

        checks = checks + 1;
        if (four_state_copy !== 8'hx5) begin
            failures = failures + 1;
            $error("4STATE_COPY_MISMATCH");
        end

        checks = checks + 1;
        if (compact_copy !== 8'h05) begin
            failures = failures + 1;
            $error("2STATE_CONVERSION_MISMATCH");
        end

        $display("TYPE logic=%h bit=%h", four_state_copy, compact_copy);
        if (failures == 0) begin
            $display("PASS checks=%0d failures=0", checks);
            $finish;
        end else begin
            $fatal(1, "FAIL checks=%0d failures=%0d", checks, failures);
        end
    end

    initial begin
        #100;
        $fatal(1, "TIMEOUT: testbench did not finish");
    end
endmodule

코드 풀이 — 자료형이 실제 검증에 쓰이는 위치

run_case(CASE_SEND, '{8'h41, 1'b1, 1'b1})은 입력 사례 이름과 10비트 구조체 값을 전달합니다. run_case() 안에서는 구조체 필드를 DUT 입력 포트에 대입하고 #1 후 실제 출력을 비교합니다. CASE_STALL에서는 준비 신호가 0이어도 유효 신호와 데이터가 그대로 유지되는지를 확인합니다.

CASE_XDATA는 8'hx5를 DUT에 전달하여 조합 데이터가 X를 보존하는지 검사합니다. 이어서 같은 입력을 logic과 bit에 복사하여 X 보존과 X→0 변환의 차이를 확인합니다. 각 검사는 !==로 비교하며 실패 시 $error를 기록하고, 마지막에 하나라도 실패했으면 $fatal로 종료합니다.

062교시 ③ · Ubuntu 실행 및 예상 출력 (100~110분)

아래 명령은 Ubuntu에서 Icarus Verilog(아이카루스 베릴로그, Verilog/SystemVerilog 시뮬레이터)를 사용해 원본 RTL과 TB를 함께 컴파일합니다. -g2012는 SystemVerilog 2012 문법 사용을 위한 옵션입니다.

Ubuntu 터미널 실행 · Bash

cd /path/to/system_verilog_uvm_tb

# 2. 시뮬레이터 설치 여부를 확인한다.

# 3. 원본 RTL과 테스트벤치를 컴파일·실행한다.

gtkwave .build/ch05/ch05_uart_types.vcd
scripts/run_ch05.sh · 전체 실행 스크립트 · Bash
#!/usr/bin/env bash
# 제05장: SystemVerilog 자료형 실습과 기존 UART Echo 조합 DUT 실행.
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/uart_echo_controller.v}"
TB_PATH="$ROOT/tb/ch05/tb_uart_types.sv"
OUT_DIR="$ROOT/.build/ch05"

for tool in iverilog vvp; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "ERROR: $tool 명령 없음. sudo apt install iverilog"
    exit 2
  fi
done
if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 원본 RTL 경로 없음: $DUT_PATH"
  echo "사용법: DUT_PATH=/경로/uart_echo_controller.v bash scripts/run_ch05.sh"
  exit 2
fi

mkdir -p "$OUT_DIR"
iverilog -g2012 -s tb_uart_types -o "$OUT_DIR/simulation.vvp" \
  "$DUT_PATH" "$TB_PATH"
(cd "$OUT_DIR" && vvp simulation.vvp | tee output.log)
echo "로그: $OUT_DIR/output.log"
echo "파형: $OUT_DIR/ch05_uart_types.vcd"

논리적으로 계산한 예상 출력 · TEXT

MATCH kind=1 data=41 valid=1 ready=1

총 여섯 개의 검사를 수행합니다. 네 번의 스트림 포트 비교와 두 번의 자료형 변환 비교입니다. 예상 출력의 PASS는 코드가 정상 실행되었을 때 기대하는 문자열이지 실제 시뮬레이션이 통과했다는 증거가 아닙니다.

072교시 ④ · 장애 분석과 확인 기준 (110~120분)

08참고 · 재사용 DUT 원본 전체 코드

아래는 이번 장에서 실제 참조하는 기존 RTL입니다. 원본 포트·조합 연결·시간 계약을 기준으로 테스트벤치를 작성했으며 소스 파일은 변경하지 않습니다.

part03/common/rtl/uart_echo_controller.v · 원본 · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule
