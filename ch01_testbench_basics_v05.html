제01장 · 테스트벤치의 첫 실행

원본 UART Echo RTL을 변경하지 않고 입력 자극과 출력 관찰을 수행하는 첫 실습

6부 · 24장입출력 관찰기존 RTL 재사용

00개요 · 무엇을 검증하는가

회로가 정상인지 확인하려면 먼저 입력에 대해 어떤 출력이 나와야 하는지 알아야 합니다. Testbench(테스트벤치, 시험 환경)는 실제 회로 대신 입력을 만들어 주고, 그 결과를 관찰하는 시뮬레이션 코드입니다.

검증 대상은 UART Echo Controller(유아트 에코 제어기)입니다. UART에서 수신한 바이트를 송신 경로로 전달하는 준비 단계 회로이며, UART 직렬 프레임을 직접 생성하거나 해석하는 회로는 아닙니다. 세 가지 조합 연결을 확인하는 것부터 시작합니다.

선행 설계 학습안내서: Basys3 소형 NPU 실습(amd_soc_npu) 제1장 UART 계산기, 03절 「서브젝트 1-1 · UART 에코」의 uart_echo_controller.v. 이 장은 에코 제어기만 시험하며 UART 송수신기 전체를 검증하지 않습니다.

01원본 RTL · UART Echo Controller

RTL(Register Transfer Level, 레지스터 전송 수준)로 작성된 원본의 전체 내용입니다. DUT(Device Under Test, 검증 대상 회로)에는 클록, 리셋, 내부 레지스터가 없습니다. 이 회로의 기능은 세 개의 연속 대입문으로 완결됩니다.

reference_rtl/uart_echo_controller.v · Verilog · 원본 동일
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule

위 코드 전체를 reference_rtl/uart_echo_controller.v로 저장합니다. 원본 저장소에 접속할 필요가 없습니다.

가운데 상자만 실제 RTL 모듈입니다. 좌우는 테스트벤치가 구동하거나 관찰하는 신호이며, 별도의 UART 송수신 모듈이 존재한다는 뜻이 아닙니다. 각 화살표는 DUT 경계에서 신호의 입력·출력 방향을 표시하고, 상자 내부에는 대응하는 원본 대입문을 제시합니다.

assign은 입력이 변하면 연결된 출력을 갱신하는 연속 대입입니다. 데이터와 유효 신호는 수신에서 송신 방향으로 전달되지만, 준비 신호는 반대 방향으로 전달됩니다. 송신 쪽이 준비되지 않았다면 앞단 역시 새로운 전달을 완료할 수 없음을 알게 됩니다.

원본 포트방향·폭동작
rx_data_i입력 · 8비트수신 바이트
rx_valid_i입력 · 1비트수신 데이터의 유효 여부
tx_ready_i입력 · 1비트송신 측 수락 가능 여부
tx_data_o출력 · 8비트rx_data_i 그대로 전달
tx_valid_o출력 · 1비트rx_valid_i 그대로 전달
rx_ready_o출력 · 1비트tx_ready_i 그대로 전달

Ready/Valid(레디/밸리드, 준비·유효 계약): 두 신호가 모두 1인 경우에만 전송 수락 조건이 성립합니다. 실제 동기식 시스템에서는 정해진 샘플링 클록에서 이 조건을 판단합니다. 이 DUT에는 클록이나 저장 기능이 없으므로 수락 횟수나 저장된 바이트를 스스로 관리하지 않습니다.

02검증 구조와 입력 시나리오

파일 두 개를 함께 컴파일합니다. uart_echo_controller.v는 회로의 기능을 정의하고, tb_uart_echo_basics.sv는 그 회로를 dut라는 이름으로 연결합니다. TB의 입력 변수는 DUT 포트로 들어가며, DUT 출력은 TB의 연결 신호를 통해 읽습니다.

입력 유지 구간rx_data_irx_valid_itx_ready_i확인 내용
0~10ns0000유효하지 않고 준비도 안 됨
10~20ns41 (A)11전송 수락 조건 성립
20~30ns5A (Z)10유효하지만 수락 불가
30~40ns0001준비되었지만 유효 데이터 없음

각 구간 끝에서 값을 출력합니다. 이 예제는 독립적인 조합 입력 조건을 관찰하는 기초 시험이며, 30ns 이후 대기 중인 Z를 취소합니다. 실제 Ready/Valid 송신기는 수락 전까지 유효 데이터와 valid를 유지해야 하므로 이 자극을 완전한 통신 규약 시험으로 해석해서는 안 됩니다.

03테스트벤치 전체 소스

tb/ch01/tb_uart_echo_basics.sv · SystemVerilog · 실행 미검증
`timescale 1ns/1ps
// 제01장: 기존 UART Echo Controller의 입출력을 관찰하는 첫 테스트벤치.
// 이 단계는 출력 표시가 목적이며, 자동 PASS/FAIL은 제04장에서 학습한다.
module tb_uart_echo_basics;
    // TB가 직접 구동하는 DUT 입력은 reg로 선언한다.
    reg  [7:0] rx_data_i;
    reg        rx_valid_i;
    reg        tx_ready_i;

    // DUT가 구동하는 출력은 wire로 관찰한다.
    wire       rx_ready_o;
    wire [7:0] tx_data_o;
    wire       tx_valid_o;

    // 기존 RTL의 실제 포트 이름과 1:1로 연결한다.
    uart_echo_controller dut (
        .rx_data_i (rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o (tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

`ifdef VCD
    // Icarus Verilog 사용 시 -DVCD 옵션으로 파형 저장 기능을 켠다.
    initial begin
        $dumpfile("ch01_uart_echo.vcd");
        $dumpvars(0, tb_uart_echo_basics);
    end
`endif

    initial begin
        $display("=== CH01 UART ECHO TESTBENCH START ===");

        // 10ns: 유효 데이터가 없고 송신 준비도 안 된 상태.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 20ns: 문자 'A'(ASCII 0x41)를 정상 전달한다.
        rx_data_i  = 8'h41;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 30ns: 뒤쪽 준비 신호를 내려 전송 대기를 관찰한다.
        rx_data_i  = 8'h5A;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 40ns: 유효 데이터 없이 준비 신호만 켠다.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        $display("=== CH01 END: OBSERVATION ONLY ===");
        $finish;
    end
endmodule

위 코드 전체를 tb/ch01/tb_uart_echo_basics.sv로 저장합니다. 두 코드 블록이 이 장의 실습에 필요한 전체 소스입니다.

05예상 출력과 타이밍 다이어그램

다음은 원본의 세 대입문과 TB의 자극 순서에서 도출한 예상 출력입니다. 실제 시뮬레이터 실행 기록이 아닙니다.

콘솔 · 예상 출력 · NOT_RUN
=== CH01 UART ECHO TESTBENCH START ===
t=10 ns rx=00 rv=0 tr=0 | tx=00 tv=0 rr=0
t=20 ns rx=41 rv=1 tr=1 | tx=41 tv=1 rr=1
t=30 ns rx=5a rv=1 tr=0 | tx=5a tv=1 rr=0
t=40 ns rx=00 rv=0 tr=1 | tx=00 tv=0 rr=1
=== CH01 END: OBSERVATION ONLY ===

20ns 출력의 tx=41, tv=1, rr=1은 A의 수락 조건을 보여 줍니다. 30ns에는 tx=5a, tv=1, rr=0이므로 데이터는 전달 경로에 있지만 수락되지 않습니다. 40ns에는 준비되어도 유효한 데이터가 없습니다.

파형의 시간 구간은 입력이 유지되는 기간입니다. 로그는 각 구간의 끝에서 다음 자극을 대입하기 직전에 기록하므로, 같은 시각의 GUI 커서가 다음 자극 값을 표시할 수 있습니다. #10은 TB가 관찰하기 위해 기다리는 시간이며 DUT 자체의 10ns 지연을 뜻하지 않습니다.

06핵심 코드 풀이

실제 코드의미와 역할
`timescale 1ns/1ps시간 단위 1ns, 정밀도 1ps. #10은 10ns를 뜻합니다.
reg [7:0] rx_data_i;initial 블록에서 자극을 대입하는 8비트 변수입니다. TB의 reg 선언 자체가 합성 레지스터를 의미하지는 않습니다.
wire [7:0] tx_data_o;DUT 출력이 구동하는 연결 신호입니다. TB는 이를 읽습니다.
uart_echo_controller dut (...)원본 모듈의 인스턴스를 생성하며 이름 기반으로 포트를 연결합니다.
initial begin ... end시뮬레이션 시작 시 한 번 수행되는 자극·관찰 절차입니다.
8'h418비트 16진수 41, ASCII 문자 A를 나타냅니다.
#10;시뮬레이션 시간을 10ns 진행시킵니다. 조합 출력이 갱신된 다음 관찰합니다.
$display(...)현재 입력과 출력을 기록합니다. %02h는 16진수, %b는 이진수, $time은 현재 시간을 표시합니다.
$finish;시험을 종료합니다. 출력의 정오를 자동 판정하지는 않습니다.

이번 단계는 관찰형 TB입니다. 다음 단계에서는 클록과 리셋을 추가로 다루고, 제4장에서 기대값과 실제 값을 비교하는 자동 판정으로 발전합니다.
