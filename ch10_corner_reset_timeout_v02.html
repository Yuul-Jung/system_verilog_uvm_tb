제10장 · 경계조건·오류 주입

기존 PWM RTL로 0%·100% 경계, 중간 리셋, 오류 주입 검출 능력을 확인합니다.

제3부 · 제10장1교시 60분 + 2교시 60분DUT 원본 보존

00개요 · 정상과 비정상을 함께 검증한다

제09장에서는 원본 PWM 회로와 독립 참조 모델의 공개 출력을 매 클록 비교했습니다. 제10장에서는 경계조건과 오류 검출 능력을 확인합니다. 단순히 정상 시험에서 PASS가 나오는 것만으로는 검증 환경이 실제 오류를 잡아낼 수 있는지 알 수 없습니다.

Corner Case(코너 케이스, 경계조건)는 0%, 100%, 리셋 전후처럼 일반 동작의 끝부분을 검사하는 방법입니다. Fault Injection(폴트 인젝션, 오류 주입)은 의도적으로 틀린 입력이나 관찰값을 만들어 검증기의 반응을 확인하는 방법입니다. 이번 오류 주입은 테스트벤치 외부 입력 및 관찰 경로에만 적용하며 DUT(검증 대상 회로) 원본은 고치지 않습니다.

구간시간내용
1교시0~60분원본 PWM 계약, 0/100% 경계, 리셋, 적용 타임아웃, 오류 주입 설계
2교시60~120분TB 전체 코드, 3가지 실행 모드, 결과 해석, 파형과 오류 검증

011교시 ① · 원본 RTL의 경계조건 (0~20분)

원본 pwm_core는 한 주기를 클록 횟수로 표현합니다. 이번 실습은 RESET_PERIOD=8, cfg_period=8, 클록 10ns를 사용합니다. 따라서 한 주기는 80ns입니다. 출력은 active_enable이 1이고, 정상 극성에서 counter < active_duty일 때 HIGH입니다.

설정기대 출력검사 목적
cfg_duty=0항상 LOW0% 경계 오프바이원(한 칸 차이) 오류 검출
cfg_duty=8항상 HIGH100% 마지막 박자 계산 오류 검출
cfg_enable=0항상 LOW출력 차단 우선순위 (기존 DUT 계약)
resetn=0즉시 LOW출력 조합 게이트 기능 확인

이 장의 실행 시험은 cfg_enable=1, cfg_polarity=0으로 유지하여 0%와 100%의 기준값을 명확히 비교합니다. Enable/Pole 반전의 조합 시험은 제09장의 스코어보드 검증에서 다룹니다.

실제 신호 이름은 cfg_apply, pending, active_duty, pwm_out입니다. 새로운 설정은 cfg_apply를 상승 에지에 읽어 Shadow에 보관하고, 주기 경계에서 Active로 반영합니다.

021교시 ② · 적용 대기와 10클록 기한 (20~40분)

설정 요청을 입력했다고 바로 active_duty를 검사하면 잘못된 실패가 발생합니다. 원본 PWM은 주기 경계에서 값을 반영하기 때문입니다. 그래서 테스트벤치의 request_duty()가 한 클록 동안 cfg_apply를 올린 다음, check_constant_window()가 pending=0과 active_duty의 목표값을 동시에 확인합니다.

설정이 주기 8클록 안에 반영되어야 하므로 관찰에는 여유를 포함한 10번 상승 에지라는 제한을 둡니다. 이 기한이 지나도 기대 설정이 적용되지 않으면 APPLY_TIMEOUT으로 중단합니다. 전체 시뮬레이션에는 별도로 5000ns 제한을 두어 이벤트 대기로 무한히 멈추는 상황도 방지합니다.

왜 단순히 pending=0만 확인하지 않을까요? 요청을 실제로 받지 못했어도 pending은 계속 0일 수 있습니다. active_duty까지 목표값과 일치하는지 확인해야 설정 요청이 무시된 결함도 검출할 수 있습니다.

031교시 ③ · 동기식 레지스터 리셋과 즉시 출력 차단 (40~50분)

resetn은 LOW 활성입니다. pwm_out은 resetn에 직접 연결된 조합 논리로 출력되므로 클록과 무관하게 즉시 LOW가 됩니다. 반면 active_period, active_duty, active_enable 등은 always @(posedge clk) 내부에서만 초기화됩니다.

따라서 시험은 두 시점을 분리합니다. 먼저 클록 상승 에지 사이에 resetn=0을 넣고 1ns 뒤 출력이 LOW인지 검사합니다. 그다음 상승 에지 이후 active_duty=0, active_enable=0, pending=0인지 확인합니다.

이렇게 분리하지 않으면 출력 즉시 차단 기능의 결함을 놓치거나, 아직 상승 에지가 발생하지 않은 레지스터에 대해 잘못된 기대값을 적용할 수 있습니다.

041교시 ④ · 오류 주입은 DUT가 아닌 검증 경로에서 (50~60분)

오류 주입의 목표는 원본 PWM에 결함을 만들어 넣는 것이 아닙니다. 잘못된 결과가 나타났을 때 검증기가 제대로 중단하고 이유를 설명하는지 확인하는 것입니다. 이번 장에서는 독립된 두 가지 부정 시험을 사용합니다.

실행 모드의도적 비정상 상황기대 반응
기본 실행없음48번 정상 출력 검사를 마치고 PASS
+INJECT_FAULTmeasured_pwm의 관찰값만 반전DETECTED_INJECTED_FAULT로 비정상 종료
+INJECT_TIMEOUT듀티 8 요청의 cfg_apply를 전달하지 않음DETECTED_APPLY_TIMEOUT으로 비정상 종료

첫 번째 모드에서 실제 pwm_out는 정상이지만 관찰값 measured_pwm가 반대가 됩니다. 두 번째 모드는 외부 요청 자체를 누락시키므로 DUT는 기존 설정을 유지합니다. 두 모드 모두 원본 RTL을 수정하지 않습니다.

중요: 부정 시험에서 시뮬레이터가 0으로 종료되면 실패입니다. 또한 비정상 종료만으로는 충분하지 않습니다. 의도한 오류 메시지가 실제로 출력됐는지까지 함께 확인해야 합니다.

052교시 ① · 전체 테스트벤치 코드 (60~90분)

테스트벤치의 역할은 입력 생성, 적용 대기, 출력 판정, 의도적 오류 주입 네 가지입니다. 아래 코드는 파일 전체 내용입니다. 비교에는 4상태 연산자 !==를 사용하므로 X/Z도 검출합니다.

tb/ch10/tb_pwm_corner_reset_timeout.sv · SystemVerilog · 신규/변경 TB · RTL 시뮬레이션 미실행
`timescale 1ns/1ps
// 제10장: PWM 경계값, 실행 중 리셋, 타임아웃을 자동 판정한다.
// 원본 pwm_core는 수정하지 않고 공개 포트만 사용한다.
module tb_pwm_corner_reset_timeout;
    reg clk = 1'b0;
    reg resetn = 1'b0;
    reg cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8, cfg_duty = 32'd0;
    reg cfg_enable = 1'b1, cfg_polarity = 1'b0;
    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    integer checks = 0;
    integer requests = 0;

    // (추가) 관찰값 오류 및 설정 요청 누락을 DUT 외부에서 주입한다.
    // +INJECT_FAULT: 측정 경로만 반전 → 스코어보드 검출 시험.
    // +INJECT_TIMEOUT: 듀티 8 요청을 누락 → 적용 기한 검출 시험.
    reg inject_fault = 1'b0;
    reg inject_timeout = 1'b0;
    reg corrupt_observation = 1'b0;
    wire measured_pwm = pwm_out ^ corrupt_observation;

    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .pwm_out(pwm_out), .pending(pending),
        .active_period(active_period), .active_duty(active_duty),
        .active_enable(active_enable), .active_polarity(active_polarity)
    );
    always #5 clk = ~clk;

    // (추가) 세 가지 실행 모드 각각의 파형을 해당 실행 폴더에 저장한다.
    initial begin
        $dumpfile("ch10_pwm_corner_reset_timeout.vcd");
        $dumpvars(0, tb_pwm_corner_reset_timeout);
    end

    // 실패 시 무한 대기하지 않도록 전체 시뮬레이션에 상한을 둔다.
    initial begin
        #5000;
        $fatal(1, "FAIL GLOBAL_TIMEOUT");
    end

    // (변경) 상태 검사와 PWM 측정값 검사를 구별한다.
    // 주입 시험에서 DUT 원본 pwm_out은 변경하지 않는다.
    task automatic check_outputs(
        input [31:0] expected_duty,
        input expected_pwm,
        input expected_pending
    );
        begin
            if (active_period !== 32'd8 ||
                active_duty !== expected_duty ||
                active_enable !== 1'b1 ||
                active_polarity !== 1'b0 ||
                pending !== expected_pending) begin
                $fatal(1, "FAIL STATE duty=%0d pending=%b", active_duty, pending);
            end

            if (measured_pwm !== expected_pwm) begin
                if (corrupt_observation && (pwm_out === expected_pwm))
                    $fatal(1, "DETECTED_INJECTED_FAULT dut=%b measured=%b",
                        pwm_out, measured_pwm);
                $fatal(1, "FAIL PWM actual=%b expected=%b",
                    measured_pwm, expected_pwm);
            end
            checks = checks + 1;
        end
    endtask

    // (변경) +INJECT_TIMEOUT이면 DUT가 아니라 외부 cfg_apply를 누락한다.
    task automatic request_duty(input [31:0] duty);
        reg withhold_apply;
        begin
            @(negedge clk);
            withhold_apply = inject_timeout && (duty == 32'd8);
            cfg_period = 32'd8;
            cfg_duty = duty;
            cfg_enable = 1'b1;
            cfg_polarity = 1'b0;
            cfg_apply = !withhold_apply;
            @(negedge clk);
            cfg_apply = 1'b0;
            requests = requests + 1;
            if (!withhold_apply && pending !== 1'b1)
                $fatal(1, "FAIL request not pending");
            if (withhold_apply)
                $display("INJECT: cfg_apply intentionally withheld");
        end
    endtask

    // (변경) pending과 active_duty를 모두 확인한 뒤 전체 두 주기를 검사한다.
    task automatic check_constant_window(
        input [31:0] duty,
        input expected_level
    );
        integer i;
        begin
            request_duty(duty);

            // 최대 10클록 동안 새 설정의 실제 적용을 기다린다.
            for (i = 0; i < 10 &&
                 ((pending !== 1'b0) || (active_duty !== duty));
                 i = i + 1) begin
                @(posedge clk);
                #1;
            end

            if (pending !== 1'b0 || active_duty !== duty) begin
                if (inject_timeout && duty == 32'd8)
                    $fatal(1, "DETECTED_APPLY_TIMEOUT duty=8 deadline=10clks");
                $fatal(1, "FAIL APPLY_TIMEOUT duty=%0d", duty);
            end

            // (추가) DUT 출력은 손대지 않고 관찰 회로에서만 비트 반전.
            corrupt_observation = inject_fault && (duty == 32'd8);
            for (i = 0; i < 16; i = i + 1) begin
                @(posedge clk);
                #1;
                check_outputs(duty, expected_level, 1'b0);
            end
            corrupt_observation = 1'b0;
        end
    endtask

    initial begin
        inject_fault = $test$plusargs("INJECT_FAULT");
        inject_timeout = $test$plusargs("INJECT_TIMEOUT");
        if (inject_fault && inject_timeout)
            $fatal(1, "FAIL: 동시에 두 오류 모드를 선택하지 마세요");

        // 동기 리셋: 첫 상승 에지 이후 초기 레지스터를 검사한다.
        @(posedge clk); #1;
        if (active_period !== 32'd8 || active_duty !== 0 ||
            active_enable !== 0 || pending !== 0 || pwm_out !== 0)
            $fatal(1, "FAIL initial reset");
        @(negedge clk);
        resetn = 1'b1;

        check_constant_window(32'd0, 1'b0); // 0%: 항상 LOW
        check_constant_window(32'd8, 1'b1); // 100%: 항상 HIGH

        // 동작 중 리셋을 하강 에지 사이에 가한다.
        #2 resetn = 1'b0;
        #1;
        if (pwm_out !== 1'b0)
            $fatal(1, "FAIL async output gate");
        @(posedge clk); #1;
        if (active_period !== 32'd8 || active_duty !== 0 ||
            active_enable !== 0 || pending !== 0 || pwm_out !== 0)
            $fatal(1, "FAIL synchronous register reset");
        @(negedge clk);
        resetn = 1'b1;

        check_constant_window(32'd8, 1'b1); // 리셋 뒤 재설정
        $display("PASS CH10 requests=%0d checks=%0d", requests, checks);
        $finish;
    end
endmodule

코드 풀이 — 핵심 절차 연결

request_duty()는 하강 에지에 설정을 넣고 다음 하강 에지에 cfg_apply를 내립니다. +INJECT_TIMEOUT일 때 듀티 8 요청에 한해 이 펄스를 의도적으로 생략합니다. 이후 check_constant_window()는 Active 설정이 바뀌는지 최대 10클록을 지켜봅니다.

check_outputs()는 active_period, active_duty, active_enable, active_polarity, pending을 먼저 검사하고 measured_pwm을 기대 레벨과 비교합니다. 의도적 반전이 있을 때는 원본 PWM이 정상인지도 확인한 뒤 DETECTED_INJECTED_FAULT를 출력합니다.

check_constant_window()는 활성 설정이 확인되면 16번의 상승 에지에서 PWM 출력을 검사합니다. 듀티 0, 듀티 8, 리셋 이후 듀티 8의 세 묶음이 정상적으로 끝나면 총 48회 검사가 수행됩니다.

062교시 ② · 실행 스크립트 및 로그 분리 (90~105분)

Ubuntu(우분투, 리눅스 배포판)의 Icarus Verilog(아이카루스 베릴로그, RTL 시뮬레이터)에서 한 번 컴파일한 뒤 동일 TB를 세 모드로 실행합니다. 스크립트는 set -euo pipefail을 사용하므로 정상 시험 실패를 성공으로 숨기지 않습니다.

scripts/run_ch10.sh · Bash · 전체 실행 스크립트 · 미실행
#!/usr/bin/env bash
# 제10장: 정상 경계값 시험 + 오류 주입 2건(예상 실패)을 자동 확인한다.
# 오류 주입은 테스트벤치의 관찰 경로/입력 요청에만 적용한다. DUT 수정 없음.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
TB_PATH="$ROOT/tb/ch10/tb_pwm_corner_reset_timeout.sv"
OUT="$ROOT/.build/ch10"

for tool in iverilog vvp; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "NOT_RUN: $tool 미설치. sudo apt update && sudo apt install iverilog" >&2
    exit 2
  fi
done
if [[ ! -f "$DUT_PATH" ]]; then
  echo "FAIL: 원본 DUT 파일 없음: $DUT_PATH" >&2
  exit 1
fi

mkdir -p "$OUT"
iverilog -g2012 -s tb_pwm_corner_reset_timeout -o "$OUT/sim.vvp" \
  "$DUT_PATH" "$TB_PATH" 2>&1 | tee "$OUT/build.log"

# ① 정상 사례: 실제 DUT가 0%·100%·중간 리셋·재설정을 통과해야 함.
(cd "$OUT" && vvp ./sim.vvp | tee normal.log)
if [[ -f "$OUT/ch10_pwm_corner_reset_timeout.vcd" ]]; then
  mv "$OUT/ch10_pwm_corner_reset_timeout.vcd" "$OUT/normal.vcd"
fi
grep -q '^PASS CH10 requests=3 checks=48
  echo "FAIL: 정상 사례가 기대한 48회 검사를 완료하지 못함" >&2
  exit 1
}

# ② 부정 시험: 관찰 경로의 PWM 값만 반전한다.
# 반드시 비정상 종료 + 전용 진단 문자열을 동시에 확인해야 통과.
if (cd "$OUT" && vvp ./sim.vvp +INJECT_FAULT >fault_injection.log 2>&1); then
  echo "FAIL: 주입한 PWM 관찰 오류를 검출하지 못함" >&2
  exit 1
fi
if [[ -f "$OUT/ch10_pwm_corner_reset_timeout.vcd" ]]; then
  mv "$OUT/ch10_pwm_corner_reset_timeout.vcd" "$OUT/fault_injection.vcd"
fi
grep -q 'DETECTED_INJECTED_FAULT' "$OUT/fault_injection.log" || {
  echo "FAIL: PWM 관찰 오류 대신 다른 이유로 실패함" >&2
  exit 1
}
echo "PASS HARNESS: 의도한 PWM 관찰 오류 검출"

# ③ 부정 시험: 듀티 8의 cfg_apply를 누락하여 적용 타임아웃을 검사한다.
if (cd "$OUT" && vvp ./sim.vvp +INJECT_TIMEOUT >apply_timeout.log 2>&1); then
  echo "FAIL: 누락한 cfg_apply를 타임아웃으로 검출하지 못함" >&2
  exit 1

09참고 · 기존 pwm_core 원본 RTL

검증 대상은 아래의 기존 reference_rtl/pwm_core.v입니다. 신호 이름과 리셋·주기 경계 동작이 테스트벤치 설명과 일치하는지 소스에서 직접 확인할 수 있습니다. 본 과제는 이 원본을 변경하지 않았습니다.

reference_rtl/pwm_core.v · Verilog · 읽기 전용 원본 · Blob e813f3fb107bd327054d11e0b397817b8e7bd813
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

counter는 내부 상태이므로 이번 검증기에서 직접 참조하지 않습니다. PWM 출력과 active_*, pending처럼 공개된 포트를 기준으로 검사합니다.
