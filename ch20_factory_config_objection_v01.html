제5부 · UVM 검증 환경

제20장 · Factory·Config·Objection

Factory·Config DB·Objection으로 기존 UVM 검증 환경의 구성·설정·종료 정책을 분리합니다.

PART 05 · CHAPTER 201교시 60분 + 2교시 60분원본 RTL 변경 없음

00개요 · 검증 로직을 고치지 않고 구성만 바꾸기

제19장에서는 Monitor(모니터, 신호 관찰), Agent(에이전트, 검증 컴포넌트 묶음), Scoreboard(스코어보드, 결과 비교)를 분리했습니다. 제20장에서는 이 검증 환경을 Factory(팩토리, 컴포넌트 구현 교체), Config DB(컨피그 디비, 설정 전달), Objection(옵젝션, 검증 종료 시점 제어)으로 관리합니다.

시간교시진행 내용
0~60분1교시Factory Override·Config DB·Objection의 필요성, 계층 연결과 수명주기
60~120분2교시기존 PWM RTL 연결, 전체 UVM 소스, 실행 스크립트, 판정과 장애 분석

DUT(디유티, 검증 대상 회로)는 기존 reference_rtl/pwm_core.v입니다. 8클록 PWM 주기, 듀티 2→6→0 설정, 10ns 클록을 그대로 사용합니다. 이번 변경은 모두 tb/ch20/의 UVM 검증 계층에서 이루어집니다.

011교시 ① · Factory는 기존 Driver의 구현만 교체한다 (0~20분)

Driver 코드를 직접 편집해 로그를 추가하면 원래 Driver가 단순 구동만 담당한다는 원칙이 무너집니다. UVM Factory Override(팩토리 오버라이드, 등록된 클래스의 실제 생성 타입 교체)는 기존 pwm20_driver의 type_id::create() 호출을 바꾸지 않은 상태에서 pwm20_traced_driver가 생성되게 합니다.

Factory Override 핵심 코드 · SystemVerilog · 실제 소스 발췌
// pwm20_test.build_phase: env 생성 전에 등록
pwm20_driver::type_id::set_type_override(
    pwm20_traced_driver::get_type());

// pwm20_agent.build_phase: 기존 생성 코드는 그대로 유지
drv = pwm20_driver::type_id::create("drv", this);

// pwm20_test.run_phase: 실제 객체 타입 검증
if (!$cast(traced, env.ag.drv))
    `uvm_fatal("FACTORY", "Driver type override was ignored")

기존 기반 클래스 pwm20_driver에는 virtual task drive_one()이 있습니다. 파생 클래스가 이를 오버라이드하여 로그를 남기고 super.drive_one(req)로 원래 구동 기능을 실행합니다. 따라서 기본 동작 유지 + 관찰 기능 추가가 가능합니다.

주의할 점은 Factory 등록 시점입니다. env가 하위 컴포넌트를 생성하기 전에 Override를 등록해야 하므로 pwm20_test.build_phase()에서 설정합니다.

021교시 ② · Config DB로 검증 설정을 공유한다 (20~40분)

제19장의 듀티 계획과 타임아웃은 Scoreboard 또는 Driver에 직접 적혀 있었습니다. 제20장에서는 pwm20_cfg 설정 객체 하나에 duty_plan, max_wait_cycles, max_apply_ns, expected_transactions, enable_trace를 모읍니다.

설정 변수기준값사용하는 곳
duty_plan[3]2, 6, 0Sequence 입력 계획 · Scoreboard 기대값
max_wait_cycles12Driver의 Pending 대기 제한
max_apply_ns80nsScoreboard의 요청→적용 기한
expected_transactions3Sequence 반복·최종 완료 검사
enable_trace1교체된 Driver의 진단 로그
Config DB의 설정/조회 · SystemVerilog · 실제 소스 발췌
// Test가 env 아래의 컴포넌트에 전달
settings = pwm20_cfg::type_id::create("settings");
uvm_config_db#(pwm20_cfg)::set(this, "env.*", "cfg", settings);

// Driver와 Scoreboard의 build_phase에서 각각 조회
if (!uvm_config_db#(pwm20_cfg)::get(this, "", "cfg", cfg))
    `uvm_fatal("NO_CFG", "Configuration was not found")

set()는 하위 계층에 설정을 등록하고 get()은 자신에게 맞는 설정을 읽습니다. vif는 최상위에서 별도의 uvm_config_db#(virtual pwm20_if) 항목으로 전달하므로, 하드웨어 신호 접근 경로와 테스트 정책이 혼동되지 않습니다.

Sequence는 컴포넌트가 아닌 객체이므로 이번 예제에서는 생성 후 seq.cfg = settings로 같은 설정 핸들을 명시적으로 전달합니다. 이는 Config DB가 Sequence 내부에서 자동 조회된다는 뜻이 아닙니다.

031교시 ③ · Objection은 종료 허가를 관리한다 (40~60분)

UVM의 run_phase()는 여러 컴포넌트에서 병렬로 수행됩니다. 아무도 Objection을 올리지 않으면 DUT 검사가 끝나기 전에 런타임 단계가 종료될 수 있습니다. Test는 검증 업무가 시작될 때 phase.raise_objection(this)를 호출하고, 입력 3개·관찰 3개·Factory 타입 확인까지 끝난 뒤 phase.drop_objection(this)를 호출합니다.

Objection 완료 조건 · SystemVerilog · 실제 소스 발췌
phase.raise_objection(this);
seq.start(env.ag.sqr);
repeat (2) @(negedge vif.clk);
if (env.ag.drv.driven != settings.expected_transactions ||
    traced.trace_count != settings.expected_transactions ||
    env.sb.requests != settings.expected_transactions ||
    env.sb.applied != settings.expected_transactions)
    `uvm_fatal("COUNTS", "Factory/Monitor/Scoreboard count mismatch")
phase.drop_objection(this);

Objection은 성공 판정을 대신하지 않습니다. DUT가 틀린 값을 내면 Scoreboard에서 uvm_fatal을 실행하고 테스트는 실패합니다. 반대로 Objection을 내리기 전에 실제 처리 건수를 확인해야 정상 종료를 PASS로 오인하지 않습니다. 파일에는 별도 2000ns 전역 타임아웃도 두었습니다.

042교시 ① · PWM 검증 환경의 전체 구성 코드 (60~90분)

pwm20_if → pwm20_cfg → 거래 객체·Sequence → 기본 Driver/교체 Driver → Monitor → Scoreboard → Agent → Environment → Test → Top 순으로 읽습니다. 최상위는 기존 PWM 포트 연결, 클록, 인터페이스 전달만 담당합니다.

tb/ch20/tb_pwm_factory_config_objection.sv · SystemVerilog · 전체 UVM 테스트벤치 · 실제 실행 전
`timescale 1ns/1ps
// 제20장: Factory Override + Config DB + Objection의 역할을 분리한다.
// DUT는 읽기 전용 reference_rtl/pwm_core.v, 원본 포트만 연결한다.
// PART 05의 제18~19장과 동일하게 듀티 2 → 6 → 0을 검증한다.
interface pwm20_if(input logic clk);
    logic        resetn = 1'b0;
    logic        cfg_apply = 1'b0;
    logic [31:0] cfg_period = 32'd8;
    logic [31:0] cfg_duty = 32'd0;
    logic        cfg_enable = 1'b0;
    logic        cfg_polarity = 1'b0;
    wire         pwm_out, pending, active_enable, active_polarity;
    wire [31:0]  active_period, active_duty;
endinterface

package ch20_uvm_pkg;
    import uvm_pkg::*;
    `include "uvm_macros.svh"

    // (추가) Config DB에서 공유할 검증 설정 객체.
    // DUT 출력에서 기대값을 복사하지 않고 테스트의 계약을 저장한다.
    class pwm20_cfg extends uvm_object;
        `uvm_object_utils(pwm20_cfg)
        bit [31:0] duty_plan[3];
        int unsigned max_wait_cycles;
        time max_apply_ns;
        int unsigned expected_transactions;
        bit enable_trace;
        function new(string name="pwm20_cfg");
            super.new(name);
            duty_plan[0] = 32'd2;
            duty_plan[1] = 32'd6;
            duty_plan[2] = 32'd0;
            max_wait_cycles = 12;
            max_apply_ns = 80;
            expected_transactions = 3;
            enable_trace = 1'b1;
        endfunction
    endclass

    class pwm20_item extends uvm_sequence_item;
        `uvm_object_utils(pwm20_item)
        bit [31:0] duty;
        function new(string name="pwm20_item");
            super.new(name);
        endfunction
    endclass

    class pwm20_sequence extends uvm_sequence #(pwm20_item);
        `uvm_object_utils(pwm20_sequence)
        pwm20_cfg cfg;
        function new(string name="pwm20_sequence");
            super.new(name);
        endfunction
        task body();
            pwm20_item req;
            if (cfg == null)
                `uvm_fatal("SEQ_CFG", "Sequence config not provided")
            for (int i=0; i<int'(cfg.expected_transactions); i++) begin
                req = pwm20_item::type_id::create($sformatf("req_%0d", i));
                start_item(req);
                req.duty = cfg.duty_plan[i];
                finish_item(req);
            end
        endtask
    endclass

    class pwm20_sequencer extends uvm_sequencer #(pwm20_item);
        `uvm_component_utils(pwm20_sequencer)
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
    endclass

    // (추가) 기본 Driver: 객체·인터페이스·설정만으로 일반적 구동을 수행.
    // 동작 변경이나 로그 추가는 원본 DUT가 아니라 Factory Override로 처리.
    class pwm20_driver extends uvm_driver #(pwm20_item);
        `uvm_component_utils(pwm20_driver)
        virtual pwm20_if vif;
        pwm20_cfg cfg;
        int unsigned driven = 0;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(virtual pwm20_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "pwm20_if not configured")
            if (!uvm_config_db#(pwm20_cfg)::get(this, "", "cfg", cfg))
                `uvm_fatal("NO_CFG", "Driver config not found")
        endfunction
        virtual task drive_one(pwm20_item req);
            int unsigned guard;
            @(negedge vif.clk);
            vif.cfg_period = 32'd8;
            vif.cfg_duty = req.duty;
            vif.cfg_enable = 1'b1;
            vif.cfg_polarity = 1'b0;
            vif.cfg_apply = 1'b1;
            @(negedge vif.clk);
            vif.cfg_apply = 1'b0;

            // 이 Driver는 다음 입력을 보낼 타이밍만 제어한다.
            // 요청·적용 데이터의 정답은 Scoreboard가 별도로 검사한다.
            guard = 0;
            while (vif.pending !== 1'b0) begin
                @(negedge vif.clk);
                guard++;
                if (guard > cfg.max_wait_cycles)
                    `uvm_fatal("DRV_TIMEOUT", "Pending did not clear")
            end
            driven++;
        endtask
        task run_phase(uvm_phase phase);
            pwm20_item req;
            forever begin
                seq_item_port.get_next_item(req);
                drive_one(req);
                seq_item_port.item_done();
            end
        endtask
    endclass

    // (추가) 기본 Driver를 수정하지 않고 로깅만 덧붙이는 교체 구현.
    class pwm20_traced_driver extends pwm20_driver;
        `uvm_component_utils(pwm20_traced_driver)
        int unsigned trace_count = 0;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        virtual task drive_one(pwm20_item req);
            if (cfg.enable_trace)
                `uvm_info("FACTORY_TRACE",
                    $sformatf("DRIVE duty=%0d", req.duty), UVM_LOW)
            super.drive_one(req);
            trace_count++;
        endtask
    endclass

    typedef enum {PWM20_REQUEST, PWM20_APPLIED} pwm20_kind_e;
    class pwm20_sample extends uvm_sequence_item;
        `uvm_object_utils(pwm20_sample)
        pwm20_kind_e kind;
        logic [31:0] duty, period;
        logic enable, polarity, pending, pwm;
        time sampled_at;
        function new(string name="pwm20_sample");
            super.new(name);
        endfunction
    endclass

    // (유지/확장) Monitor: 공개 입력과 출력을 관찰만 하며 구동하지 않는다.
    class pwm20_monitor extends uvm_monitor;
        `uvm_component_utils(pwm20_monitor)
        virtual pwm20_if vif;
        uvm_analysis_port #(pwm20_sample) ap;
        bit previous_pending = 1'b0;
        function new(string name, uvm_component parent);
            super.new(name, parent);
            ap = new("ap", this);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(virtual pwm20_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "Monitor interface missing")
        endfunction
        task run_phase(uvm_phase phase);
            pwm20_sample s;
            forever begin
                @(posedge vif.clk);
                #1; // 상승 에지의 비차단 대입 완료 이후 읽는다.
                if (!vif.resetn) begin
                    previous_pending = 1'b0;
                end else begin
                    if (vif.cfg_apply === 1'b1) begin
                        s = pwm20_sample::type_id::create("req_sample");
                        s.kind = PWM20_REQUEST;
                        s.duty = vif.cfg_duty;
                        s.period = vif.cfg_period;
                        s.enable = vif.cfg_enable;
                        s.polarity = vif.cfg_polarity;
                        s.pending = vif.pending;
                        s.pwm = vif.pwm_out;
                        s.sampled_at = $time;
                        ap.write(s);
                    end
                    if (previous_pending && vif.pending === 1'b0) begin
                        s = pwm20_sample::type_id::create("applied_sample");
                        s.kind = PWM20_APPLIED;
                        s.duty = vif.active_duty;
                        s.period = vif.active_period;
                        s.enable = vif.active_enable;
                        s.polarity = vif.active_polarity;
                        s.pending = vif.pending;
                        s.pwm = vif.pwm_out;
                        s.sampled_at = $time;
                        ap.write(s);
                    end
                    previous_pending = (vif.pending === 1'b1);
                end
            end
        endtask
    endclass

    // (추가) Scoreboard는 Config DB 설정을 읽어 계획값과 비교한다.
    class pwm20_scoreboard extends uvm_scoreboard;
        `uvm_component_utils(pwm20_scoreboard)
        uvm_analysis_imp #(pwm20_sample, pwm20_scoreboard) analysis_export;
        pwm20_cfg cfg;
        int unsigned requests = 0, applied = 0;
        time request_time[3];
        function new(string name, uvm_component parent);
            super.new(name, parent);
            analysis_export = new("analysis_export", this);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(pwm20_cfg)::get(this, "", "cfg", cfg))
                `uvm_fatal("NO_CFG", "Scoreboard config not found")
        endfunction
        function void write(pwm20_sample s);
            if (s.kind == PWM20_REQUEST) begin
                if (requests >= cfg.expected_transactions)
                    `uvm_fatal("EXTRA_REQUEST", "More requests than configured")
                if (s.period !== 32'd8 ||
                    s.duty !== cfg.duty_plan[requests] ||
                    s.enable !== 1'b1 || s.polarity !== 1'b0 ||
                    s.pending !== 1'b1)
                    `uvm_fatal("REQ_MISMATCH", "Request was not as configured")
                request_time[requests] = s.sampled_at;
                requests++;
                `uvm_info("SCOREBOARD",
                    $sformatf("REQUEST %0d", requests), UVM_LOW)
            end else if (s.kind == PWM20_APPLIED) begin
                if (applied >= requests || applied >= cfg.expected_transactions)
                    `uvm_fatal("APPLY_ORDER", "Applied event without request")
                if (s.period !== 32'd8 ||
                    s.duty !== cfg.duty_plan[applied] ||
                    s.enable !== 1'b1 || s.polarity !== 1'b0 ||
                    s.pending !== 1'b0 ||
                    s.pwm !== (cfg.duty_plan[applied] != 0))
                    `uvm_fatal("APPLY_MISMATCH", "PWM active setting mismatch")
                if (s.sampled_at < request_time[applied] ||
                    s.sampled_at - request_time[applied] > cfg.max_apply_ns)
                    `uvm_fatal("APPLY_LATENCY", "Applied after allowed deadline")
                applied++;
                `uvm_info("SCOREBOARD",
                    $sformatf("APPLIED %0d", applied), UVM_LOW)
            end else begin
                `uvm_fatal("UNKNOWN_EVENT", "Unexpected monitor event kind")
            end
        endfunction
    endclass

    // (유지) Agent는 Driver를 기반 클래스 타입으로 factory 생성한다.
    // 실제 객체는 Test의 Override 정책에 따라 traced_driver가 된다.
    class pwm20_agent extends uvm_agent;
        `uvm_component_utils(pwm20_agent)
        pwm20_sequencer sqr;
        pwm20_driver drv;
        pwm20_monitor mon;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            sqr = pwm20_sequencer::type_id::create("sqr", this);
            drv = pwm20_driver::type_id::create("drv", this);
            mon = pwm20_monitor::type_id::create("mon", this);
        endfunction
        function void connect_phase(uvm_phase phase);
            super.connect_phase(phase);
            drv.seq_item_port.connect(sqr.seq_item_export);
        endfunction
    endclass

    class pwm20_env extends uvm_env;
        `uvm_component_utils(pwm20_env)
        pwm20_agent ag;
        pwm20_scoreboard sb;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            ag = pwm20_agent::type_id::create("ag", this);
            sb = pwm20_scoreboard::type_id::create("sb", this);
        endfunction

            ag.mon.ap.connect(sb.analysis_export);
        endfunction
    endclass

    // (추가) Factory/Config/Objection의 책임은 Test에 집중한다.
    class pwm20_test extends uvm_test;
        `uvm_component_utils(pwm20_test)
        pwm20_cfg settings;
        virtual pwm20_if vif;
        pwm20_env env;
        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction
        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            settings = pwm20_cfg::type_id::create("settings");
            if (!uvm_config_db#(virtual pwm20_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "Test interface missing")

            // Factory Override는 env.build_phase() 실행 이전에 등록한다.
            pwm20_driver::type_id::set_type_override(
                pwm20_traced_driver::get_type());

            // Config DB는 구성 값을 계층 아래에 공유한다.
            uvm_config_db#(pwm20_cfg)::set(this, "env.*", "cfg", settings);
            env = pwm20_env::type_id::create("env", this);
        endfunction

        task run_phase(uvm_phase phase);
            pwm20_sequence seq;
            pwm20_traced_driver traced;

            // (추가) Objection을 올려 UVM이 Sequence 도중 종료되지 않게 한다.
            phase.raise_objection(this);
            repeat (3) @(negedge vif.clk);
            if (vif.active_period !== 32'd8 ||
                vif.active_duty !== 32'd0 || vif.pending !== 1'b0)
                `uvm_fatal("RESET", "PWM sync reset not confirmed")
            vif.resetn = 1'b1;

            // 실제 생성 객체가 Override된 타입인지 런타임에 확인.
            if (!$cast(traced, env.ag.drv))
                `uvm_fatal("FACTORY", "Driver type override was ignored")

            seq = pwm20_sequence::type_id::create("seq");
            seq.cfg = settings;
            seq.start(env.ag.sqr);
            repeat (2) @(negedge vif.clk);

            // 입력 3건과 Monitor·Scoreboard 적용 관찰 3건을 모두 확인.
            if (env.ag.drv.driven != settings.expected_transactions ||
                traced.trace_count != settings.expected_transactions ||
                env.sb.requests != settings.expected_transactions ||
                env.sb.applied != settings.expected_transactions)
                `uvm_fatal("COUNTS", "Factory/Monitor/Scoreboard count mismatch")
            `uvm_info("RESULT",
                "PASS CH20 factory=traced config=3 applied=3", UVM_NONE)

            // 모든 판정을 마친 뒤 Objection을 내려 종료를 허용한다.
            phase.drop_objection(this);
        endtask

pwm20_agent.build_phase()는 여전히 pwm20_driver::type_id::create("drv", this)로 구동기를 생성합니다. 하지만 Test에서 Factory Override가 등록되었으므로 파생 타입이 선택됩니다. pwm20_test.run_phase()의 $cast로 실제 생성 타입도 확인합니다.

이후 Sequence는 설정 객체의 듀티 2→6→0을 생성하고, Driver가 입력을 구동합니다. Monitor는 PWM20_REQUEST와 PWM20_APPLIED 두 이벤트를 ap.write()로 Scoreboard에 전달합니다. Scoreboard는 Config DB에서 받은 계획과 실제 출력을 비교합니다.

#!/usr/bin/env bash
# 제20장 UVM Factory/Config/Objection 검증. DUT 원본 수정 금지.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
TB_PATH="$ROOT/tb/ch20/tb_pwm_factory_config_objection.sv"
OUT="$ROOT/.build/ch20"

if [[ ! -f "$DUT_PATH" || ! -f "$TB_PATH" ]]; then
  echo "NOT_RUN: PWM DUT 또는 제20장 테스트벤치 파일이 없습니다." >&2
  exit 2
fi
if ! command -v verilator >/dev/null 2>&1; then
  echo "NOT_RUN: Verilator가 설치되지 않았습니다." >&2
  exit 2
fi
if [[ -z "${UVM_HOME:-}" || ! -f "$UVM_HOME/src/uvm_pkg.sv" ]]; then
  echo "NOT_RUN: UVM_HOME/src/uvm_pkg.sv를 찾지 못했습니다." >&2
  exit 2
fi

mkdir -p "$OUT"
verilator --version | tee "$OUT/verilator_version.txt"

# --binary 실행 파일, --timing 지연/이벤트, --assert 검증,
# --trace VCD 파형 지원, -Wno-fatal 경고만으로 빌드 중단하지 않음.
verilator --binary --timing --assert --trace -Wno-fatal \
  --top-module tb_pwm_factory_config_objection \
  --Mdir "$OUT/obj_dir" +incdir+"$UVM_HOME/src" \
  "$UVM_HOME/src/uvm_pkg.sv" "$DUT_PATH" "$TB_PATH" \
  2>&1 | tee "$OUT/build.log"

(cd "$OUT" && ./obj_dir/Vtb_pwm_factory_config_objection \
  +UVM_TESTNAME=pwm20_test | tee simulation.log)

# 성공 종료에 더해 Trace Driver의 실행과 Scoreboard 완료를 확인한다.
if ! grep -q 'PASS CH20 factory=traced config=3 applied=3' "$OUT/simulation.log"; then
  echo "FAIL: Factory·Config·Scoreboard 판정이 완료되지 않았습니다." >&2
  exit 1
fi
if ! grep -q 'FACTORY_TRACE.*DRIVE duty=2' "$OUT/simulation.log"; then
  echo "FAIL: Traced Driver의 실제 작동 증거가 없습니다." >&2
  exit 1
fi
if grep -Eq 'UVM_(FATAL|ERROR) @[[:space:]]*[0-9]+|UVM_(FATAL|ERROR)[[:space:]]*:[[:space:]]*[1-9]' "$OUT/simulation.log"; then
  echo "FAIL: UVM 오류 메시지가 기록되었습니다." >&2
  exit 1
fi
echo "PASS CH20 SUITE: factory override + config DB + 3 applied transactions"
echo "빌드 로그: $OUT/build.log"
echo "실행 로그: $OUT/simulation.log"

실행 스크립트는 먼저 DUT 파일, Verilator 설치, UVM_HOME 경로를 확인합니다. --binary는 실행 파일을, --timing은 지연 제어를, --assert는 속성 검증 기능을 활성화하고 --trace는 VCD 출력을 위한 기능을 준비합니다. 실제 UVM 버전별 지원 차이로 빌드 오류가 발생하면 원인을 확인한 후 호환되는 버전을 사용합니다.

09참고 · 검증 대상 pwm_core 원본 RTL

아래는 이번 장에서도 수정하지 않은 PWM 원본 RTL입니다. Factory·Config DB·Objection 기능은 모두 테스트벤치 영역에만 있으며, DUT에서는 cfg_apply, cfg_duty, pending, active_duty, pwm_out 등의 공개 포트를 사용합니다.

reference_rtl/pwm_core.v · Verilog · 기존 원본 · Blob SHA e813f3fb107bd327054d11e0b397817b8e7bd813
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

원본의 동기 리셋, Shadow→Active 전환, 주기 경계 적용은 제17~19장과 같은 계약입니다. DUT 내부 counter·shadow_duty를 Scoreboard의 정답으로 사용하지 않습니다.
