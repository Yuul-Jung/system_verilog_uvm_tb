00개요 · 독립 기대값으로 매 클록 검증

제04장에서는 PWM(Pulse Width Modulation, 펄스폭 변조)의 한 주기 HIGH 개수를 비교했습니다. 개수가 같더라도 출력 위상이나 설정 반영 시점이 다를 수 있습니다. 이번 장에서는 DUT와 같은 입력을 참조 모델에 전달하고, 매 상승 에지 이후 두 출력의 상태를 비교합니다.

선행 설계 학습안내서: 제2부 사용자 AXI IP와 주변장치(amd_soc_p2), 04.2장 「RTL · AXI 풀이」 02절 「설정 Shadow와 출력 Active를 분리」 및 06절 「독립 PWM Core 전체」. 파일은 pwm_core.v입니다. AXI 래퍼 및 보드는 검증 대상이 아닙니다.

실습 폴더를 먼저 만들고 01절·04절·05절의 전체 코드를 해당 파일에 저장합니다.

01원본 RTL · PWM의 기능 계약

원본은 설정을 Shadow(섀도, 대기 설정)에 저장하고 주기 경계에서 Active(액티브, 활성 설정)로 반영합니다. 이 장의 실습은 8클록 주기, 10ns 클록, 듀티 0~8에 한정합니다.

reference_rtl/pwm_core.v · Verilog
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

내부 상태는 상승 에지의 동기 리셋으로 초기화되지만 출력 pwm_out은 resetn에 의해 조합적으로 차단됩니다. 따라서 두 리셋 효과의 발생 시점을 구분해야 합니다.

02DUT·Reference Model·Scoreboard

Reference Model(레퍼런스 모델, 정답 동작 모델)은 입력과 자신의 상태로 기대값을 계산합니다. Scoreboard(스코어보드, 실제값과 기대값 비교기)는 두 출력의 차이를 판정합니다. 이 스코어보드는 별도 RTL 모듈이 아니라 TB 내부 always 블록입니다.

DUT 공개 출력참조 모델 출력검사
pwm_outref_pwm출력 위상·극성
pendingref_pending설정 대기 여부
active_period[31:0]ref_period[31:0]활성 주기
active_duty[31:0]ref_duty[31:0]활성 듀티
active_enableref_enable출력 활성

독립 상태를 가진 모델이라고 해서 정답이 보장되는 것은 아닙니다. 현재 모델과 DUT는 구조와 수식이 유사하여 같은 명세 해석 오류를 공유할 수 있습니다. 독립적으로 계산한 적용 시간표와 경계값·속성 검사를 함께 사용해야 합니다.

03시간 계약 · 요청과 반영을 구분한다

하강 에지에서 설정을 요청하고, 다음 상승 에지에서 대기 설정이 저장됩니다. 주기 경계가 오면 이전에 저장된 요청이 활성화됩니다. 새 요청이 경계와 같은 에지에 들어오면 현재 경계가 아니라 다음 경계에 반영됩니다.

사례요청 ns수락 상승 에지 ns활성 반영 ns관찰 ns활성 설정
130359596duty 2, en 1, pol 0
2140145175176duty 6, en 1, pol 0
3250255335336duty 6, en 1, pol 1
4360365415416duty 6, en 0, pol 1
5470475495496duty 8, en 1, pol 0
6610615675676duty 0, en 1, pol 0

사례 3은 250ns에 요청하고 255ns 경계에서 수락합니다. 이전 pending이 0이므로 255ns에는 새 극성이 반영되지 않고 335ns 경계에서 반영됩니다. 리셋은 580ns에 인가되며 581ns에 조합 출력 차단을 확인합니다. 585ns 상승 에지에서 내부 상태가 초기화됩니다.

위 시간표는 초기 리셋 해제 후 8개 상승 에지마다 경계가 발생한다는 계약으로 계산한 예상값입니다. 내부 카운터를 읽어 산출한 로그가 아닙니다.

04참조 모델 전체 코드

모델은 phase, queued_*, ref_*를 자체 관리합니다. 현재 주기의 마지막 박자인지 계산하고, 대기 중인 설정만 반영합니다.

tb/ch09/pwm_reference_model.sv · SystemVerilog
`timescale 1ns/1ps
// (추가) 제09장: 공개 PWM 계약으로 예상값을 계산하는 독립 참조 모델.
// DUT 내부 신호 counter, boundary, shadow_*는 참조하지 않는다.
module pwm_reference_model #(
    parameter [31:0] INITIAL_PERIOD = 32'd8
)(
    input wire clk, resetn, cfg_apply,
    input wire [31:0] cfg_period, cfg_duty,
    input wire cfg_enable, cfg_polarity,
    output wire ref_pwm,
    output reg ref_pending,
    output reg [31:0] ref_period, ref_duty,
    output reg ref_enable, ref_polarity
);
    reg [31:0] phase, queued_period, queued_duty;
    reg queued_enable, queued_polarity;

    // 주기/듀티 기준으로 DUT와 별개 예상 파형을 구한다.
    // 이번 장의 입력 주기는 항상 8이므로 0 주기는 다루지 않는다.
    wire period_end = (phase + 32'd1 >= ref_period);
    wire high_window = (phase < ref_duty);
    assign ref_pwm = resetn && ref_enable &&
                     (ref_polarity ? !high_window : high_window);

    always @(posedge clk) begin
        if (!resetn) begin
            phase           <= 32'd0;
            ref_period      <= INITIAL_PERIOD;
            ref_duty        <= 32'd0;
            ref_enable      <= 1'b0;
            ref_polarity    <= 1'b0;
            queued_period   <= INITIAL_PERIOD;
            queued_duty     <= 32'd0;
            queued_enable   <= 1'b0;
            queued_polarity <= 1'b0;
            ref_pending     <= 1'b0;
        end else begin
            // 현재 주기를 완료한 뒤 대기 중인 설정을 반영한다.
            if (period_end) begin
                phase <= 32'd0;
                if (ref_pending) begin
                    ref_period   <= queued_period;
                    ref_duty     <= queued_duty;
                    ref_enable   <= queued_enable;
                    ref_polarity <= queued_polarity;
                    ref_pending  <= 1'b0;
                end
            end else begin
                phase <= phase + 32'd1;
            end

            // 경계와 cfg_apply가 겹치면 새 값은 다음 경계에서 적용.
            if (cfg_apply) begin
                queued_period   <= cfg_period;
                queued_duty     <= cfg_duty;
                queued_enable   <= cfg_enable;
                queued_polarity <= cfg_polarity;
                ref_pending     <= 1'b1;
            end
        end
    end
endmodule
실제 코드의미
phase + 32'd1 >= ref_period고정 주기 8의 마지막 박자 판정
phase < ref_duty정상 극성의 HIGH 구간
queued_*대기 설정
ref_*활성 설정과 기대 출력
if (cfg_apply)새 요청을 대기 상태에 저장. 같은 에지의 적용보다 뒤에 대입

비차단 대입은 에지 직전 상태를 기준으로 계산합니다. 같은 에지에 적용과 새 요청이 겹치면 기존 queued 값을 반영하고 새 값을 다음 적용을 위해 저장합니다. 주기 0, 범위를 벗어난 듀티, 여러 요청의 덮어쓰기 전체 조합은 이번 실습의 검증 범위가 아닙니다.

05스코어보드 전체 테스트벤치

매 상승 에지 이후 #1ns에 공개 출력 여섯 개를 비교합니다. 이는 비차단 대입과 조합 출력 갱신이 끝난 뒤 관찰하기 위한 TB 시간이며, 실제 DUT 지연 사양은 아닙니다.

tb/ch09/tb_pwm_scoreboard.sv · SystemVerilog
`timescale 1ns/1ps
// (추가) 제09장: DUT와 참조 모델의 공개 출력 6개를 자동 비교한다.
module tb_pwm_scoreboard;
    reg clk = 1'b0, resetn = 1'b0, cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8, cfg_duty = 32'd0;
    reg cfg_enable = 1'b1, cfg_polarity = 1'b0;

    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    wire ref_pwm, ref_pending, ref_enable, ref_polarity;
    wire [31:0] ref_period, ref_duty;
    integer score_cycles = 0, scenarios = 0;

    // (추가) 원본 DUT 13포트를 변경 없이 연결한다.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .pwm_out(pwm_out), .pending(pending),
        .active_period(active_period), .active_duty(active_duty),
        .active_enable(active_enable), .active_polarity(active_polarity)
    );

    // (추가) 같은 입력을 독립된 Golden(정답) 모델에도 공급한다.
    pwm_reference_model #(.INITIAL_PERIOD(32'd8)) golden (
        .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
        .cfg_period(cfg_period), .cfg_duty(cfg_duty),
        .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
        .ref_pwm(ref_pwm), .ref_pending(ref_pending),
        .ref_period(ref_period), .ref_duty(ref_duty),
        .ref_enable(ref_enable), .ref_polarity(ref_polarity)
    );

    // 입력 자극은 하강 에지에서, 비교는 상승 에지 이후에 수행한다.
    always #5 clk = ~clk;

    // (추가) scoreboard: 4상태 비교 !==로 X/Z까지 놓치지 않는다.
    // #1은 비차단 대입이 완료된 뒤 읽는 테스트벤치 관찰 지연이다.
    always @(posedge clk) begin
        #1;
        score_cycles = score_cycles + 1;
        // (추가) 양쪽이 같은 X/Z여도 정상으로 판정하지 않는다.
        // Reduction XOR는 묶음에 X/Z가 있으면 X를 반환한다.
        if ((^{pwm_out, pending, active_period, active_duty,
               active_enable, active_polarity}) === 1'bx ||
            (^{ref_pwm, ref_pending, ref_period, ref_duty,
               ref_enable, ref_polarity}) === 1'bx)
            $fatal(1, "UNKNOWN_OUTPUT t=%0d", $time);
        if ((pwm_out         !== ref_pwm)      ||
            (pending         !== ref_pending)  ||
            (active_period   !== ref_period)   ||
            (active_duty     !== ref_duty)     ||
            (active_enable   !== ref_enable)   ||
            (active_polarity !== ref_polarity)) begin
            $display("EXPECTED t=%0d pwm=%b pend=%b period=%0d duty=%0d en=%b pol=%b",
                $time, ref_pwm, ref_pending, ref_period,
                ref_duty, ref_enable, ref_polarity);
            $fatal(1,
                "FAIL t=%0d pwm=%b pend=%b period=%0d duty=%0d en=%b pol=%b",
                $time, pwm_out, pending, active_period,
                active_duty, active_enable, active_polarity);
        end
    end

    // (추가) 설정을 한 클록만 HIGH로 전달하는 재사용 태스크.
    task automatic request_config(
        input integer case_id,
        input [31:0] duty_ticks,
        input reg enabled, inverted
    );
        begin
            @(negedge clk);
            cfg_period   = 32'd8;
            cfg_duty     = duty_ticks;
            cfg_enable   = enabled;
            cfg_polarity = inverted;
            cfg_apply    = 1'b1;
            scenarios = scenarios + 1;
            $display("REQUEST case=%0d t=%0d duty=%0d en=%b pol=%b",
                case_id, $time, duty_ticks, enabled, inverted);
            @(negedge clk);
            cfg_apply = 1'b0;
        end
    endtask

`ifdef VCD
    // (변경) VCD는 Icarus 실행에서만 활성화한다.
    initial begin
        $dumpfile("ch09_pwm_scoreboard.vcd");
        $dumpvars(0, tb_pwm_scoreboard);
    end
`endif
    initial begin
        #1200;
        $fatal(1, "CH09 TIMEOUT: 검증이 정상 종료되지 않음");
    end

    initial begin
        $display("=== CH09 PWM MODEL / SCOREBOARD START ===");

        repeat (2) @(negedge clk); // t=20ns 초기 리셋 해제
        resetn = 1'b1;

        request_config(1, 32'd2, 1'b1, 1'b0); // t=30ns: 25%
        repeat (9) @(negedge clk);

        request_config(2, 32'd6, 1'b1, 1'b0); // t=140ns: 75%
        repeat (9) @(negedge clk);

        // t=250ns 요청이 t=255ns 주기 경계와 겹친다.
        // 새 극성은 다음 주기 경계(t=335ns)에 반영되어야 한다.
        request_config(3, 32'd6, 1'b1, 1'b1);
        repeat (9) @(negedge clk);

        request_config(4, 32'd6, 1'b0, 1'b1); // 출력 차단
        repeat (9) @(negedge clk);

        request_config(5, 32'd8, 1'b1, 1'b0); // 100% HIGH
        repeat (9) @(negedge clk);

        // t=580ns: PWM HIGH 상태에서 LOW 리셋 인가.
        @(negedge clk);
        // (추가) 이미 LOW라면 출력 차단 검사가 무의미하므로 선행 조건 확인.
        if ((pwm_out !== 1'b1) || (ref_pwm !== 1'b1))
            $fatal(1, "FAIL RESET_PRECONDITION: expected HIGH");
        resetn = 1'b0;
        #1;
        if ((pwm_out !== 1'b0) || (ref_pwm !== 1'b0))
            $fatal(1, "FAIL RESET_GATE: 출력 즉시 LOW 실패");
        $display("RESET_GATE PASS t=%0d", $time);

        repeat (2) @(negedge clk); // t=600ns 리셋 해제
        resetn = 1'b1;
        request_config(6, 32'd0, 1'b1, 1'b0); // 0% 듀티
        repeat (10) @(negedge clk);

        // (추가) 현재 고정 시나리오의 전체 비교·요청 횟수 확인.
        if (score_cycles != 72 || scenarios != 6)
            $fatal(1, "FAIL COUNT cycles=%0d scenarios=%0d",
                score_cycles, scenarios);
        $display("PASS CH09 score_cycles=%0d scenarios=%0d",
            score_cycles, scenarios);
        $finish;
    end
endmodule

두 값에 동일한 X/Z가 포함되어 있으면 !==만으로는 불일치를 발견하지 못합니다. 이 실습은 정상 입력과 초기 리셋 이후의 확정 출력을 기대하므로 양쪽 출력의 미정값을 별도로 금지합니다. 리셋 차단 역시 이미 LOW라면 의미가 약하므로 HIGH였음을 먼저 확인합니다.

xsim시뮬레이션 실행·GUI 파형 관찰

07반례와 검증 범위

가상 결함예상 검출
255ns에 새 극성 즉시 반영256ns 공개 active_polarity 또는 pending 불일치
비활성화 상태에서도 출력 HIGH활성화 차단 조건에 따라 pwm_out 비교에서 검출
resetn 조합 차단 누락581ns RESET_GATE 검사
양쪽 출력에 같은 XUNKNOWN_OUTPUT 검사
비교 블록이 실행되지 않음최종 COUNT 검사

위 반례는 시간 계약과 코드 경로에 따른 논리 분석입니다. 실제 변이 RTL을 실행한 결과가 아닙니다. 두 모델이 같은 오류를 포함하거나 샘플 사이에서 순간적인 출력 이상이 발생하면 검출하지 못할 수 있습니다. 제10장은 경계조건·중간 리셋·오류 주입으로 검사를 확장합니다.
