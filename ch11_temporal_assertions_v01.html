기존 PWM 코어의 시간 계약을 SVA로 기술하고, 자동으로 위반을 탐지합니다.

PART 03 · CHAPTER 111교시 60분 + 2교시 60분DUT 원본 보존

00개요 · 파형을 규칙으로 바꾸기

SVA(SystemVerilog Assertions, 시스템베릴로그 속성 검증)는 파형을 눈으로 보는 대신 언제 무엇이 반드시 성립해야 하는가를 코드로 기록합니다. 제10장의 단발성 검사에서 한 단계 나아가, 매 클록 같은 규칙을 자동으로 검사합니다.

교시시간실습
1교시0~60분RTL 포트·타이밍 계약, 동시/다음 클록 속성, 리셋 예외
2교시60~120분전체 SVA TB, 실행 스크립트, 예상 출력, 오류 분석

011교시 ① · 기존 RTL 시간 계약 (0~20분)

pwm_core는 cfg_apply를 상승 에지에 읽어 Shadow(섀도, 대기 설정)에 보관하고, counter의 주기 경계에서 active_duty를 갱신합니다. 같은 에지에 경계와 새 요청이 겹치면 새 요청은 다음 경계까지 기다립니다. pending은 요청 수락 후 1이 됩니다.

입력은 clk, resetn, cfg_apply, cfg_period, cfg_duty, cfg_enable, cfg_polarity의 7개이고, 출력은 pwm_out, pending, active_period, active_duty, active_enable, active_polarity의 6개입니다.

리셋은 혼합 계약입니다. resetn=0일 때 pwm_out은 조합식으로 즉시 LOW가 되지만 상태 레지스터는 다음 상승 에지에서 초기화됩니다.

021교시 ② · |-> 와 |=>의 차이 (20~40분)

|->는 선행 조건과 결론을 같은 샘플 클록에서 확인합니다. |=>는 결론을 다음 샘플 클록에서 확인합니다. SVA는 상승 에지의 Preponed(프리폰드, 선행 샘플) 영역에서 값을 읽으므로, 같은 에지에서 비차단 대입으로 갱신되는 pending을 확인하려면 cfg_apply |=> pending을 사용합니다.

속성의미
!active_enable |-> !pwm_out출력 비활성일 때 같은 샘플에서 LOW
cfg_apply |=> pending요청 샘플 다음 상승 에지에서 대기 표시 확인
disable iff (!resetn)리셋 중인 속성 시도를 비활성화

disable iff는 일반적인 샘플 조건과 달리 비동기적으로 평가될 수 있습니다. 리셋 출력 차단 자체를 검사하는 속성에는 적용하지 않습니다.

031교시 ③ · 속성의 경계와 주의점 (40~60분)

현재 공개 포트만으로는 내부 counter의 경계 시점을 직접 알 수 없습니다. 따라서 이번 장에서는 주기 경계의 정확한 내부 전이를 SVA로 단정하지 않고, apply_duty()가 충분히 기다린 뒤 active_duty와 pending을 확인합니다. 내부 상태를 참조하는 속성은 향후 별도 White-box(화이트박스, 내부 구조 기반) 검증으로 확장합니다.

검사 항목은 리셋 출력 LOW, 비활성 출력 LOW, 요청 다음 클록의 pending, 듀티 0의 LOW, 듀티 8의 HIGH입니다. 100% 조건에는 active_period==8을 함께 확인해 무리한 일반화를 피합니다.

042교시 ① · 전체 테스트벤치 (60~90분)

원본 RTL은 수정하지 않고, 동일한 공개 포트에 연결한 별도 검증 모듈에서 다섯 개의 assert property를 평가합니다. $fatal은 속성 위반을 실패로 종료시킵니다.

tb/ch11/tb_pwm_sva.sv · 전체 코드 · 시뮬레이션 NOT_RUN
`timescale 1ns/1ps
// 제11장: 기존 pwm_core 공개 포트에 SVA 시간 계약을 적용한다.
// SVA를 지원하는 SystemVerilog 시뮬레이터에서만 실행한다.
module tb_pwm_sva;
  logic clk = 0, resetn = 0, cfg_apply = 0;
  logic [31:0] cfg_period = 8, cfg_duty = 0;
  logic cfg_enable = 1, cfg_polarity = 0;
  wire pwm_out, pending, active_enable, active_polarity;
  wire [31:0] active_period, active_duty;
  integer checks = 0;

  pwm_core #(.RESET_PERIOD(32'd8)) dut (
    .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
    .cfg_period(cfg_period), .cfg_duty(cfg_duty),
    .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
    .pwm_out(pwm_out), .pending(pending),
    .active_period(active_period), .active_duty(active_duty),
    .active_enable(active_enable), .active_polarity(active_polarity)
  );
  always #5 clk = ~clk;

  // 리셋 중 출력은 LOW. 조합 차단은 별도 즉시 검사로 보강한다.
  ap_reset_low: assert property (
    @(posedge clk) !resetn |-> !pwm_out
  ) else $fatal(1, "FAIL SVA reset output");

  // Enable=0이면 극성과 무관하게 출력은 LOW.
  ap_disabled_low: assert property (
    @(posedge clk) disable iff (!resetn)
      !active_enable |-> !pwm_out
  ) else $fatal(1, "FAIL SVA disabled output");

  // cfg_apply는 상승 에지에 캡처되고 pending은 다음 샘플에 1.
  // 경계와 겹쳐도 cfg_apply 대입이 마지막이므로 pending=1.
  ap_apply_pending: assert property (
    @(posedge clk) disable iff (!resetn)
      cfg_apply |=> pending
  ) else $fatal(1, "FAIL SVA apply pending");

  // 주기·듀티가 8/0이고 정상 극성이면 출력은 LOW.
  ap_zero_duty: assert property (
    @(posedge clk) disable iff (!resetn)
      (active_enable && !active_polarity &&
       active_duty == 32'd0) |-> !pwm_out
  ) else $fatal(1, "FAIL SVA zero duty");

  // 8/8의 100% 듀티는 정상 극성에서 HIGH.
  ap_full_duty: assert property (
    @(posedge clk) disable iff (!resetn)
      (active_enable && !active_polarity &&
       active_period == 32'd8 &&
       active_duty == 32'd8) |-> pwm_out
  ) else $fatal(1, "FAIL SVA full duty");

  task automatic apply_duty(input logic [31:0] duty);
    @(negedge clk);
    cfg_duty = duty;
    cfg_apply = 1;
    @(negedge clk);
    cfg_apply = 0;
    repeat (12) @(negedge clk);
    if (active_duty !== duty || pending !== 1'b0)
      $fatal(1, "FAIL APPLY duty=%0d actual=%0d pending=%b",
             duty, active_duty, pending);
    checks++;
  endtask

  initial begin
    #2000;
    $fatal(1, "FAIL GLOBAL_TIMEOUT");
  end
  initial begin
    $dumpfile("ch11_pwm_sva.vcd");
    $dumpvars(0, tb_pwm_sva);
    repeat (3) @(negedge clk);
    resetn = 1;
    apply_duty(32'd0);
    apply_duty(32'd8);
    apply_duty(32'd4);
    // 클록 사이에서 LOW 리셋을 걸면 PWM 출력은 즉시 차단된다.
    @(negedge clk);
    resetn = 0;
    #1;
    if (pwm_out !== 1'b0)
      $fatal(1, "FAIL RESET_GATE");
    repeat (2) @(negedge clk);
    resetn = 1;
    apply_duty(32'd2);
    $display("PASS CH11 SVA checks=%0d", checks);
    $finish;
  end
endmodule

052교시 ② · 실행과 예상 출력 (90~105분)

실행 스크립트는 SVA를 지원하는 xrun(엑스런, 시뮬레이터)이 설치된 환경에서만 실행하도록 작성했습니다. 첫 인자는 읽기 전용 원본 pwm_core.v 경로입니다. 도구가 없으면 NOT_RUN으로 종료합니다.

tb/ch11/run_ch11.sh · 전체 코드 · 시뮬레이션 NOT_RUN
#!/usr/bin/env bash
# 제11장: 원본 RTL은 외부 저장소에서 읽기 전용으로 준비한다.
set -euo pipefail
RTL="${1:-}"
if [[ -z "$RTL" || ! -f "$RTL" ]]; then
  echo "NOT_RUN: pwm_core.v 경로를 첫 인자로 지정하세요" >&2
  exit 2
fi
if ! command -v xrun >/dev/null 2>&1; then
  echo "NOT_RUN: SVA 지원 xrun 시뮬레이터가 없습니다" >&2
  exit 2
fi
mkdir -p out/ch11
cd out/ch11
xrun -64bit -sv -assert -access +r "$RTL" ../../tb/ch11/tb_pwm_sva.sv -R -l ch11.log

예상 출력 — 실제 실행 결과가 아님

정상 실행 예상 로그
PASS CH11 SVA checks=4

속성 위반이 있으면 FAIL SVA ... 또는 FAIL APPLY ...가 출력되고 비정상 종료해야 합니다. 시뮬레이터 옵션·라이선스·SVA 지원 범위에 따라 실행 가능 여부가 달라집니다.

062교시 ③ · 핵심 코드 풀이와 장애 분석 (105~120분)

ap_apply_pending은 수락 이벤트와 다음 클록 상태를 연결하는 시간적 속성입니다. ap_zero_duty와 ap_full_duty는 출력과 설정 상태의 관계를 같은 클록에 검사합니다. apply_duty()는 각 설정 후 12클록을 기다려 실제 적용 결과를 확인하므로, SVA와 절차적 검사를 함께 사용합니다.

현상점검
속성 구문 오류시뮬레이터의 SVA 지원·컴파일 옵션 확인
apply pending 실패입력 구동 에지, 리셋, 비차단 대입의 샘플링 시점 확인
듀티 적용 실패cfg_apply 1클록 펄스 및 주기 경계 확인
실행 불가도구가 없으면 PASS가 아닌 NOT_RUN 기록
