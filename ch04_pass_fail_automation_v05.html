제04장 · PASS/FAIL 자동 판정

PWM 출력과 독립 기대값을 비교하는 자동 판정 테스트벤치

6부 · 24장자동 판정기존 RTL 재사용

00개요 · 관찰에서 자동 판정으로

제03장에서는 PWM(Pulse Width Modulation, 펄스폭 변조)의 출력 HIGH 개수를 셌습니다. 이제 기대값과 실제값을 자동으로 비교하여 정상과 오류를 구분합니다. 사람이 파형을 일일이 확인하지 않아도 테스트벤치가 검사 결과를 판정하는 구조입니다.

선행 설계 학습안내서: 제2부 사용자 AXI IP와 주변장치(amd_soc_p2), 04.2장 「RTL · AXI 풀이」 02절 「설정 Shadow와 출력 Active를 분리」, 06절 「독립 PWM Core 전체」. 파일은 pwm_core.v입니다. 이 장은 AXI 래퍼나 보드 전체가 아닌 PWM 코어의 단위 검증을 수행합니다.

01원본 RTL · 검증 대상

pwm_core는 설정값을 Shadow에 보관한 후 현재 주기가 끝날 때 Active에 반영합니다. 정상 극성에서 카운터가 Active 듀티보다 작으면 출력이 HIGH입니다. TB에서는 초기 주기를 8클록으로 지정하고 원본 자체는 수정하지 않습니다.

reference_rtl/pwm_core.v · Verilog
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

이 모듈은 추가 사용자 RTL 없이 독립적으로 컴파일할 수 있습니다.

02검증 구조와 독립 기대값

기대 HIGH 개수는 입력 듀티 step에서 가져옵니다. 실제 DUT의 active_duty나 내부 counter로 기대값을 만들지 않습니다. 그렇지 않으면 회로가 잘못된 설정을 반영했을 때 기대값까지 잘못 바뀌어 오류를 놓칠 수 있습니다.

입력 듀티정상 HIGH 표본정상 LOW 표본듀티비
0080%
22625%
44450%
66275%
880100%

정상 극성·출력 활성·고정 주기 8이라는 조건에 한정합니다. 총 HIGH 개수만 같고 순서가 뒤바뀌는 오류는 이 검사만으로 검출할 수 없습니다. 이후 장에서 시간적 속성과 경계조건 검사를 확장합니다.

034상태 비교와 오류 처리

구문동작
== / !=비교 결과가 X가 될 수 있음
=== / !==0·1·X·Z를 명시적으로 비교. 결과는 0 또는 1
$error오류 메시지를 남김. 도구 설정에 따라 실행이 중단될 수도 있음
$fatal(1,...)치명적 오류를 보고하고 시뮬레이션 종료
$finish시뮬레이션 종료. 자체적으로 정답 검증을 의미하지 않음

예를 들어 정상 출력의 기대값이 1일 때 실제가 X라면 actual !== expected는 참입니다. 기대값까지 X로 만들면 X와 X의 일치를 정상으로 오해할 수 있으므로 기대값은 명확히 정의합니다.

SystemVerilog · 실제 TB 비교 구문
checks = checks + 1;
if (actual !== expected) begin
    errors = errors + 1;
    $error("MISMATCH t=%0d ns actual=%b expected=%b",
        $time, actual, expected);
end

출력의 X/Z는 HIGH 개수에 포함하지 않고 별도 오류로 기록합니다. 이 검사에서 HIGH 개수 비교가 맞더라도 X/Z가 있으면 최종 PASS가 나오지 않습니다.

04테스트벤치 전체 코드

입력 자극, 적용 완료 대기, 출력 관찰, 비교와 종료 처리를 하나의 TB로 연결합니다. 클록은 10ns 주기이며 하강 에지에서 입력을 바꾸고 안정된 출력도 하강 에지에서 관찰합니다.

tb/ch04/tb_pwm_pass_fail.sv · SystemVerilog
`timescale 1ns/1ps
// CH04: 기존 pwm_core의 PASS/FAIL 자동 판정 테스트벤치.
module tb_pwm_pass_fail;
    reg clk = 1'b0;
    reg resetn = 1'b0;
    reg cfg_apply = 1'b0;
    reg [31:0] cfg_period = 32'd8;
    reg [31:0] cfg_duty = 32'd0;
    reg cfg_enable = 1'b1;
    reg cfg_polarity = 1'b0;
    wire pwm_out, pending, active_enable, active_polarity;
    wire [31:0] active_period, active_duty;
    integer checks = 0, errors = 0, step;

    // 원본 RTL의 13개 포트를 동일한 이름으로 연결.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk(clk), .resetn(resetn),
        .cfg_apply(cfg_apply), .cfg_period(cfg_period),
        .cfg_duty(cfg_duty), .cfg_enable(cfg_enable),
        .cfg_polarity(cfg_polarity), .pwm_out(pwm_out),
        .pending(pending), .active_period(active_period),
        .active_duty(active_duty), .active_enable(active_enable),
        .active_polarity(active_polarity)
    );
    always #5 clk = ~clk; // 10ns 주기

    // (추가) X/Z까지 검사하는 4상태 비교.
    task automatic check_bit(input reg actual, input reg expected);
        begin
            checks = checks + 1;
            if (actual !== expected) begin
                errors = errors + 1;
                $error("MISMATCH t=%0d ns actual=%b expected=%b",
                    $time, actual, expected);
            end
        end
    endtask

    // (추가) 설정 요청 뒤 Shadow 수락과 Active 반영을 모두 기다림.
    task automatic apply_duty(input [31:0] requested);
        begin
            @(negedge clk);
            cfg_duty = requested;
            cfg_apply = 1'b1;
            @(negedge clk);
            cfg_apply = 1'b0;
            wait (pending === 1'b1);
            wait (pending === 1'b0);
            #1; // NBA 반영 후 안정된 값 검사
            checks = checks + 1;
            if (active_duty !== requested) begin
                errors = errors + 1;
                $error("ACTIVE_DUTY expected=%0d actual=%0d",
                    requested, active_duty);
            end
            $display("APPLIED duty=%0d t=%0d ns", requested, $time);
        end
    endtask

    // (추가) 내부 counter를 참조하지 않는 독립 기준값.
    task automatic check_period(input integer duty_ticks);
        integer sample, high_count;
        begin
            high_count = 0;
            for (sample = 0; sample < 8; sample = sample + 1) begin
                @(negedge clk);
                if (pwm_out === 1'b1)
                    high_count = high_count + 1;
                if ((pwm_out !== 1'b0) && (pwm_out !== 1'b1)) begin
                    errors = errors + 1;
                    $error("UNKNOWN_PWM sample=%0d pwm=%b",
                        sample, pwm_out);
                end
            end
            checks = checks + 1;
            if (high_count !== duty_ticks) begin
                errors = errors + 1;
                $error("HIGH_COUNT duty=%0d expected=%0d actual=%0d",
                    duty_ticks, duty_ticks, high_count);
            end
            $display("CHECK duty=%0d high=%0d/8 expected=%0d/8",
                duty_ticks, high_count, duty_ticks);
        end
    endtask

`ifdef VCD
    // (변경) Icarus 실행에서만 VCD 기록을 사용한다.
    initial begin
        $dumpfile("ch04_pwm_pass_fail.vcd");
        $dumpvars(0, tb_pwm_pass_fail);
    end
`endif
    initial begin
        #2000;
        $fatal(1, "TIMEOUT: pending 적용 완료 대기 초과");
    end
    initial begin
        $display("=== CH04 PWM SELF-CHECK START ===");
        repeat (2) @(negedge clk);
        check_bit(pwm_out, 1'b0);
        resetn = 1'b1;
        for (step = 0; step <= 8; step = step + 2) begin
            apply_duty(step);
            check_period(step);
        end
        // (추가) 비교 누락을 정상 종료로 처리하지 않는다.
        if (checks != 11)
            $fatal(1, "FAIL COUNT checks=%0d expected=11", checks);
        if (errors == 0) begin
            $display("PASS checks=%0d errors=0", checks);
            $finish;
        end else begin
            $fatal(1, "FAIL checks=%0d errors=%0d", checks, errors);
        end
    end
endmodule

핵심 코드 풀이

실제 코드역할
check_bit()리셋 중 출력 LOW인지 1회 비교
apply_duty()한 클록 동안 요청, pending 1→0 대기, #1 뒤 Active 듀티 비교
check_period()하강 에지 8회 관찰, X/Z 오류 기록, HIGH 개수 비교
for (step = 0; ...)0·2·4·6·8 다섯 설정을 순차 시험
checks리셋 1 + Active 듀티 5 + HIGH 개수 5 → 11회
errors오류 건수. X/Z 표본 오류는 별도 누적하며 checks를 증가시키지는 않음
#2000; $fatal(...)pending 대기가 끝나지 않을 때 무한 시뮬레이션 방지

06예상 출력 · 정답 및 반례

정상 RTL의 시간 계약으로 계산한 예상 출력입니다. 실제 실행 로그와 비교합니다.

첫 요청은 30ns, 반영 에지는 95ns, 로그는 96ns입니다. 첫 8개 표본은 100~170ns에 읽습니다. 두 번째 요청은 180ns입니다(첫 요청과의 간격은 150ns). 이후 적용 관찰 시각은 160ns씩 증가합니다.

실제 관측기대판정
듀티 4, HIGH 4HIGH 4개수 일치
듀티 4, HIGH 3HIGH 4HIGH_COUNT 오류
듀티 4, HIGH 4 + X/Z 표본모든 표본 0/1UNKNOWN_PWM 오류

반례는 검사의 의미를 보여주는 가상 입력 결과이며 실제 오류 주입 실행 기록은 아닙니다. 최종 PASS는 이 장의 11개 비교와 표본 미정값 검사 범위에만 해당합니다.
