제02장 · Clock·Reset·이벤트

기존 PWM RTL로 클록·리셋·설정 반영의 실제 시간 관계를 읽는 순차회로 검증

6부 · 24장클록·리셋·시간 경계기존 RTL 재사용

00개요 · 클록에 따라 상태가 변하는 회로

제1장의 UART Echo는 입력을 그대로 출력하는 조합회로였습니다. 제2장은 PWM(Pulse Width Modulation, 펄스폭 변조) 회로를 통해 클록에 맞춰 내부 값이 바뀌는 순차회로를 검증합니다. 설정값을 입력한 순간과 실제 출력에 반영되는 순간이 왜 다른지 확인합니다.

선행 설계 학습안내서: 제2부 사용자 AXI IP와 주변장치(amd_soc_p2), 04.2장 「RTL · AXI 풀이」 02절 「설정 Shadow와 출력 Active를 분리」 및 06절 「독립 PWM Core 전체」. 파일: pwm_core.v. 이 장은 AXI IP 전체가 아니라 독립 PWM 코어만 검증합니다.

01원본 RTL · pwm_core

다음은 실제 설계 학습안내서의 독립 코어와 동일한 전체 코드입니다. 이 회로는 주기와 듀티를 즉시 바꾸지 않고 먼저 Shadow(섀도, 임시 설정 레지스터)에 보관합니다. Active(액티브, 현재 적용 레지스터)는 현재 주기를 끝낸 다음 바뀌므로 한 주기 도중 출력 폭이 불필요하게 변하지 않습니다.

reference_rtl/pwm_core.v · Verilog
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

전체 코드를 reference_rtl/pwm_core.v에 저장합니다. 이 모듈은 추가 사용자 RTL 없이 독립적으로 컴파일할 수 있습니다.

그림의 네 상자는 별도의 RTL 모듈이 아니라 pwm_core 내부 기능을 구분한 것입니다. cfg_apply를 상승 에지에서 읽으면 Shadow와 pending을 갱신하고, boundary가 참인 상승 에지에서 기존 Shadow 값을 Active에 반영합니다. pending과 cfg_apply가 경계에서 동시에 참이면 기존 요청은 반영되고 새 요청은 다음 경계에 남습니다. 이번 TB는 이 동시 요청까지 시험하지 않습니다.

02입출력과 시간 계약

구분실제 신호역할
입력 1비트clk, resetn, cfg_apply클록, 활성 LOW 리셋, 설정 요청
입력 32비트cfg_period, cfg_duty주기·듀티의 클록 수
입력 1비트cfg_enable, cfg_polarity출력 허용·극성
출력 1비트pwm_out, pendingPWM 및 설정 대기
출력 32비트active_period, active_duty현재 적용 주기·듀티
출력 1비트active_enable, active_polarity현재 적용 허용·극성

TB 인스턴스에서만 RESET_PERIOD=8을 지정합니다. 클록 주기는 10ns, PWM 주기는 8×10ns=80ns입니다. 정상 극성에서 3클록 HIGH, 5클록 LOW이므로 듀티비는 37.5%입니다. RTL 내부 리셋은 always @(posedge clk)에 있으므로 동기식이지만, assign pwm_out에 직접 연결된 resetn은 조합 출력도 차단합니다.

시각TB 동작 또는 DUT 사건
0~20nsresetn=0, 5ns와 15ns 상승 에지에서 초기화
20ns하강 에지에서 resetn=1
30nscfg_apply=1
35ns상승 에지에서 Shadow 저장, pending=1
40nscfg_apply=0
95ns기존 주기 종료: counter=0, active_duty=3, pending=0
125nscounter=3, pwm_out=0
175ns다음 주기: counter=0, pwm_out=1

03테스트벤치 전체 코드

TB(Testbench, 테스트벤치)는 하강 에지에 입력을 바꾸고, DUT(Device Under Test, 검증 대상 회로)의 상승 에지로부터 1ns 뒤에 값을 읽습니다. 이렇게 하면 같은 시각의 비차단 대입 갱신 이전 값을 읽는 실수를 줄일 수 있습니다.

tb/ch02/tb_pwm_clock_reset.sv · SystemVerilog
`timescale 1ns/1ps
// 제02장: 기존 pwm_core의 클록·리셋·주기 경계를 관찰한다.
// DUT 원본은 변경하지 않는다. 자동 PASS/FAIL 판정은 제04장에서 다룬다.
module tb_pwm_clock_reset;
    reg         clk;
    reg         resetn;
    reg         cfg_apply;
    reg  [31:0] cfg_period;
    reg  [31:0] cfg_duty;
    reg         cfg_enable;
    reg         cfg_polarity;

    wire        pwm_out;
    wire        pending;
    wire [31:0] active_period;
    wire [31:0] active_duty;
    wire        active_enable;
    wire        active_polarity;

    // (추가) 실제 DUT의 모든 포트를 원래 이름으로 연결한다.
    // RESET_PERIOD만 교육용으로 8클록으로 축소한다.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk             (clk),
        .resetn          (resetn),
        .cfg_apply       (cfg_apply),
        .cfg_period      (cfg_period),
        .cfg_duty        (cfg_duty),
        .cfg_enable      (cfg_enable),
        .cfg_polarity    (cfg_polarity),
        .pwm_out         (pwm_out),
        .pending         (pending),
        .active_period   (active_period),
        .active_duty     (active_duty),
        .active_enable   (active_enable),
        .active_polarity (active_polarity)
    );

    // 5ns마다 반전하므로 클록의 전체 주기는 10ns이다.
    initial clk = 1'b0;
    always #5 clk = ~clk;

`ifdef VCD
    // (변경) Icarus 실행에서만 VCD 시스템 태스크를 활성화한다.
    initial begin
        $dumpfile("ch02_pwm_clock_reset.vcd");
        $dumpvars(0, tb_pwm_clock_reset);
    end
`endif

    // (변경) %0d로 $time의 현재 모듈 시간 단위(ns)를 그대로 표시한다.
    // 상승 에지 이후 1ns를 기다려 비차단 대입 결과를 읽는다.
    // #1은 하드웨어 지연이 아니라 테스트벤치 관찰용 시간 이동이다.
    always @(posedge clk) begin
        #1;
        $display("POS t=%0d ns rst=%b apply=%b pending=%b period=%0d duty=%0d en=%b pwm=%b",
            $time, resetn, cfg_apply, pending,
            active_period, active_duty, active_enable, pwm_out);
    end

    initial begin
        // 0~20ns: 활성 LOW 리셋을 유지한다.
        resetn       = 1'b0;
        cfg_apply    = 1'b0;
        cfg_period   = 32'd8;
        cfg_duty     = 32'd3;
        cfg_enable   = 1'b1;
        cfg_polarity = 1'b0;
        $display("=== CH02 PWM CLOCK / RESET START ===");

        // t=20ns 하강 에지에 리셋 해제.
        @(negedge clk);
        @(negedge clk);
        resetn = 1'b1;

        // t=30~40ns 설정 요청, t=35ns Shadow 저장.
        @(negedge clk);
        cfg_apply = 1'b1;
        @(negedge clk);
        cfg_apply = 1'b0;

        // t=190ns: PWM이 HIGH인 구간에서 리셋 재인가.
        repeat (15) @(negedge clk);
        resetn = 1'b0;
        #1;
        // 리셋 입력만 LOW로 바뀌어도 조합 출력은 즉시 LOW가 된다.
        $display("EVENT t=%0d ns resetn=%b active_duty=%0d pwm=%b",
            $time, resetn, active_duty, pwm_out);

        // t=195ns 순차 레지스터 리셋, t=200ns 리셋 해제.
        @(negedge clk);
        resetn = 1'b1;

        repeat (4) @(negedge clk);
        $display("=== CH02 END: OBSERVATION ONLY ===");
        $finish;
    end
endmodule

위 파일을 tb/ch02/tb_pwm_clock_reset.sv로 저장합니다.

05예상 로그와 파형

다음은 원본 RTL의 논리와 TB 자극 순서를 대조하여 얻은 기대값입니다. 실제 시뮬레이터 출력에서 해당 행을 찾아 비교합니다.

예상 콘솔 출력 · 주요 관찰 시점
POS t=26 ns rst=1 apply=0 pending=0 period=8 duty=0 en=0 pwm=0
POS t=36 ns rst=1 apply=1 pending=1 period=8 duty=0 en=0 pwm=0
POS t=96 ns rst=1 apply=0 pending=0 period=8 duty=3 en=1 pwm=1
POS t=126 ns rst=1 apply=0 pending=0 period=8 duty=3 en=1 pwm=0
POS t=176 ns rst=1 apply=0 pending=0 period=8 duty=3 en=1 pwm=1
EVENT t=191 ns resetn=0 active_duty=3 pwm=0
POS t=196 ns rst=0 apply=0 pending=0 period=8 duty=0 en=0 pwm=0

36ns에는 설정 요청이 저장되었지만 Active는 0입니다. 96ns에 Active가 3으로 바뀌고 출력이 HIGH가 됩니다. 125ns부터 LOW가 되는 이유는 비교식 counter < active_duty가 거짓이기 때문입니다.

190ns에 resetn이 LOW가 되면 pwm_out은 즉시 LOW로 바뀝니다. 그러나 191ns의 active_duty는 아직 3입니다. 195ns 상승 에지가 지나고 196ns에 읽으면 0이 됩니다. 파형이 변하는 시각과 TB가 값을 읽는 시각은 서로 다릅니다.

06핵심 코드 풀이

구문동작과 의미
always #5 clk = ~clk;5ns마다 반전하는 클록을 생성합니다. 전체 주기는 10ns입니다.
@(negedge clk)클록 하강 에지까지 기다립니다. 상승 에지보다 앞서 DUT 입력을 안정시킵니다.
@(posedge clk)클록 상승 에지를 기다립니다. DUT 순차 논리의 갱신 기준입니다.
#1;상승 에지 뒤 1ns를 기다려 비차단 대입(NBA, Nonblocking Assignment)의 갱신 결과를 관찰합니다. DUT 지연은 아닙니다.
repeat (15) @(negedge clk);40ns 이후 하강 에지를 15번 기다려 190ns에 도달합니다.
$display(... %0d ... $time ...)현재 모듈의 시간 단위 1ns 기준 정수 시각을 출력합니다.
$finish;관찰을 종료합니다. 자동 정답 판정은 수행하지 않습니다.
