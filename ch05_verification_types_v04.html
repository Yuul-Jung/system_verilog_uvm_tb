제05장 · 검증 자료형과 타입

UART Echo의 검증 데이터를 자료형과 구조체로 표현

6부 · 24장4상태·2상태 · 구조체기존 RTL 재사용

00개요 · 검증 데이터에 의미를 부여한다

제1부에서는 입력 자극을 반복하고 기대값과 실제값을 비교했습니다. 제2부에서는 SystemVerilog(시스템베릴로그, 하드웨어 설계·검증 언어)의 자료형을 이용해 복잡해지는 검증 데이터를 체계적으로 관리합니다. 제05장은 데이터를 표현하고, 사례에 이름을 붙이고, 관련 신호를 하나로 묶는 기초입니다.

선행 설계 학습안내서: Basys3 소형 NPU 실습(amd_soc_npu) 제1장 UART 계산기 03절 「서브젝트 1-1 · UART 에코」, uart_echo_controller.v. 이 장은 에코 제어기만 검증합니다.

01검증 대상 · 원본 RTL과 포트 계약

이 회로는 수신 측 데이터와 유효 신호를 송신 측으로 전달하고, 송신 측 준비 신호를 수신 측으로 되돌립니다. 클록·리셋·저장 레지스터가 없는 조합회로입니다. 자료형을 새로 정의하는 곳은 TB(Testbench, 테스트벤치)이며 원본 RTL을 변경하지 않습니다.

reference_rtl/uart_echo_controller.v · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule
입력출력폭·동작
rx_data_itx_data_o8비트 그대로 전달
rx_valid_itx_valid_o1비트 유효 신호 전달
tx_ready_irx_ready_o1비트 준비 신호 역방향 전달

유효와 준비가 모두 1이면 일반적인 클록 기반 스트림에서는 샘플링 에지에 전송이 수락됩니다. 이 DUT에는 클록이 없으므로 이번 TB는 전송 횟수가 아닌 세 조합 연결을 확인합니다. 각 사례는 독립 자극이며, 대기 상태에서 다음 입력으로 바꾸는 것은 완전한 Ready/Valid 프로토콜 시험이 아닙니다.

02logic과 bit · 미정값을 보존하는 이유

logic(로직, 4상태 변수형)은 0, 1, X(미정), Z(고임피던스)를 표현합니다. bit(비트, 2상태 변수형)는 0과 1만 표현하고 X/Z를 대입하면 해당 비트를 0으로 변환합니다. 하드웨어의 미정 상태를 발견해야 하는 검증에서는 이러한 차이가 중요합니다.

입력값logic [7:0]bit [7:0]
8'h410100000101000001
8'hx5xxxx010100000101
8'hz5zzzz010100000101 (설명용 추가 예)

실제 TB는 8'hx5를 DUT에 입력하고 four_state_copy와 compact_copy에 복사합니다. 4상태 비교 연산자 !==를 사용하면 X가 예상대로 보존되었는지 확인할 수 있습니다. 이 예제에서 X 일치는 의도적인 검사이며 정상 유효 데이터가 X인 것을 허용한다는 의미는 아닙니다.

03typedef·enum · 검증 사례의 이름

typedef(타입디프, 자료형에 이름을 부여하는 선언)는 정의한 타입을 여러 선언에서 재사용하게 합니다. enum(이넘, 열거형)은 특정 값에 의미 있는 이름을 붙입니다.

SystemVerilog · case_kind_t
typedef enum logic [1:0] {
    CASE_IDLE  = 2'd0,
    CASE_SEND  = 2'd1,
    CASE_STALL = 2'd2,
    CASE_XDATA = 2'd3
} case_kind_t;
사례datavalidready관찰 의미
CASE_IDLE (0)0001유효하지 않은 입력
CASE_SEND (1)4111정상 데이터 전달
CASE_STALL (2)4210준비 신호 LOW의 조합 출력
CASE_XDATA (3)x511의도적인 X 전달

kind는 TB가 시험하고 있는 사례를 기록합니다. DUT 내부에 존재하는 FSM(유한상태머신) 상태가 아닙니다.

04packed struct · 10비트 데이터 표현

struct packed(스트럭트 팩트, 비트 단위로 연속 배치된 구조체)는 여러 필드를 하나의 벡터처럼 묶습니다. 선언 순서가 상위에서 하위 비트로 이어집니다.

SystemVerilog · uart_sample_t
typedef struct packed {
    logic [7:0] data;
    logic       valid;
    logic       ready;
} uart_sample_t;

run_case(CASE_SEND, {8'h41, 1'b1, 1'b1});에서 중괄호는 Concatenation(컨캐터네이션, 비트 연결)입니다. 8+1+1의 10비트를 uart_sample_t 인자로 전달하면 data, valid, ready로 구분하여 읽습니다. 구조체의 필드 대입 패턴 '{...}도 SystemVerilog 문법이지만, 여기서는 도구별 지원 차이를 줄이기 위해 같은 비트 폭의 연결 표현을 사용합니다.

05전체 테스트벤치 · 자료형을 사용한 검증

run_case()는 사례 이름과 구조체를 받아 세 DUT 입력에 대입하고 1ns 뒤 실제 출력과 기대값을 비교합니다. 이 1ns는 TB 관찰을 위한 시간이며 하드웨어 지연이 아닙니다.

tb/ch05/tb_uart_types.sv · SystemVerilog
`timescale 1ns/1ps
// 제05장: SystemVerilog 자료형으로 UART Echo의 입력·출력을 모델링한다.
// 기존 uart_echo_controller는 수정하지 않는다.
// DUT는 조합 논리이므로 클록·리셋·지연된 UART 직렬 비트는 없다.
module tb_uart_types;
    // (추가) 4상태 logic: X/Z를 포함한 신호 검증에 사용한다.
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    logic       tx_ready_i;
    wire        rx_ready_o;
    wire [7:0]  tx_data_o;
    wire        tx_valid_o;

    // (추가) typedef + enum: 검증 단계 이름을 숫자 대신 타입으로 지정한다.
    typedef enum logic [1:0] {
        CASE_IDLE  = 2'd0,
        CASE_SEND  = 2'd1,
        CASE_STALL = 2'd2,
        CASE_XDATA = 2'd3
    } case_kind_t;

    // (추가) packed struct: 한 번의 스트림 입력을 하나의 값으로 묶는다.
    typedef struct packed {
        logic [7:0] data;
        logic       valid;
        logic       ready;
    } uart_sample_t;

    // (추가) bit는 2상태 값만 저장한다. X/Z를 저장하면 0으로 변환된다.
    bit [7:0] compact_copy;
    logic [7:0] four_state_copy;
    uart_sample_t sample;
    case_kind_t  kind;
    integer checks = 0;
    integer failures = 0;

    // 실제 원본 RTL의 여섯 포트를 이름 그대로 연결한다.
    uart_echo_controller dut (
        .rx_data_i(rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

    // (추가) 입력 적용 후 조합 회로가 안정될 시간을 1ns 제공한다.
    // 출력은 rx_ready_o=tx_ready_i, tx_valid_o=rx_valid_i,
    // tx_data_o=rx_data_i의 관계를 그대로 만족해야 한다.
    task automatic run_case(
        input case_kind_t next_kind,
        input uart_sample_t next_sample
    );
        begin
            kind = next_kind;
            sample = next_sample;
            rx_data_i  = sample.data;
            rx_valid_i = sample.valid;
            tx_ready_i = sample.ready;
            #1;

            checks = checks + 1;
            if ((rx_ready_o !== sample.ready) ||
                (tx_valid_o !== sample.valid) ||
                (tx_data_o !== sample.data)) begin
                failures = failures + 1;
                $error("MISMATCH kind=%0d data=%h valid=%b ready=%b",
                    kind, tx_data_o, tx_valid_o, rx_ready_o);
            end else begin
                $display("MATCH kind=%0d data=%h valid=%b ready=%b",
                    kind, tx_data_o, tx_valid_o, rx_ready_o);
            end
        end
    endtask

`ifdef VCD
    // (변경) Icarus 실행에서 VCD 파형을 기록한다.
    initial begin
        $dumpfile("ch05_uart_types.vcd");
        $dumpvars(0, tb_uart_types);
    end
`endif

    initial begin
        $display("=== CH05 SYSTEMVERILOG TYPES START ===");

        // 입력 데이터가 있어도 valid=0이면 전송은 유효하지 않다.
        // (변경) packed struct와 같은 10비트의 연결 표현을 사용한다.
        // data[9:2], valid[1], ready[0] 순서로 구성된다.
        run_case(CASE_IDLE, {8'h00, 1'b0, 1'b1});

        // valid=1, ready=1이면 전송 가능 상태이다. 실제 수락 이벤트를 측정하지 않는다.
        run_case(CASE_SEND, {8'h41, 1'b1, 1'b1});

        // ready=0이면 이 입력 사례에서는 출력 valid와 data가 그대로 전달된다.
        run_case(CASE_STALL, {8'h42, 1'b1, 1'b0});

        // logic과 원본 조합 DUT는 X를 보존하는지 확인할 수 있다.
        run_case(CASE_XDATA, {8'hx5, 1'b1, 1'b1});
        four_state_copy = rx_data_i;
        compact_copy = rx_data_i;

        checks = checks + 1;
        if (four_state_copy !== 8'hx5) begin
            failures = failures + 1;
            $error("4STATE_COPY_MISMATCH");
        end

        checks = checks + 1;
        if (compact_copy !== 8'h05) begin
            failures = failures + 1;
            $error("2STATE_CONVERSION_MISMATCH");
        end

        $display("TYPE logic=%h bit=%h", four_state_copy, compact_copy);
        // (추가) 입력 사례 또는 자료형 비교 누락 방지.
        if (checks != 6)
            $fatal(1, "FAIL COUNT checks=%0d expected=6", checks);
        if (failures == 0) begin
            $display("PASS checks=%0d failures=0", checks);
            $finish;
        end else begin
            $fatal(1, "FAIL checks=%0d failures=%0d", checks, failures);
        end
    end

    initial begin
        #100;
        $fatal(1, "TIMEOUT: testbench did not finish");
    end
endmodule
코드역할
kind = next_kind시험 사례 이름 기록
sample = next_sample10비트 입력 묶음을 복사
rx_data_i = sample.data 등세 입력 포트에 필드별 대입
#1조합 출력 안정화 후 관찰
!==와 ||세 포트 중 하나라도 기대값과 다르면 사례 실패
four_state_copyX를 그대로 보존
compact_copyX를 0으로 변환
checks · failures사례 검사 4회 + 타입 검사 2회 집계

세 포트 비교는 각 사례당 하나의 검사로 집계합니다. 4개 사례에서 총 12개의 포트 조건을 비교하지만 checks는 4만 증가하고, 타입 검사 두 개를 더해 6이 됩니다.

07예상 결과와 오류 분석

최종 PASS 전에 네 입력 사례와 두 자료형 비교가 모두 수행되어 checks가 6인지 확인합니다.

다음은 원본 연결식과 4상태·2상태 변환 규칙으로 도출한 예상 출력입니다. 실제 시뮬레이터 실행 결과와 대조합니다.

예상 콘솔 출력 · 주요 행
=== CH05 SYSTEMVERILOG TYPES START ===
MATCH kind=0 data=00 valid=0 ready=1
MATCH kind=1 data=41 valid=1 ready=1
MATCH kind=2 data=42 valid=1 ready=0
MATCH kind=3 data=x5 valid=1 ready=1
TYPE logic=x5 bit=05
PASS checks=6 failures=0
시각관찰 결과
1nsCASE_IDLE 비교
2nsCASE_SEND 비교
3nsCASE_STALL 비교
4nsCASE_XDATA 및 두 타입 변환 비교 후 종료
오류점검
MISMATCH세 포트의 비트 폭·방향 및 sample 필드
4STATE_COPY_MISMATCHlogic을 bit로 먼저 변환했는지 확인
2STATE_CONVERSION_MISMATCHcompact_copy의 bit 선언 확인
TIMEOUTTB 종료 및 실행 상태 확인
컴파일 오류SystemVerilog 옵션과 설치 버전 확인
