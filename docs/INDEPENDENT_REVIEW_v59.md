## 새로 발견한 검증 도구의 제한

### V59-01 (중간): 증거 무결성 검사와 증거 완전성 검사 분리 필요
`scripts/collect_evidence.py`의 `verify()`는 manifest에 기재된 파일의 SHA256만 확인한다. 24개 장의 고유 ID·상태·필수 로그·12개 부정 시험 목록이 모두 존재하는지는 확인하지 않는다. 원격 코드의 verify 함수 그대로 임시 Python 환경에서 아래 세 반례 실행 결과를 얻었다.

| 반례 | 현재 종료 코드 | 필요한 판정 |
|---|---:|---|
| chapters=[], sources_sha256={} | 0 | 불완전 증거 거절 |
| 1개 장, status=FAIL, exit_code=1, 빈 로그 목록 | 0 | 실행 결과 승인 거절 |
| chapter=1 중복 24개, 빈 로그 목록 | 0 | 중복·누락 거절 |

해시 무결성 자체와 현재 실제 v59 증거는 위 반례로 무효화되지 않는다. 그러나 이 함수를 전체 검증 승인 게이트로 사용하려면 01~24 고유/연속 ID, 관찰/자동 판정 상태와 종료 코드, 각 장 필수 정상 로그, 12개 부정 시험의 정확한 고유 목록 및 기대 진단, 필수 소스 집합을 검증해야 한다. hash-only 검사를 별도 이름으로 유지하는 방법도 가능하다.

### V59-02 (낮음, 개선 권고): 재수집 경로의 최신성 및 최소 공개
collect_evidence.py는 장별 최신 run*을 mtime으로 선택하고 fixed-directory 로그를 재사용한다. 새 실행에 속한 로그 경로를 명시하거나 실행 전후 생성 시각/파일 목록을 검증하면 실패 실행에서 과거 로그가 혼입될 가능성을 줄인다. 또한 bash -x는 source된 외부 환경 스크립트의 확장값도 기록할 수 있다. 표본 runner.txt 4개에서 일반 비밀 변수 패턴 및 개인 홈/임시 경로는 발견되지 않았으나 전수 비밀 검색은 미검증이다. 실행 명령 중심 최소 추적을 권장한다.

### V59-03 (범위 제한): 실제 환경 재현
현재 독립 환경에서 GitHub 직접 git clone은 DNS 실패, xvlog/iverilog/verilator는 없음. 공개 Pages URL도 조회 도구 접근 오류. Codex의 103개 HTTP 200·해시 확인 기록은 존재하며 실제 사이트 장애로 판단하지 않는다. 독립 시뮬레이션 및 실제 브라우저/Pages 재현은 NOT_RUN. 원격 Actions, 합성, 보드 검증 및 현행 외부 NPU 엔진에 대한 새 TB는 기존 범위 밖.
