01원본 RTL과 검증 구조

DUT(디유티, 검증 대상 회로)는 데이터와 유효 신호를 전달하고 준비 신호를 역방향으로 전달하는 조합 회로입니다. UART 직렬 송수신기 전체가 아니며 클록과 리셋, 저장소가 없습니다.

reference_rtl/uart_echo_controller.v · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule
입력출력
rx_data_i[7:0]tx_data_o[7:0]
rx_valid_itx_valid_o
tx_ready_irx_ready_o

02Class와 new · 핸들과 객체

Class(클래스, 객체의 자료와 동작을 정의하는 형식)는 한 입력 사례를 data·valid·ready로 묶습니다. uart_txn normal;은 객체를 참조할 핸들 선언이고 normal = new();를 실행하면 생성자가 초기값을 설정합니다. 선언만으로 DUT 입력을 구동하지 않습니다.

SystemVerilog · 실제 클래스 선언의 일부
class uart_txn;
    rand bit [7:0] data;
    rand bit       valid;
    rand bit       ready;
    // 제약 및 describe()는 전체 코드 참조
    function new();
        data = 8'h41;
        valid = 1'b1;
        ready = 1'b1;
    endfunction
endclass

객체 핸들을 다른 변수에 대입하거나 태스크 인자로 전달해도 객체의 내용이 자동 복제되는 것은 아닙니다. 이번 검사는 객체를 읽기만 하며 실행 중 별도의 동시 변경이 없습니다. 2상태 bit는 정상 0/1 입력을 생성하는 데 쓰고, DUT 입력 관찰용 logic과 출력 wire는 4상태를 유지합니다.

03Rand·constraint · 허용 입력 공간

rand(랜드, 무작위 생성 대상 속성)는 randomize() 호출에서 변경할 수 있는 필드를 나타냅니다. constraint(컨스트레인트, 허용 조건)는 생성값의 범위를 제한합니다.

SystemVerilog · 실제 제약
constraint c_printable { data inside {[8'h20:8'h7e]}; }
// 호출 시점의 추가 제약
if (!normal.randomize() with { valid == 0; ready == 1; })
    $fatal(1, "RANDOMIZE_FAIL IDLE");

0x20~0x7E는 출력 가능한 ASCII(아스키, 문자 코드) 95개입니다. 부모 클래스에서는 valid와 ready가 각각 0 또는 1이므로 전체 허용 조합은 95 × 2 × 2 → 380개입니다. IDLE 호출은 valid=0, ready=1을 추가하여 95개 조합으로 제한합니다. 이는 가능한 입력 공간의 크기이지 실제로 95개 또는 380개를 시험했다는 뜻은 아닙니다.

randomize()가 0을 반환하면 실패입니다. 생성 성공 이후에도 실제 값이 제약을 만족하는지 검사합니다. 예를 들어 printable 제약과 data=0을 동시에 강제하면 허용 조합이 없습니다. 일반 필드 직접 대입은 제약을 자동으로 검사하지 않습니다.

04Extends · 상속과 부모 타입 재사용

extends(익스텐즈, 상속)는 부모의 필드·메서드·제약을 자식에서 재사용합니다. 아래 자식 클래스는 출력 가능한 문자 범위를 물려받고 c_stall로 정지 사례를 제한합니다.

SystemVerilog · 실제 자식 클래스
class uart_stall_txn extends uart_txn;
    constraint c_stall { valid == 1'b1; ready == 1'b0; }
endclass
사례datavalidready
DIRECT_A4111
RANDOM_IDLE20~7E01
RANDOM_STALL20~7E10
POLYMORPHIC_STALL직전 자식 객체와 동일10

apply_and_check(input uart_txn tr, ...)는 부모 클래스 핸들 인자를 사용하므로 자식 객체도 전달할 수 있습니다(업캐스팅). 실제 객체의 필드를 읽어 공통 검사를 재사용합니다. 이 예제는 virtual 메서드의 재정의나 동적 디스패치를 구현하지 않습니다. 마지막 사례의 기존 로그 이름은 유지하되, 새로운 난수 생성이나 별도 가상 메서드 시험으로 계산하지 않습니다.

05테스트벤치 전체 코드

부모 객체의 직접 입력 → IDLE 제약 생성 → 자식의 STALL 제약 생성 → 자식 객체 재사용 순서로 네 번 검사합니다. 모든 검사에서 원본 RTL의 세 조합 연결을 확인합니다.

tb/ch08/tb_uart_objects.sv · SystemVerilog
`timescale 1ns/1ps
// 제08장: 원본 UART Echo의 6개 포트를 변경하지 않고 객체 기반 입력을 검증한다.
// class, new, extends, rand, constraint, randomize()를 직접 실습한다.

class uart_txn;
    rand bit [7:0] data;
    rand bit       valid;
    rand bit       ready;

    // (추가) 출력 가능한 ASCII(아스키) 문자 범위로 데이터를 제한한다.
    constraint c_printable { data inside {[8'h20:8'h7e]}; }

    function new();
        data = 8'h41;
        valid = 1'b1;
        ready = 1'b1;
    endfunction

    function string describe();
        return $sformatf("data=%02h valid=%0b ready=%0b",
                         data, valid, ready);
    endfunction
endclass

// (추가) 부모의 데이터 범위 제약을 물려받고 정지 조건을 추가한다.
class uart_stall_txn extends uart_txn;
    constraint c_stall { valid == 1'b1; ready == 1'b0; }
endclass

module tb_uart_objects;
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    wire        rx_ready_o;
    wire [7:0]  tx_data_o;
    wire        tx_valid_o;
    logic       tx_ready_i;

    integer checked = 0;
    uart_txn normal;
    uart_stall_txn stalled;

    // 원본 DUT: 데이터/유효/준비를 그대로 전달하는 조합회로이다.
    uart_echo_controller dut (
        .rx_data_i(rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

    // (추가) 객체의 속성을 DUT 포트에 적용하고 4상태 비교로 확인한다.
    task automatic apply_and_check(input uart_txn tr, input string label_name);
        begin
            rx_data_i  = tr.data;
            rx_valid_i = tr.valid;
            tx_ready_i = tr.ready;
            #1; // 조합 출력이 안정되도록 TB에서만 기다린다. DUT 지연이 아니다.
            if ((tx_data_o !== tr.data) ||
                (tx_valid_o !== tr.valid) ||
                (rx_ready_o !== tr.ready))
                $fatal(1, "FAIL %s expected %s got %02h/%b/%b",
                       label_name, tr.describe(), tx_data_o,
                       tx_valid_o, rx_ready_o);
            checked++;
            $display("PASS %s %s", label_name, tr.describe());
        end
    endtask

    initial begin
        $display("=== CH08 OBJECT / CONSTRAINT START ===");
        normal = new();
        stalled = new();

        // (추가) 부모 객체에 특정 값을 넣어 기준 동작부터 확인한다.
        normal.data = 8'h41;
        normal.valid = 1'b1;
        normal.ready = 1'b1;
        apply_and_check(normal, "DIRECT_A");

        // (추가) 인라인 제약으로 유효한 IDLE 사례를 생성한다.
        if (!normal.randomize() with { valid == 0; ready == 1; })
            $fatal(1, "RANDOMIZE_FAIL IDLE");
        // (추가) 생성 성공뿐 아니라 실제 IDLE 제약 만족 여부도 검사한다.
        if (!(normal.data >= 8'h20 && normal.data <= 8'h7e &&
              normal.valid == 1'b0 && normal.ready == 1'b1))
            $fatal(1, "CONSTRAINT_FAIL IDLE");
        apply_and_check(normal, "RANDOM_IDLE");

        // (추가) 상속된 제약은 데이터 범위를 유지하고 정지를 강제한다.
        if (!stalled.randomize()) $fatal(1, "RANDOMIZE_FAIL STALL");
        if (!(stalled.data >= 8'h20 && stalled.data <= 8'h7e &&
              stalled.valid == 1'b1 && stalled.ready == 1'b0))
            $fatal(1, "CONSTRAINT_FAIL STALL");
        apply_and_check(stalled, "RANDOM_STALL");

        // (추가) 부모 타입 인자로 자식 객체를 전달해 공통 검사 태스크를 재사용한다.
        apply_and_check(stalled, "POLYMORPHIC_STALL");
        if (checked != 4) $fatal(1, "COUNT_FAIL %0d", checked);
        $display("CH08 PASS: %0d cases checked", checked);
        $finish;
    end

    initial begin
        #100;
        $fatal(1, "CH08 TIMEOUT");
    end
endmodule

핵심 코드 풀이

코드역할
new()객체 생성 및 초기 필드 설정
randomize() with이번 호출에만 추가 제약 적용
CONSTRAINT_FAIL IDLE / STALL난수 생성 결과의 범위와 제어값 별도 검사
apply_and_check(tr)객체 필드를 DUT 입력으로 복사
#1조합 출력 안정화 뒤 관찰. DUT 지연 사양 아님
!==출력과 객체의 기대값 비교
checked++정상 비교 사례 수 증가
$fatal제약·출력·횟수·타임아웃 실패 시 종료

제약은 입력 생성 정책이고 apply_and_check()는 DUT 정답 비교입니다. 제약이 정상이라는 사실만으로 출력도 정상이라고 판단하지 않습니다.

07오류 분석과 검증 범위

증상확인 사항
randomize 컴파일 오류설치 버전의 클래스·인라인 제약 지원 및 외부 해결기
RANDOMIZE_FAIL제약 간 모순 또는 해결기 오류
CONSTRAINT_FAIL IDLE / STALL실제 생성값의 범위·valid·ready
FAIL원본 여섯 포트 및 #1 관찰 시점
COUNT_FAIL / TIMEOUT네 번의 검사 완료와 종료 경로

네 번의 비교는 직접 입력 1회, 난수 생성 2회, 자식 객체 재사용 1회입니다. 모든 입력 조합의 검증이나 기능 커버리지 달성을 의미하지 않습니다. 클록 없는 조합 DUT이므로 실제 전송 수락 에지, UART 직렬 프레임 및 FIFO도 검사 범위 밖입니다.
