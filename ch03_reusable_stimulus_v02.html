기존 PWM RTL을 사용하여 task·function·repeat·for·wait를 실무형 검증 코드로 연결하는 2시간 실습

6부 · 24장각 장 2시간 · 1시간씩 분리기존 RTL 재사용

00학습 개요 · 같은 입력을 여러 번 시험하는 이유

제02장에서는 PWM(펄스폭 변조) 코어의 클록과 리셋을 관찰했습니다. 이번 장은 회로를 다시 만들지 않고 입력 자극을 반복해서 만드는 검증 코드를 정리합니다. 같은 일을 다섯 번 복사하는 대신, 작업을 하나의 task(태스크, 시간 흐름을 포함할 수 있는 작업 단위)로 묶고 반복문으로 호출합니다.

시간구성실습 결과
1교시 · 0~60분task·function·repeat·for·wait 문법과 신호 흐름중복을 줄이는 검증 절차 설계
2교시 · 60~120분기존 PWM DUT를 이용한 전체 TB와 파형 확인5개 듀티 설정을 하나의 반복 루프로 관찰

검증 대상 DUT(디유티, 검증 대상 회로)는 제02장과 같은 원본 part02_1/ch04/rtl/pwm_core.v입니다. 실습을 빠르게 끝내기 위해 인스턴스의 RESET_PERIOD만 8로 설정하며 기존 RTL은 변경하지 않습니다.

011교시 ① · task와 function의 차이 (0~25분)

task(태스크, 절차를 묶은 작업)는 여러 문장을 하나의 이름으로 묶습니다. 시간이 걸리는 @(negedge clk)나 wait도 포함할 수 있으므로, 설정을 쓰고 결과가 반영될 때까지 기다리는 시뮬레이션 절차에 적합합니다.

function(펑션, 값을 계산해 돌려주는 함수)은 입력으로부터 결과를 계산합니다. 이번 예제의 duty_percent()는 듀티 클록 수와 전체 주기를 받아 백분율을 반환합니다. 일반적인 Verilog/SystemVerilog 함수 내부에서는 시간 지연·에지 대기처럼 시뮬레이션 시간을 소비하는 명령을 사용하지 않습니다.

핵심 문법 · 설명용 부분 코드 · SystemVerilog · 교육용 발췌
// function: 계산 후 값 하나를 반환, 시간은 흐르지 않음.
function automatic integer duty_percent(
    input [31:0] high_ticks,
    input [31:0] period_ticks
);
    begin
        duty_percent = (high_ticks * 100) / period_ticks;
    end
endfunction

// task: 실제 시간과 이벤트를 포함하는 작업
task automatic request_pwm(input [31:0] duty_ticks);
    begin
        @(negedge clk);
        cfg_duty = duty_ticks;
        cfg_apply = 1'b1;
        // 이후 wait(pending...) 등은 전체 코드에 이어짐
    end
endtask
비교taskfunction
주요 용도시간에 맞춰 입력을 주는 절차듀티비처럼 즉시 구하는 계산
시간 소비가능: #, @, wait일반 함수는 불가
결과 전달출력 인자 등을 사용할 수 있음반환값이 있음
이번 장request_pwm(), observe_one_period()duty_percent()

automatic(오토매틱, 호출마다 독립적인 지역 저장 공간을 사용하는 선언)을 사용하면 반복 호출 시 지역 변수와 인자를 각 실행에 독립적으로 처리할 수 있습니다. 다만 이 예제는 순차적으로 호출하므로 동시 실행 문제를 아직 다루지 않습니다.

021교시 ② · repeat·for·wait의 역할 (25~45분)

repeat(리피트, 지정 횟수 반복)는 몇 번 실행할지가 정해져 있을 때 쓰고, for(포, 초기값·조건·증가식 반복)는 반복하는 동안 값을 변경할 때 편리합니다. wait(웨이트, 조건 충족까지 대기)는 시간을 미리 계산하지 않고 회로의 상태 변화에 맞춰 다음 단계로 넘어가게 합니다.

반복과 상태 대기 · 핵심 코드 · SystemVerilog · 교육용 발췌
// 리셋을 두 번의 하강 에지까지 유지한다.
repeat (2) @(negedge clk);

// 0, 2, 4, 6, 8의 5개 설정을 반복한다.
for (duty_step = 0; duty_step <= 8;
     duty_step = duty_step + 2) begin
    request_pwm(duty_step);
    observe_one_period();
end

// 먼저 대기 설정을 받았는지 확인한다.
wait (pending === 1'b1);
// 이어서 주기 경계에서 적용 완료되기를 기다린다.
wait (pending === 1'b0);

왜 wait(pending === 1'b0)만 쓰면 위험할까요? 설정을 요청하기 전의 pending은 이미 0일 수 있습니다. 그때 적용이 끝났다고 오해하면 아직 반영되지 않은 값을 관찰합니다. 먼저 pending이 1이 되는 요청 수락 이후를 확인하고, 다시 0으로 내려오는 적용 완료 이후에 출력을 읽어야 합니다.

wait는 조건이 이미 참이면 지체 없이 통과하고, 거짓이면 참이 될 때까지 멈춥니다. 반면 @(posedge clk)는 해당 신호의 다음 상승 이벤트까지 기다립니다. 이 차이는 실제 실무용 버스 검증에서도 중요합니다.

031교시 ③ · PWM 한 주기의 시간표 (45~60분)

클록 전체 주기는 10ns입니다. 20ns 하강 에지에서 리셋을 해제하고, 30ns에 첫 번째 설정 요청을 올립니다. 35ns에 원본 코어는 Shadow 값을 저장하고 pending을 1로 만듭니다. 이후 주기 경계인 95ns에 Active 설정을 갱신하며 pending이 0으로 돌아갑니다.

시점TB 코드실제 RTL의 의미
30nscfg_apply = 1새 듀티 설정 요청
35nswait(pending === 1'b1)의 선행 조건 충족Shadow 저장 완료
95nswait(pending === 1'b0) 통과Active 설정 적용 완료
96ns#1; $display(...)비차단 대입 이후 안정된 값 관찰
100~170nsobserve_one_period()8개의 하강 에지에서 PWM 출력 표본 기록
180ns다음 request_pwm(2)다음 듀티 설정 요청

이 방식에서는 #80처럼 고정 지연으로 설정 완료를 추정하지 않습니다. 설정 요청과 실제 적용이 서로 다른 클록에 발생하는 이유를 pending으로 확인합니다. 안전한 무한 대기 방지를 위해 TB에는 별도로 2000ns의 전체 시뮬레이션 제한을 둡니다.

042교시 ① · 테스트벤치 전체 소스 (60~85분)

앞의 핵심 문법을 하나의 실행 가능한 테스트벤치로 묶습니다. request_pwm()는 설정을 요청하고 실제 적용을 기다리며, observe_one_period()는 8개 표본에서 출력 HIGH 횟수를 셉니다. 마지막 for 루프가 두 태스크를 다섯 번 호출합니다.

tb/ch03/tb_pwm_reusable_stimulus.sv · SystemVerilog · 신규 교육용 TB · 실제 컴파일 판정 별도
`timescale 1ns/1ps
// 제03장: task, function, repeat, for, wait로 PWM 입력 자극을 재사용한다.
// DUT는 기존 pwm_core 원본을 참조하며, 이 TB는 관찰용이다.
// 자동 PASS/FAIL 판정은 제04장에서 다룬다.
module tb_pwm_reusable_stimulus;
    reg         clk;
    reg         resetn;
    reg         cfg_apply;
    reg  [31:0] cfg_period;
    reg  [31:0] cfg_duty;
    reg         cfg_enable;
    reg         cfg_polarity;

    wire        pwm_out;
    wire        pending;
    wire [31:0] active_period;
    wire [31:0] active_duty;
    wire        active_enable;
    wire        active_polarity;

    // 원본 RTL의 포트 13개를 이름 그대로 연결한다.
    // 인스턴스 초기 주기만 8클록으로 축소해 관찰 시간을 절약한다.
    pwm_core #(.RESET_PERIOD(32'd8)) dut (
        .clk             (clk),
        .resetn          (resetn),
        .cfg_apply       (cfg_apply),
        .cfg_period      (cfg_period),
        .cfg_duty        (cfg_duty),
        .cfg_enable      (cfg_enable),
        .cfg_polarity    (cfg_polarity),
        .pwm_out         (pwm_out),
        .pending         (pending),
        .active_period   (active_period),
        .active_duty     (active_duty),
        .active_enable   (active_enable),
        .active_polarity (active_polarity)
    );

    // (추가) 클록 주기: 5ns + 5ns → 10ns.
    initial clk = 1'b0;
    always #5 clk = ~clk;

    // (추가) function은 시뮬레이션 시간을 소비하지 않고 값을 반환한다.
    // 실습 범위는 period=8이므로 나눗셈 분모는 항상 0이 아니다.
    function automatic integer duty_percent(
        input [31:0] high_ticks,
        input [31:0] period_ticks
    );
        begin
            duty_percent = (high_ticks * 100) / period_ticks;
        end
    endfunction

    // (추가) 설정 요청을 매번 중복 작성하지 않고 task 한 곳에 모은다.
    // cfg_apply는 하강 에지에서 한 클록 동안 유지한다.
    task automatic request_pwm(input [31:0] duty_ticks);
        begin
            @(negedge clk);
            cfg_duty  = duty_ticks;
            cfg_apply = 1'b1;
            $display("REQUEST t=%0d ns duty=%0d", $time, duty_ticks);

            @(negedge clk);
            cfg_apply = 1'b0;

            // 먼저 Shadow 저장 완료를 확인한 뒤 적용 완료를 기다린다.
            // pending=0만 즉시 검사하면 이전 상태를 오인할 수 있다.
            wait (pending === 1'b1);
            wait (pending === 1'b0);
            #1;
            $display("APPLIED t=%0d ns duty=%0d percent=%0d",
                $time, active_duty,
                duty_percent(active_duty, active_period));
        end
    endtask

    // (추가) 한 PWM 주기의 8개 하강 에지에서 출력을 샘플링한다.
    // 표본 개수를 표시할 뿐, 아직 기대값과 자동 비교하지 않는다.
    task automatic observe_one_period;
        integer cycle_index;
        integer high_samples;
        begin
            high_samples = 0;

            for (cycle_index = 0; cycle_index < 8;
                 cycle_index = cycle_index + 1) begin
                @(negedge clk);
                if (pwm_out === 1'b1)
                    high_samples = high_samples + 1;

                $display("SAMPLE duty=%0d cycle=%0d pwm=%b",
                    active_duty, cycle_index, pwm_out);
            end

            $display("OBSERVED duty=%0d HIGH=%0d/8",
                active_duty, high_samples);
        end
    endtask

    initial begin
        $dumpfile("ch03_pwm_reusable_stimulus.vcd");
        $dumpvars(0, tb_pwm_reusable_stimulus);
    end

    // (추가) 시뮬레이션 무한 대기를 방지하기 위한 안전 종료.
    initial begin
        #2000;
        $display("TIMEOUT: PWM 설정 완료 신호를 확인하세요.");
        $finish;
    end

    integer duty_step;

    initial begin
        resetn       = 1'b0;
        cfg_apply    = 1'b0;
        cfg_period   = 32'd8;
        cfg_duty     = 32'd0;
        cfg_enable   = 1'b1;
        cfg_polarity = 1'b0;

        $display("=== CH03 REUSABLE STIMULUS START ===");

        // (추가) 리셋을 두 번의 하강 에지 동안 유지한다.
        repeat (2) @(negedge clk);
        resetn = 1'b1;

        // (추가) 0, 2, 4, 6, 8클록의 Duty를 순서대로 시험한다.
        // cfg_period=8이므로 0%, 25%, 50%, 75%, 100%가 된다.
        for (duty_step = 0; duty_step <= 8;
             duty_step = duty_step + 2) begin
            request_pwm(duty_step);
            observe_one_period();
        end

        $display("=== CH03 END: OBSERVATION ONLY ===");
        $finish;
    end
endmodule

코드 풀이 — 한 줄의 호출이 수행하는 일

request_pwm(duty_step) 한 줄은 하강 에지 대기 → 듀티 설정 → cfg_apply 한 클록 유지 → pending 상승·하강 대기 → 실제 active_duty 출력까지 수행합니다. 외부에서는 매번 같은 문장을 다시 작성할 필요가 없습니다.

observe_one_period()는 for 반복문을 이용해 각 하강 에지에서 pwm_out을 관찰하고 HIGH 표본 수를 집계합니다. 숫자를 세는 if는 아직 DUT가 올바른지 자동 판정하는 검증문이 아닙니다. 제04장에서 기대값과 비교하는 PASS/FAIL로 확장합니다.

duty_percent(active_duty, active_period)의 결과는 설정 2/8에서 25, 4/8에서 50입니다. 이 예제에서는 주기가 8로 고정되어 분모가 0이 아니며 연산 폭의 문제가 없습니다. 범용 모듈로 확장할 때는 0 주기 처리와 곱셈 폭을 검토해야 합니다.

052교시 ② · Ubuntu 실행·파일 확인 (85~100분)

Ubuntu(우분투, 리눅스 배포판)에서는 기존 설치된 Icarus Verilog(아이카루스 베릴로그, RTL 시뮬레이터)를 사용합니다. 기존 저장소의 원본 PWM 파일은 읽기 전용으로 컴파일 대상에 지정할 뿐 복사하거나 수정하지 않습니다.

Ubuntu 터미널 · Bash · 실행 명령 · 최초 환경에 따라 설치 확인
# 1. 저장소의 검증 과정 폴더로 이동한다.
cd /path/to/system_verilog_uvm_tb

# 2. Icarus Verilog가 설치되어 있는지 확인한다.
iverilog -V

# 3. TB와 기존 pwm_core를 컴파일하고 시뮬레이션한다.
bash scripts/run_ch03.sh

# 4. 로그에서 각 듀티의 관찰 요약을 확인한다.
grep '^OBSERVED' .build/ch03/output.log

# 5. GTKWave가 설치되었다면 파형 파일을 연다.
gtkwave .build/ch03/ch03_pwm_reusable_stimulus.vcd
scripts/run_ch03.sh · Bash · 신규 교육용 실행 스크립트
#!/usr/bin/env bash
# 제03장: 기존 pwm_core와 반복 자극 TB를 컴파일하고 시뮬레이션한다.
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
COURSE_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
DUT_PATH="${DUT_PATH:-$COURSE_ROOT/reference_rtl/pwm_core.v}"
TB_PATH="$COURSE_ROOT/tb/ch03/tb_pwm_reusable_stimulus.sv"
OUT_DIR="$COURSE_ROOT/.build/ch03"

# 컴파일러·실행기를 반드시 함께 확인한다.
for tool in iverilog vvp; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "ERROR: $tool 명령이 없습니다. sudo apt install iverilog"
    exit 2
  fi
done

# DUT가 없으면 파일을 복사하지 말고 경로를 먼저 확인한다.
if [[ ! -f "$DUT_PATH" ]]; then
  echo "ERROR: 원본 RTL 없음: $DUT_PATH"
  echo "사용법: DUT_PATH=/실제/경로/pwm_core.v bash scripts/run_ch03.sh"
  exit 2
fi

mkdir -p "$OUT_DIR"

# -g2012는 이 테스트벤치의 SystemVerilog 문법을 지원하기 위한 옵션이다.
iverilog -g2012 -s tb_pwm_reusable_stimulus \
  -o "$OUT_DIR/simulation.vvp" "$DUT_PATH" "$TB_PATH"

# 표준 출력과 VCD 파형을 이 장만의 출력 폴더에 보존한다.
(cd "$OUT_DIR" && vvp simulation.vvp | tee output.log)
echo "로그: $OUT_DIR/output.log"
echo "파형: $OUT_DIR/ch03_pwm_reusable_stimulus.vcd"

스크립트의 DUT_PATH는 기본적으로 상위 part02_1/ch04/rtl/pwm_core.v를 가리킵니다. 독립 경로로 옮긴 경우에는 DUT_PATH=/절대/경로/pwm_core.v bash scripts/run_ch03.sh로 실행합니다. 컴파일된 결과와 VCD(브이시디, 신호 변화 기록)는 .build/ch03/에 보관합니다.

062교시 ③ · 예상 출력과 해석 (100~110분)

08참고 · 재사용한 pwm_core 원본 코드

실제 검증 대상은 아래 기존 RTL과 동일합니다. pending, shadow_duty, active_duty, counter의 관계를 소스에서 다시 확인하면, 태스크가 무엇을 기다리는지 자연스럽게 이해할 수 있습니다.

part02_1/ch04/rtl/pwm_core.v · Verilog · 기존 원본 · 소스 변경 없음
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

주기 경계 검사는 boundary, 출력 HIGH 구간 검사는 duty_high로 구현되어 있습니다. 도식과 테스트벤치의 신호 명칭은 원본 포트명과 동일하게 유지했습니다.
