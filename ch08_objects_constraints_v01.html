제08장 · 객체와 제약 기반 입력

class · new · extends · rand · constraint로 검증 입력을 생성하고 원본 UART Echo와 자동 비교합니다.

제2부 · 제08장1교시 60분 + 2교시 60분기존 RTL 변경 없음

00학습 개요 · 반복 입력을 객체로 관리한다

제07장에서는 신호 묶음과 관찰 시점을 정리했습니다. 제08장에서는 하나의 입력 사례를 객체로 표현하여 수십·수백 개의 검증 사례로 확장하는 기반을 마련합니다. class(클래스, 객체 설계도), new(뉴, 객체 생성), extends(익스텐즈, 상속), rand(랜드, 무작위 변수), constraint(컨스트레인트, 허용 범위 제한)를 사용합니다.

구간시간실습
1교시0~60분클래스·객체·상속·제약·난수 실패 이해
2교시60~120분UART 원본 연결, 4사례 자동 검사, 실행·오류 분석

이번 DUT는 uart_echo_controller입니다. UART 직렬 프레임을 해석하는 장치가 아니라 8비트 Ready/Valid 조합 전달 회로입니다. 입력 rx_data_i는 tx_data_o, rx_valid_i는 tx_valid_o, tx_ready_i는 rx_ready_o로 그대로 전달됩니다. 클록·리셋은 없습니다.

011교시 ① · class와 new (0~20분)

uart_txn 클래스는 데이터와 유효·준비 신호를 하나의 트랜잭션(거래 단위)으로 묶습니다. uart_txn normal;은 아직 객체를 생성하지 않은 핸들이고, normal = new();를 실행하면 실제 객체가 만들어집니다. 클래스 선언만으로 신호가 자동 구동되지는 않습니다.

객체 생성 · SystemVerilog
uart_txn normal;
normal = new();
normal.data = 8'h41;
normal.valid = 1'b1;
normal.ready = 1'b1;

핸들은 객체를 가리키는 변수입니다. normal.data는 실제 하드웨어 포트가 아니라 객체 내부 값이므로, 별도 구동 코드가 DUT 입력으로 복사해야 합니다.

021교시 ② · rand와 constraint (20~40분)

rand는 randomize() 호출 시 변경 가능한 필드입니다. constraint c_printable은 데이터를 16진수 20~7E(출력 가능한 ASCII 범위)로 제한합니다. 제한 없는 무작위 입력보다 재현·해석이 쉬운 유효 입력을 생성합니다.

제약 조건 · 실제 TB 발췌
rand bit [7:0] data;
rand bit valid;
rand bit ready;
constraint c_printable { data inside {[8'h20:8'h7e]}; }

if (!normal.randomize() with { valid == 0; ready == 1; })
    $fatal(1, "RANDOMIZE_FAIL IDLE");

randomize() with는 이번 호출에서만 추가 제약을 부여합니다. 만족 가능한 조합이 없으면 0을 반환하므로 반드시 실패를 검사해야 합니다. 무작위 생성값은 시드와 시뮬레이터에 따라 달라지며, 특정 바이트를 고정된 출력처럼 가정하면 안 됩니다.

031교시 ③ · extends와 다형성 (40~60분)

uart_stall_txn extends uart_txn은 부모의 필드·메서드·출력 가능 문자 제약을 물려받습니다. 여기에 valid=1과 ready=0 조건을 추가하면 데이터가 존재하지만 상대가 받을 수 없는 전송 정지 상황만 생성합니다.

상속 제약 · 실제 TB 발췌
class uart_stall_txn extends uart_txn;
    constraint c_stall { valid == 1'b1; ready == 1'b0; }
endclass

apply_and_check(input uart_txn tr, ...)는 부모 타입을 인자로 받지만 자식 객체도 전달할 수 있습니다. 공통 검사 함수를 재사용하면서 자식의 입력 정책만 달라집니다. 이는 UVM(유니버설 검증 방법론)의 sequence item(시퀀스 아이템, 검증 거래 객체) 설계로 이어집니다.

042교시 ① · 실제 DUT와 테스트벤치 구조 (60~70분)

구현 구조는 객체 생성 → 제약 무작위 생성 → 포트 구동 → 1ns 안정 대기 → DUT 출력 비교입니다. 여기서 1ns는 테스트벤치 관찰 지연이지 DUT의 물리적 지연이 아닙니다.

052교시 ② · 전체 테스트벤치 코드 (70~100분)

아래 코드는 독립 파일 tb/ch08/tb_uart_objects.sv의 전체 내용입니다. 네 사례는 직접 지정 A, 제약 IDLE, 상속 정지, 부모 타입을 통한 자식 재사용입니다. 모든 사례는 원본 DUT의 조합 전달 계약과 비교합니다.

tb/ch08/tb_uart_objects.sv · SystemVerilog · 전체 소스 · RTL_SIM NOT_RUN
`timescale 1ns/1ps
// 제08장: 원본 UART Echo의 6개 포트를 변경하지 않고 객체 기반 입력을 검증한다.
// class, new, extends, rand, constraint, randomize()를 직접 실습한다.

class uart_txn;
    rand bit [7:0] data;
    rand bit       valid;
    rand bit       ready;

    // (추가) 출력 가능한 ASCII(아스키) 문자 범위로 데이터를 제한한다.
    constraint c_printable { data inside {[8'h20:8'h7e]}; }

    function new();
        data = 8'h41;
        valid = 1'b1;
        ready = 1'b1;
    endfunction

    function string describe();
        return $sformatf("data=%02h valid=%0b ready=%0b",
                         data, valid, ready);
    endfunction
endclass

// (추가) 부모의 데이터 범위 제약을 물려받고 정지 조건을 추가한다.
class uart_stall_txn extends uart_txn;
    constraint c_stall { valid == 1'b1; ready == 1'b0; }
endclass

module tb_uart_objects;
    logic [7:0] rx_data_i;
    logic       rx_valid_i;
    wire        rx_ready_o;
    wire [7:0]  tx_data_o;
    wire        tx_valid_o;
    logic       tx_ready_i;

    integer checked = 0;
    uart_txn normal;
    uart_stall_txn stalled;

    // 원본 DUT: 데이터/유효/준비를 그대로 전달하는 조합회로이다.
    uart_echo_controller dut (
        .rx_data_i(rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

    // (추가) 객체의 속성을 DUT 포트에 적용하고 4상태 비교로 확인한다.
    task automatic apply_and_check(input uart_txn tr, input string label_name);
        begin
            rx_data_i  = tr.data;
            rx_valid_i = tr.valid;
            tx_ready_i = tr.ready;
            #1; // 조합 출력이 안정되도록 TB에서만 기다린다. DUT 지연이 아니다.
            if ((tx_data_o !== tr.data) ||
                (tx_valid_o !== tr.valid) ||
                (rx_ready_o !== tr.ready))
                $fatal(1, "FAIL %s expected %s got %02h/%b/%b",
                       label_name, tr.describe(), tx_data_o,
                       tx_valid_o, rx_ready_o);
            checked++;
            $display("PASS %s %s", label_name, tr.describe());
        end
    endtask

    initial begin
        $display("=== CH08 OBJECT / CONSTRAINT START ===");
        normal = new();
        stalled = new();

        // (추가) 부모 객체에 특정 값을 넣어 기준 동작부터 확인한다.
        normal.data = 8'h41;
        normal.valid = 1'b1;
        normal.ready = 1'b1;
        apply_and_check(normal, "DIRECT_A");

        // (추가) 인라인 제약으로 유효한 IDLE 사례를 생성한다.
        if (!normal.randomize() with { valid == 0; ready == 1; })
            $fatal(1, "RANDOMIZE_FAIL IDLE");
        apply_and_check(normal, "RANDOM_IDLE");

        // (추가) 상속된 제약은 데이터 범위를 유지하고 정지를 강제한다.
        if (!stalled.randomize()) $fatal(1, "RANDOMIZE_FAIL STALL");
        if (!(stalled.data >= 8'h20 && stalled.data <= 8'h7e &&
              stalled.valid == 1'b1 && stalled.ready == 1'b0))
            $fatal(1, "CONSTRAINT_FAIL STALL");
        apply_and_check(stalled, "RANDOM_STALL");

        // (추가) 부모 클래스 핸들로 자식 객체를 넘겨 다형성을 실습한다.
        apply_and_check(stalled, "POLYMORPHIC_STALL");
        if (checked != 4) $fatal(1, "COUNT_FAIL %0d", checked);
        $display("CH08 PASS: %0d cases checked", checked);
        $finish;
    end

    initial begin
        #100;
        $fatal(1, "CH08 TIMEOUT");
    end
endmodule

코드 풀이 — 입력과 검사

new()에서 초기 필드 값을 설정하고, randomize()를 호출한 경우에만 무작위 제약을 적용합니다. apply_and_check()는 객체 필드를 DUT 입력으로 복사하고 #1 후 실제 출력과 비교합니다. !==는 X·Z까지 구분하는 4상태 비교이므로 예상하지 않은 미정 값을 숨기지 않습니다.

checked++는 실제 검사 함수가 통과한 횟수를 셉니다. 마지막에 4회를 확인하고, 어느 검사든 실패하면 $fatal로 비정상 종료합니다. RANDOM_STALL과 POLYMORPHIC_STALL은 같은 자식 객체를 두 번 검사하므로 서로 독립적인 난수 사례 두 개가 아닙니다.

062교시 ③ · Ubuntu 실행과 도구 지원 (100~110분)

클래스 제약 무작위화는 도구별 지원 수준이 다릅니다. Icarus Verilog(아이카루스 베릴로그)는 이 장의 전체 기능을 보장하지 않으므로 Verilator(베릴레이터, SystemVerilog 시뮬레이터) 5.x의 최신 지원 버전 또는 상용 시뮬레이터를 사용합니다. 버전에 따라 외부 제약 해결기 설치가 필요할 수 있습니다.

scripts/run_ch08.sh · Bash · 전체 실행 스크립트
#!/usr/bin/env bash
# 제08장: 클래스/상속/제약 무작위 입력을 기존 UART Echo RTL에 적용한다.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DUT_PATH="${DUT_PATH:-$ROOT/reference_rtl/uart_echo_controller.v}"
TB_PATH="$ROOT/tb/ch08/tb_uart_objects.sv"
OUT="$ROOT/.build/ch08"
if ! command -v verilator >/dev/null 2>&1; then
  echo "ERROR: Verilator 미설치. Ubuntu: sudo apt update && sudo apt install verilator g++ make"
  exit 2
fi
if [[ ! -f "$DUT_PATH" ]]; then echo "ERROR: DUT 파일 없음: $DUT_PATH"; exit 2; fi
mkdir -p "$OUT"
verilator --version | tee "$OUT/tool_version.txt"
# Verilator 5.x의 randomize/constraint 지원 및 solver 설치 여부를 확인한다.
verilator --binary --timing --sv --top-module tb_uart_objects \
  --Mdir "$OUT/obj_dir" "$DUT_PATH" "$TB_PATH" 2>&1 | tee "$OUT/build.log"
(cd "$OUT" && ./obj_dir/Vtb_uart_objects | tee output.log)
echo "실행 기록: $OUT/output.log"

sudo apt update는 Ubuntu 패키지 목록을 갱신하고, sudo apt install verilator g++ make는 시뮬레이터와 C++ 빌드 도구를 설치합니다. bash scripts/run_ch08.sh는 프로젝트 루트에서 실행합니다. --binary는 실행 파일 빌드, --timing은 시간 지연 처리, --sv는 SystemVerilog 해석을 지정합니다. set -euo pipefail은 빌드·실행 오류를 성공으로 숨기지 않습니다.

072교시 ④ · 예상 출력과 오류 분석 (110~118분)

다음은 예상 출력 형식이며 실제 실행 로그가 아닙니다. 무작위 데이터는 예시이며 매 실행 달라질 수 있습니다.

08마무리 · 다음 단계 (118~120분)

class는 입력의 구조, extends는 재사용과 확장, constraint는 유효 입력 공간을 표현합니다. 제08장은 데이터를 생성하고 원본 RTL과 비교하는 최소 객체 기반 검증을 다루며, UVM 프레임워크 자체를 실행한 장은 아닙니다. 제09장에서는 이 비교를 참조 모델·스코어보드로 분리합니다.

검증 판정: 문서·포트 계약 정적 검토, RTL_SIM=NOT_RUN (제작 환경에 Verilator가 없음), 실제 브라우저 렌더링=NOT_RUN. 시뮬레이션 로그가 확보되기 전에는 실제 PASS로 표기하지 않습니다.
