00개요 · 테스트벤치에서 UVM으로

UVM(Universal Verification Methodology, 유브이엠, 표준 검증 방법론)은 SystemVerilog 클래스와 표준 실행 단계를 이용하여 검증 환경을 재사용할 수 있게 합니다. 제09~12장에서 사용한 PWM 검증을 uvm_test와 uvm_env로 옮깁니다. 아직 Sequence·Driver·Monitor·Agent는 만들지 않습니다. 제18~19장에서 각 기능을 분리합니다.

선행 설계 학습안내서: 제2부 사용자 AXI IP와 주변장치(amd_soc_p2) 04.2장 「RTL · AXI 풀이」 02절 「설정 Shadow와 출력 Active를 분리」, 06절 「독립 PWM Core 전체」. 원본 PWM만 사용하며 AXI 래퍼와 보드는 범위 밖입니다.

01원본 PWM RTL 전체

10ns 클록, RESET_PERIOD=8로 인스턴스화합니다. 동기 리셋은 상승 에지에서 내부 상태를 초기화하고 출력은 resetn으로 조합 차단합니다. cfg_apply를 한 클록 인가하면 Shadow 설정과 pending을 저장하고 다음 주기 경계에 Active 설정을 적용합니다.

reference_rtl/pwm_core.v · Verilog
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

실습은 period=8, duty=4, enable=1, polarity=0입니다. 주기 경계 후 위상 0~3은 HIGH, 4~7은 LOW입니다. 실제 포트에서 설정과 출력을 관찰하며 내부 counter는 읽지 않습니다.

03Phase·Objection · 종료 계약

Phase실제 수행
build_phasepwm_test가 env 생성, pwm_env가 vif 획득
connect_phase프레임워크 단계, 이번 코드에는 별도 연결 구현 없음
run_phasetest가 objection 유지, env가 리셋·설정·8개 표본 검사
check_phasechecks=8, done=1 확인
report_phaseUVM_ERROR/FATAL 누계 및 완료 행 확인

Phase(페이즈, 표준 실행 단계)는 순서를 관리합니다. run_phase는 시간을 사용하는 task 단계이고 build/check/report는 function 단계입니다. test와 env의 run_phase는 병렬로 수행됩니다. Objection(옵젝션, 종료 보류 요청)은 test에서 올리고, env가 마지막 검사 및 메시지 기록까지 완료한 뒤 done을 1로 설정하면 wait(env.done)이 풀려 내려갑니다. 단순 시간 대기나 일부 검사 완료를 종료 조건으로 사용하지 않습니다. 전역 2000ns 타임아웃은 무한 대기 방지용입니다.

기존처럼 두 표본만 검사하면 중간 출력 오류를 놓칠 수 있으므로 매 하강 에지에서 active_period/duty/enable/polarity, pending 및 pwm_out을 대조합니다. 위 시각은 독립 계산한 예상값이며 TB는 pending 해제에 따라 관찰을 시작합니다. 적용 시각의 정확한 105ns 자체를 별도 assertion으로 강제하지는 않습니다.

부정 시험은 NO_VIF 인자로 Top의 config_db::set을 생략합니다. 정상 DUT를 변경하지 않고 build_phase에서 NOVIF가 발생하며 PASS가 없어야 합니다. UVM의 실패 판정 경로를 확인하는 시험이지 DUT의 모든 오류 검출을 보장하는 것은 아닙니다.

05전체 UVM 테스트벤치

tb/ch17/tb_pwm_uvm.sv · SystemVerilog / UVM
`timescale 1ns/1ps
// 제17장: 기존 pwm_core를 읽기 전용 DUT로 사용하는 최소 UVM 환경.
// UVM의 build/run/check/report phase와 objection 수명주기를 확인한다.
interface pwm_if(input logic clk);
    logic resetn = 0;
    logic cfg_apply = 0;
    logic [31:0] cfg_period = 8;
    logic [31:0] cfg_duty = 0;
    logic cfg_enable = 0;
    logic cfg_polarity = 0;
    wire pwm_out;
    wire pending;
    wire [31:0] active_period, active_duty;
    wire active_enable, active_polarity;
endinterface

package ch17_uvm_pkg;
    import uvm_pkg::*;
    `include "uvm_macros.svh"

    class pwm_env extends uvm_env;
        `uvm_component_utils(pwm_env)
        virtual pwm_if vif;
        int unsigned checks = 0;
        bit done = 0;

        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction

        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            if (!uvm_config_db#(virtual pwm_if)::get(this, "", "vif", vif))
                `uvm_fatal("NOVIF", "pwm_if was not provided")
        endfunction

        // (변경) 호출자가 하강 에지에서 관찰 시점을 정한다.
        task automatic expect_ports(
            input logic [31:0] duty, input logic enable,
            input logic expected_pwm
        );
            if (vif.pending !== 1'b0 ||
                vif.active_period !== 32'd8 ||
                vif.active_duty !== duty ||
                vif.active_enable !== enable ||
                vif.active_polarity !== 1'b0 ||
                vif.pwm_out !== expected_pwm)
                `uvm_fatal("MISMATCH", $sformatf(
                    "period=%0d duty=%0d enable=%b pwm=%b",
                    vif.active_period, vif.active_duty,
                    vif.active_enable, vif.pwm_out))
            checks++;
        endtask

        task run_phase(uvm_phase phase);
            // DUT는 동기 리셋: resetn=0인 동안 posedge가 필요하다.
            repeat (3) @(negedge vif.clk);
            if (vif.active_period !== 32'd8 ||
                vif.active_duty !== 32'd0 ||
                vif.active_enable !== 1'b0 || vif.pending !== 1'b0 ||
                vif.active_polarity !== 1'b0 || vif.pwm_out !== 1'b0)
                `uvm_fatal("RESET", "PWM reset contract violated")
            `uvm_info("PWM", "RESET_CHECKED", UVM_LOW)

            // 설정은 Shadow에 저장되고, 다음 주기 경계에서 활성화된다.
            vif.resetn = 1;
            @(negedge vif.clk);
            vif.cfg_period = 8;
            vif.cfg_duty = 4;
            vif.cfg_enable = 1;
            vif.cfg_polarity = 0;
            vif.cfg_apply = 1;
            @(negedge vif.clk);
            vif.cfg_apply = 0;
            if (vif.pending !== 1'b1 || vif.active_duty !== 32'd0 ||
                vif.active_enable !== 1'b0 || vif.pwm_out !== 1'b0)
                `uvm_fatal("PENDING", "cfg_apply was not latched")

            // 8클록 주기 경계가 도래할 때까지 기다린다.
            // 비활성 상태에서 활성 상태로 전환되는 조건만 감시한다.
            begin
                int guard;
                guard = 0;
                while (vif.pending !== 1'b0) begin
                    @(negedge vif.clk);
                    guard++;
                    if (guard > 12)
                        `uvm_fatal("TIMEOUT", "PWM apply boundary timeout")
                end
            end
            if (vif.active_duty !== 32'd4 || vif.active_enable !== 1'b1)
                `uvm_fatal("APPLY", "PWM active settings mismatch")

            // (변경) 경계 직후 phase 0부터 전체 8개 표본을 검사한다.
            for (int i=0; i<8; i++) begin
                expect_ports(32'd4, 1'b1, (i < 4));
                if (i < 7) @(negedge vif.clk);
            end
            `uvm_info("PWM", "PWM_DUTY_CHECKED", UVM_LOW)
            // (추가) 마지막 검사 및 기록 이후에만 완료를 통지한다.
            done = 1;
        endtask

        function void check_phase(uvm_phase phase);
            super.check_phase(phase);
            if (checks != 8 || !done)
                `uvm_fatal("CHECK", $sformatf("checks=%0d", checks))
        endfunction

        function void report_phase(uvm_phase phase);
            super.report_phase(phase);
            if (uvm_report_server::get_server().get_severity_count(UVM_ERROR) != 0 ||
                uvm_report_server::get_server().get_severity_count(UVM_FATAL) != 0)
                `uvm_fatal("REPORT", "UVM error or fatal reported")
            `uvm_info("RESULT", $sformatf(
                "PASS CH17 checks=%0d", checks), UVM_NONE)
        endfunction
    endclass

    class pwm_test extends uvm_test;
        `uvm_component_utils(pwm_test)
        pwm_env env;

        function new(string name, uvm_component parent);
            super.new(name, parent);
        endfunction

        function void build_phase(uvm_phase phase);
            super.build_phase(phase);
            env = pwm_env::type_id::create("env", this);
        endfunction

        task run_phase(uvm_phase phase);
            phase.raise_objection(this);
            // env의 run_phase와 test의 run_phase는 병렬 수행된다.
            // 이 장에서는 env의 완료를 기다리는 명시적 동기화가 필요하다.
            wait (env.done);
            phase.drop_objection(this);
        endtask
    endclass
endpackage

module tb_pwm_uvm;
    import uvm_pkg::*;
    import ch17_uvm_pkg::*;

    logic clk = 0;
    always #5 clk = ~clk;
    pwm_if bus(clk);

    pwm_core #(.RESET_PERIOD(8)) dut (
        .clk(clk), .resetn(bus.resetn), .cfg_apply(bus.cfg_apply),
        .cfg_period(bus.cfg_period), .cfg_duty(bus.cfg_duty),
        .cfg_enable(bus.cfg_enable), .cfg_polarity(bus.cfg_polarity),
        .pwm_out(bus.pwm_out), .pending(bus.pending),
        .active_period(bus.active_period), .active_duty(bus.active_duty),
        .active_enable(bus.active_enable),
        .active_polarity(bus.active_polarity)
    );

    initial begin
        // (추가) NO_VIF는 연결 실패를 검출하는 부정 시험 전용이다.

            uvm_config_db#(virtual pwm_if)::set(null, "uvm_test_top.env", "vif", bus);
        run_test("pwm_test");
    end
    initial begin
        #2000;
        $fatal(1, "FAIL CH17 GLOBAL_TIMEOUT");
    end
endmodule

06Ubuntu · Vivado XSIM 실행

AMD UG900의 내장 UVM 라이브러리를 이용합니다. 독립 실행에서 xvlog와 xelab에 -L uvm을 전달합니다. 설치된 Vivado 버전의 UVM 지원 및 매크로 경로를 확인해야 합니다. 모든 Verilator 5.x가 같은 UVM 기능을 지원한다고 가정하지 않으며 Icarus는 이 클래스 기반 UVM 실습의 실행 경로로 사용하지 않습니다.

scripts/run_ch17.sh · Bash
#!/usr/bin/env bash
# 제17장: Vivado XSIM 내장 UVM 라이브러리 사용.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
RTL="${DUT_PATH:-$ROOT/reference_rtl/pwm_core.v}"
if [[ ! -f "$RTL" ]]; then
  echo "NOT_RUN: DUT missing" >&2
  exit 2
fi
RTL="$(realpath "$RTL")"
for tool in xvlog xelab xsim; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "NOT_RUN: $tool missing; source Vivado settings64.sh" >&2
    exit 2
  fi
done
mkdir -p "$ROOT/.build/ch17"
OUT="$(mktemp -d "$ROOT/.build/ch17/run.XXXXXX")"
cd "$OUT"
xvlog "$RTL" 2>&1 | tee rtl.log
xvlog -sv -L uvm "$ROOT/tb/ch17/tb_pwm_uvm.sv" 2>&1 | tee tb.log
xelab -timescale 1ns/1ps -L uvm -debug typical tb_pwm_uvm -s ch17_sim 2>&1 | tee elaborate.log
xsim ch17_sim -runall -onerror quit 2>&1 | tee normal.log
grep -Eq '\[RESULT\][[:space:]]+PASS CH17 checks=8[[:space:]]*$' normal.log
grep -Eq 'UVM_ERROR[[:space:]]*:[[:space:]]*0[[:space:]]*$' normal.log
grep -Eq 'UVM_FATAL[[:space:]]*:[[:space:]]*0[[:space:]]*$' normal.log
# 부정 시험: 실제 연결을 생략하고 build_phase의 NOVIF를 확인한다.
# UVM $finish에 따른 종료 코드 차이가 있으므로 전용 진단도 검사한다.
rc=0
xsim ch17_sim -runall -onerror quit -testplusarg NO_VIF > negative.log 2>&1 || rc=$?
grep -Eq 'UVM_FATAL.*\[NOVIF\].*pwm_if was not provided' negative.log
if grep -q 'PASS CH17\|FAIL CH17 GLOBAL_TIMEOUT' negative.log; then
  echo "FAIL: unexpected negative result" >&2
  exit 1
fi
echo "PASS CH17 HARNESS (negative exit=$rc)"
echo "Logs: $OUT"
